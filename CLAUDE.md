## Project Overview

**Project Name:** ND2Studios
**Current version:** V1.45
**Repository:** https://github.com/DeclercqCortex/ND2Studios.git
**Description:** GUI-based PySide6 application for the McGhee Lab to load Nikon
ND2 microscopy files (with full metadata), apply a user-defined linear recipe
of image processing steps (trial / accept / reject), and export common
deliverables: Z-projection TIFF stacks, RGB composite TIFFs, and time-lapse
movies (MP4 / GIF) with scale bars, timestamps, and channel overlays.

ND2Studios is a *sibling* of CellTracker. It shares backend code (ND2 I/O,
enhancement plugins, recipe save/load) but does not depend on CellTracker's
segmentation/tracking pipeline. Shared code is currently **copied**; it will
be extracted to a common package only if the duplication becomes painful.

## Conventions

- **Naming:** `snake_case` for functions and modules, `CamelCase` for classes,
  `SCREAMING_SNAKE_CASE` for module-level constants.
- **Type hints:** required on all public functions. Use `from __future__ import
  annotations` at the top of every module.
- **Qt imports:** PySide6 only — never PyQt6. Pages and widgets are hand-coded
  in Python; we do **not** use `.ui` files.
- **Backend purity:** modules under `nd2studios/backend/` and
  `nd2studios/plugins/` must not import from `PySide6`. They take data in,
  return data out, and accept an optional `progress_cb: Callable[[int], None]`.
  This makes them callable from workers and (later) from headless scripts.
- **Data shapes:** image timeseries are always `(T, H, W)` numpy arrays for
  single-channel, with channels held in a `Dict[str, np.ndarray]` keyed by
  channel name. Z is collapsed at load time via projection (max/mean/min/none).
- **Pixel size:** stored in micrometers. Always honor the `pixel_size_um`
  field from `ND2Metadata` for scale bars, exports, and any spatial metric.
- **Recipes:** a recipe is an ordered list of `(plugin_name, params_dict)`
  tuples plus a `normalized` flag. Recipes are dataset-agnostic and
  serialize to `.nd2s_recipe.json`.
- **Sessions:** a session captures everything needed to resume work — current
  recipe, raw + preprocessed channels, ND2 metadata, current export config.
  Sessions serialize to `.nd2s` (JSON manifest + companion NPZ for arrays).

## Key Technical Decisions

1. **`nd2` library, not `nd2reader`.** Only `nd2` (Talley Lambert's modern
   library) reliably exposes voxel size, channel names, multipoint indexing,
   and ND2 SDK-grade metadata via `ND2File.metadata`. We pin to `nd2`.
2. **`LazyND2Channel` for memory.** Large ND2 files can be tens of GB. The
   GUI works with a numpy-protocol proxy that reads frames on demand.
   `np.asarray(...)` and `.materialize()` are escape hatches for code paths
   that genuinely need a contiguous array (e.g., movie export).
3. **Trial / Accept / Reject pipeline.** Mirrors CellTracker. The recipe is
   built incrementally; the user previews each step before committing it.
   `Reject` discards the trial; `Accept` appends to the pipeline and
   advances the baseline; `Remove Last` reprocesses from scratch.
4. **PySide6 + Dracula dark theme only.** Theme switching is out of scope
   for V1.0 but the QSS is structured to make it easy to add later.
5. **PyDracula chrome ported into Python.** The animated collapsible sidebar
   (60 ↔ 240 px) and custom frameless title bar with edge grips are
   reimplemented in `core/main_window.py` and `widgets/custom_grips.py`.
   We do not introduce `.ui` files.
6. **Workers, not async.** All long-running operations (file load, recipe
   step, export) run in `BaseWorker(QThread)` subclasses with
   `progress`/`finished`/`error` signals. The GUI never blocks.
7. **No segmentation, no tracking.** ND2Studios is intentionally narrower
   than CellTracker. If a user needs that flow, they use CellTracker.

## Dependencies

- **Python 3.9+**
- **PySide6** — GUI framework
- **numpy, scipy, pandas** — numerical core
- **nd2** — ND2 file I/O with full metadata
- **tifffile** — TIFF stack export
- **scikit-image, opencv-python, PyWavelets** — image processing
- **matplotlib** — plots, color LUTs, scale bars
- **imageio + imageio-ffmpeg** — MP4 / GIF movie export
- **certifi** — SSL certificate handling

ND2Studios does not depend on any segmentation library in its **core** install.
Segmentation backends are **optional, lazily-imported** extras, each gated by
`importlib.util.find_spec` with a friendly `ImportError` when missing (never in
`requirements.txt`):
- **cellpose** — the Nuclei Segmentation node (`pip install cellpose`).
- **stardist + tensorflow + csbdeep** — the StarDist Segmentation node, ported
  from CellTracker (`pip install stardist tensorflow csbdeep`). TensorFlow is
  imported lazily on first model load and locked to single inter/intra-op threads
  to avoid worker-thread deadlocks.
