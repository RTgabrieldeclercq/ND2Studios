# V1.43 — NIS-Elements-style Tile-Strip Frame Navigator

## Goal

Replace the plain per-axis `QSlider` with a Nikon NIS-Elements-style strip of
rectangular frame tiles, adding selection, range selection, keyboard stepping,
play-only-selected, right-click crop-to-selection (producing a new in-RAM
dataset that never touches the original file), and per-axis metadata.

## Approach

### New widget — `nd2studios/widgets/frame_strip.py`

`FrameStrip(QWidget)` — a single-`paintEvent` surface (not N child widgets, so
thousands of T frames stay cheap). One per axis (M / T / Z).

- **Tiles fill the full viewer width** and **wrap to additional rows** when
  there are more frames than fit at the minimum tile width. The minimum width is
  DPI-scaled (`9 px × dpi/96`, ≥ half a cursor). `resizeEvent` recomputes the
  row count and the widget's fixed height.
- **Current frame** highlighted in `ACCENT_PURPLE`; **selection** in a
  translucent `ACCENT_CYAN`; hover in `BG_HOVER`.
- **Mouse:** click = select + set current; **Shift-click** = inclusive range
  from current; **Ctrl-click** = toggle one tile; right-click = ensure tile is
  selected then context menu (Crop / Clear).
- **Keyboard** (focused): `←`/`→` = ±1, `Shift` = ±5, `Ctrl` = ±10. Documented
  in the widget tooltip.
- Signals: `current_changed(int)`, `selection_changed(frozenset)`,
  `crop_requested(frozenset)`. Per-frame tooltip via an injected `meta_fn`.

### Integration — `nd2studios/widgets/multi_axis_viewer.py`

The strip is **additive and low-risk**: each axis keeps its existing (now
hidden) `QSlider` as the source of truth for the current index, parented to the
strip. `_make_axis_row` adds the `FrameStrip` (stretch) in place of the visible
slider and wires bidirectional sync (`strip.current_changed → slider.setValue`;
`slider.valueChanged → strip.set_current(emit=False)`). All existing playback /
`.value()` / label code is unchanged.

- `_configure_slider` (the single range/visibility chokepoint) now also pushes
  `set_count` / `set_current` / visibility onto the matching strip and resets the
  tracked selection.
- **Play-only-selected:** `_axis_tick` calls new `_next_playback_value` which
  loops through the sorted selection when one exists (≥2 frames), else advances
  linearly.
- **Per-axis metadata** via `_frame_meta_text(axis, idx)`:
  - **T:** time imaged, Δt to previous, total elapsed (from `_frame_timestamps`,
    supplied by `set_frame_timestamps`).
  - **M:** pixel size (µm/px), resolution (W×H px), field of view (µm × µm).
  - **Z:** µm step, height within Z range (`step·idx` / `step·(n_z-1)`).
- New signal `crop_to_selection_requested(axis, frozenset)` relays the strip's
  crop request to the host.

### Crop to selection — new dataset, original untouched

- `MaterializedDataset.subset(*, m=None, t=None, z=None, progress_cb=None)` —
  advanced-indexing (`np.ix_`) copy of the selected indices on the leading
  M/T/Z axes; H/W preserved. Returns a **new** dataset (copy ⇒ independent), so
  the source is never mutated. Empty/over-range indices fall back to "keep all".
- `nd2studios/workers/crop_worker.py` — `CropWorker(BaseWorker)` runs `subset`
  off the GUI thread with frame-accurate progress (the copy can be multi-GB).
- **Host wiring** in `widgets/file_panel.py`: `crop_to_selection_requested` →
  `_on_crop_to_selection` builds the subset via `CropWorker`; on finish, swaps
  `record._raw_volume` to the cropped dataset, subsets the T timestamps, and
  refreshes the viewer. A **"Revert to full data"** button restores the original
  dataset reference. A fresh import clears any crop. The **T selection
  automatically keeps all M and Z** (the hierarchy rule) because `subset(t=…)`
  only constrains T; M-only / Z-only crops use `subset(m=…)` / `subset(z=…)`.

- `nd2studios/widgets/frame_strip.py` (new)

## Key Decisions

- **Hidden slider stays the model.** Keeps the blast radius tiny — playback,
  label edits, and every `slider.value()`/`maximum()` reader keep working; the
  strip is a view layer that syncs both ways.
- **Crop = copy, never mutate.** `np.ix_` advanced indexing guarantees an
  independent array; "revert" is just restoring the saved reference. Downstream
  tabs read `record._raw_volume`, so they automatically operate on the crop.
- **Single paint surface.** Avoids per-tile widget overhead for large T.

## Verification

- Headless: `MultiAxisViewer` builds; `set_channels`/`set_volume` sync strip
  counts to slider maxima; `_frame_meta_text` returns correct T/M/Z strings;
  `_next_playback_value` loops a selection and wraps.
- `MaterializedDataset.subset(t=[…])` keeps all M/Z, copies data correctly, and
  leaves the original unchanged (verified independent after mutation).
- `CropWorker.run_task` produces the expected cropped shape.
- Manual: open a multi-T/M/Z file → tiles fill width and wrap → arrows step
  1/5/10 → shift-range selects → play loops only the selection → right-click
  Crop shrinks the dataset (recipe/export see it) → "Revert to full data"
  restores it; the source file is never modified.

## Out of Scope

- Selection persistence across re-import.
- Crossing crops on multiple axes simultaneously in one action (each crop
  constrains one axis; chain them if needed).
