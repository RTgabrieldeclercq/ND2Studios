# V1.45 — "Pipelines" Tab (GA3-style node graph) — Phase 1: Processing MVP

## Goal

Add a new top-level **Pipelines** page modeled on Nikon NIS-Elements *General
Analysis 3 (GA3)*: a node-graph editor that fuses the existing
Recipe → Analysis → Results flow into one connected workflow. Drop nodes, wire
typed ports, preview live in the viewer, Apply.

This is **Phase 1**: the **Processing** sub-tab is fully wired end-to-end; the
graph model, executor, and node editor are built **stage-generic and
branching-DAG-capable** so Analysis / Results / Undo / Export integration slot
in as follow-ups (V1.46+).

## Decisions (confirmed with Gabriel)

1. **Phased** — Processing sub-tab end-to-end this pass. Analysis, Results +
   Export, and Undo are deferred.
2. **Branching DAG**, not strictly linear — even in the MVP. Each Processing
   **output node** is the unique linear path back to the input ⇒ its own
   recipe ⇒ its own `EnhancedDataset`. An output port may fan out.
3. **Processing accent = cyan** (`Settings.ACCENT_CYAN` `#8be9fd`); Analysis =
   pink, Results = green.
4. **Apply = current document only.** Batch-over-files deferred.

## Approach

### Qt-free graph core — `nd2studios/pipeline_graph/` (no PySide6)
- `model.py` — `PortType` / `Stage` / `NodeRole` enums; `Port` / `Node` /
  `Edge` / `GraphSlice` / `Bridge` / `PipelineDoc` dataclasses. Helpers:
  `new_id`, `can_connect(src, dst)`, `GraphSlice.add_node/remove_node/
  add_edge/remove_edge`, `would_create_cycle`, `to_dict`/`from_dict`.
- `registry_adapter.py` — enumerate `PluginBase.get_plugins("enhancement")`
  into `NodeSpec`s (op_key `enhancement:<name>`, title, port signature, default
  params from `instance.get_params()`). **Read names at runtime — never
  hardcode.** Input/output node specs synthesized here too.
- `executor.py` — `recipe_for_node(slice, node_id)` walks the single input edge
  back to the INPUT node, collecting `(plugin_name, params)`; `apply_recipe(
  channels, recipe, normalized, frame=None, progress_cb, cancelled_cb)` mirrors
  `RecipeWorker` / `EnhancedDataset.materialize_channel` using
  `PluginBase.get_plugin("enhancement", name).execute(...)` (stays Qt-free).
  `topo_order`, `param_hash`, `node_signature` for dirty/cache keys.
- `io.py` — `save_pipeline(doc, path)` / `load_pipeline(path)` →
  `<name>.nd2s_pipeline.json`, `kind="nd2studios.pipeline"`, `schema_version=1`.
  Mirrors `backend/recipes.py:build_recipe/save_recipe/load_recipe`.

### Node board UI — `nd2studios/widgets/node_board/` (Qt)
- `node_item.py` `NodeItem(QGraphicsObject)` — rounded body + cyan/pink/green
  lip; title; hover/selected corner buttons (Disconnect / Duplicate / Delete,
  `qtawesome` via `icon_button`, each with `setToolTip`).
- `port_item.py` `PortItem(QGraphicsObject)` — typed point, color by `PortType`.
- `edge_item.py` `EdgeItem(QGraphicsPathItem)` — cubic Bézier in source-port
  color; live rubber-band with type validation + reject flash.
- `node_scene.py` — one `QGraphicsScene` per `Stage`; connect/validate; signals
  on add / select / param-dirty.
- `param_popup.py` — frameless panel embedding `widgets/common.py:ParamEditor`;
  `set_params(get_params())`, `params_changed → Node.params → dirty → debounced
  preview`; close on click-away / Esc.

### Page — `nd2studios/pages/pipelines_page.py`
`QSplitter(Qt.Horizontal)` 50/50 (mirrors `MultiAxisViewer` / `ResultsPage`
idiom). Left = sub-tab selector (3 `tool_button`s) + control bar (Preview
ON/OFF via `bind_toggle_icon`, Apply, Undo[disabled]) + single `QGraphicsView`
swapping scenes per sub-tab. Right = reused `MultiAxisViewer`.
- Preview: thin `_ProcessingPreviewJob(AnalysisJob)` (defined in the page) calls
  `executor.apply_recipe(...)` on `record._raw_channels`; result →
  `viewer.set_channels(...)`. Submitted to `MainWindow.job_runner`, coalesce key
  `"pipeline_preview"`, 300 ms debounce, generation-tag stale-drop, honors
  `heavy_ops_blocked()`.
- Apply: build the primary output node's recipe → set `record.recipe` /
  `recipe_normalized`, `record._processed_view = EnhancedDataset(...)`, status →
  `preprocessed`, best-effort `RecipeStage.set_recipe(...).commit()` when a
  session exists. (Additional branch outputs preview but only the primary drives
  the canonical processed view this pass.)
- Implements `on_activated` (read channels from active record), `on_close`
  (flush debounce).

### Edits to existing files
- `core/settings.py` — add `("pipelines","🧩","Pipelines",…)` to `PAGES` (after
  `results`, before `batch`); add `"pipelines": ("imported", …)` to
  `PAGE_PREREQS`.
- `core/main_window.py` — add `PipelinesPage` to the `page_classes` dict in
  `_build_content_area` (~line 293).
- `core/theme.py` — QSS for `#nodeBoard`, sub-tab buttons, popup.
- `CLAUDE.md` — bump stale "V1.0" version line.

## Reused building blocks
`PluginBase.get_plugins/get_plugin` (`core/plugin_registry.py`),
`ParamEditor` (`widgets/common.py`), `EnhancedDataset` +
`MainWindow.recipe_stage()` (`pipeline/stages/recipe_stage.py`,
`main_window.py:555`), `MultiAxisViewer.set_channels` (`widgets/
multi_axis_viewer.py:677`), `JobRunner` + `AnalysisJob`/`ProgressReporter`
(`compute/`), `icon_button`/`tool_button`/`bind_toggle_icon` (`widgets/
icon_button.py`), `build_recipe` shape (`backend/recipes.py`).

## Key decisions / trade-offs
- **Custom `QGraphicsScene`, no NodeGraphQt** — honors the project's
  dependency-conservatism rule and the custom lip / hover-button / in-canvas
  popup chrome.
- **Executor reimplements the ~10-line recipe-apply loop** rather than importing
  `EnhancedDataset` into the pure core, so `pipeline_graph/` stays Qt-free and
  decoupled from the session/stage import graph. The Qt-side Apply path still
  reuses `EnhancedDataset` + `RecipeStage`.
- **Full-channel preview materialization** (matches today's Recipe page) for the
  MVP; current-frame / pyramid preview is a named follow-up.

## Deferred (Phase 2/3)
Analysis sub-tab execution (`PipelinePreviewJob`/`PipelineCommitJob`, overlay via
`set_frame_post_process`), Results sub-tab (`results_engine`, CSV table, toggle +
split), Export source-selector bridges, Undo/redo, batch-over-files.

## Verification
1. `python run.py` launches clean.
2. Headless graph tests (Qt-free): connect type-check, cycle rejection, fan-out,
   `save_pipeline`/`load_pipeline` round-trip.
3. Import → open Pipelines (prereq gate works) → wire input→Gaussian Blur→output
   → param popup → Preview ON updates viewer → Apply → Export "Processed Image"
   reflects the recipe.
4. Hover node → Disconnect/Duplicate/Delete with tooltips.
5. Save/load `.nd2s_pipeline.json` restores nodes/edges/params/positions.

# Phase 1.1 — Node-board UX refinements (V1.45.1)

Follow-up pass on the Processing board, driven by review feedback. The Qt-free
graph core, executor, and serialization are unchanged — this is purely the Qt
board UI plus the page control bar.

## Changes

1. **Vertical flow (ports top/bottom, lip left).** Connection anchors were on
   the left (inputs) / right (outputs) edges with the accent lip across the top.
   Now inputs anchor on the **top** edge, outputs on the **bottom** edge, so a
   pipeline reads top→bottom, and the lip moves to the **left** edge (the only
   edge no longer carrying ports). `NodeItem` height becomes fixed
   (`_title_h + _body_pad`) rather than `_n_rows()`-driven, ports spread evenly
   per edge via `_port_x(i, n)`, and the corner buttons move to a top-right
   margin clear of the centered top port. `EdgeItem._rebuild` switches the
   cubic-Bézier control points from x-offset to **y-offset** so wires curve
   vertically.

2. **Double-click a wire to disconnect.** `EdgeItem` becomes interactive: hover
   feedback (thicken + tooltip), a `QPainterPathStroker`-widened `shape()` for an
   easy hit target, `mousePressEvent` accepts the press so the view doesn't start
   a rubber-band and the double-click is delivered, and `mouseDoubleClickEvent`
   calls the new `NodeScene.disconnect_edge(edge_id)`. The `"__temp__"` drag wire
   is excluded via an `_interactive()` guard.

3. **Add button + catalog dialog.** Besides the existing right-click "Add
   operation" menu, a toolbar **Add** button opens `AddNodeDialog`
   (`widgets/node_board/add_node_dialog.py`): a `QListWidget` of node types and a
   detail pane showing (a) a concise description — the plugin's `description`
   plus its parameter labels — and (b) a **raw → processed** thumbnail pair. The
   raw image is a cached synthetic microscopy field (`_synthetic_raw`: Gaussian
   blobs + illumination gradient + noise, uint16); the processed image runs the
   actual registry plugin at default params (`_process`, wrapped in try/except
   with a uint8 fallback so a plugin that dislikes the synthetic input degrades
   to "preview unavailable" rather than crashing the picker). Accept drops the
   node at the visible-canvas center (`_new_node_pos`, small per-add cascade).

4. **Preview progress bar.** A slim `QProgressBar` next to Preview/Apply/Undo,
   fed by `JobRunner.job_progress` filtered to `"pipeline_preview"`. Shown when a
   preview job is submitted, advanced per channel/step (the executor's
   `progress_cb`), and hidden on done / preview-off / stage switch. Cancelled
   (superseded) previews leave it visible because the superseding submit already
   re-showed it.

## Files touched
- `widgets/node_board/node_item.py` — geometry: top/bottom ports, left lip,
  fixed height, button reposition.
- `widgets/node_board/edge_item.py` — vertical Bézier, hover, widened `shape()`,
  double-click → `disconnect_edge`.
- `widgets/node_board/node_scene.py` — `disconnect_edge(edge_id)`.
- `widgets/node_board/add_node_dialog.py` — **new** catalog dialog + preview.
- `widgets/node_board/__init__.py` — export `AddNodeDialog`.
- `pages/pipelines_page.py` — Add button, preview progress bar, `job_progress`
  wiring, `_on_add_node`, `_new_node_pos`, hint text.
- `core/theme.py` — QSS for the progress bar + dialog.

## Verification (1.1)
1. Headless smoke (`QT_QPA_PLATFORM=offscreen`): `AddNodeDialog` previews all 20
   specs with zero plugin failures; `NodeItem` reports its input port on the TOP
   edge and output on the BOTTOM; `NodeScene.disconnect_edge` removes an edge +
   its item; `PipelinesPage(None)` builds with the Add button enabled and the
   progress bar hidden.
2. `python scripts/_pipeline_graph_selftest.py` still green (core untouched).
3. In-app: Add → pick "Gaussian Blur" (see description + raw→blurred preview) →
   node drops with the input anchor on top, output on bottom, lip on the left →

# Phase 1.2 — Previewed node + interaction polish (V1.45.2)

Second refinement pass on the Processing board, again purely Qt/UI.

## Changes

1. **Sticky "previewed" node + golden highlight.** The viewer used to follow the
   current selection. It now tracks an explicit `_preview_node_id` on the page:
   `_preview_target()` prefers it (falling back to the primary Output, then the
   Input). The previewed node and **its whole connected component** (nodes +
   wires, edges treated as undirected via `_connected_subgraph`) get a gold
   outline (`Settings.ACCENT_GOLD = #ffc83d`); the previewed node is drawn
   thicker. Implemented with `NodeItem.set_highlighted(on, previewed=)`,
   `EdgeItem.set_highlighted(on)`, `NodeScene.set_highlight(node_ids, edge_ids,
   preview_id)`, and `PipelinesPage._update_preview_highlight()` (called on
   double-click, graph change, stage select, load, activation).

2. **Interaction model.** `_on_node_double_clicked` now promotes a node to the
   previewed node (was: rename Input/Output). `_on_scene_selection` only opens
   the param pop-up and no longer touches the preview — so a single click shows
   params, a double-click sets the preview, and clicking off keeps both the
   preview result and the gold highlight. (Trade-off: double-click no longer
   renames bridge nodes; the preview promotion is the more valuable gesture and
   bridges still auto-name.)

3. **Drag nodes from the top anchors.** Connections only ever start from output
   (bottom) ports, so input (top) ports had no press role yet sat on top of the
   grab area. They are now `setAcceptedMouseButtons(NoButton)`, so a press on a
   top anchor falls through to the movable node body — you can drag a node by its
   top anchor. Inputs stay valid drop targets on release (`_port_at` uses
   `items()`, which ignores accepted-button masks).

4. **Bigger, richer Add dialog.** Minimum size 900×640, 210 px thumbnails, a
   scrollable lengthy description (curated `_DETAILS` paragraph per op + per-param
   notes), and a larger 240² synthetic field with comprehensive content —
   multi-size blobs, large diffuse debris, fine texture, vignette × diagonal
   illumination heterogeneity, read noise, and hot pixels — so every plugin's
   effect is visible.

## Files touched (1.2)
- `core/settings.py` — `ACCENT_GOLD`.
- `widgets/node_board/node_item.py` — highlight/previewed state + border priority.
- `widgets/node_board/edge_item.py` — `set_highlighted` gold pen.
- `widgets/node_board/port_item.py` — input ports mouse-transparent.
- `widgets/node_board/node_scene.py` — `set_highlight`.
- `widgets/node_board/add_node_dialog.py` — larger dialog/thumbnails, `_DETAILS`,
  richer `_synthetic_raw`.
- `pages/pipelines_page.py` — `_preview_node_id`, `_update_preview_highlight`,
  `_connected_subgraph`, reworked selection/double-click, `_preview_target`.
- `core/theme.py` — description-scroll transparency.

## Verification (1.2)
1. Headless: dialog ≥ 900×640, all 20 specs preview, shortest description ≫ the
   old one-liner, raw image 240² uint16; input ports report
   `acceptedMouseButtons() == NoButton`, outputs do not; `set_highlight` lights

# Phase 1.3 — Highlight repaint fix + elbow bridge routing (V1.45.3)

## Changes

1. **Golden-ghost fix.** `NodeItem.boundingRect` padded the exact body rect, but
   the previewed node's 3 px gold border strokes ~1.5 px outside it. Since
   `update()` only invalidates `boundingRect`, switching the previewed node left
   the outer ring of the old outline on screen. `boundingRect` now inflates by
   `scaled(3)` (the widest pen), and a new `shape()` override returns the tight
   body so hit-testing isn't loosened by the pad. (The highlight *state* was
   already correct — `set_highlight` clears every non-member node — this was
   purely a repaint-region bug.)

2. **Elbow bridge routing.** `EdgeItem._rebuild` replaces the vertical cubic
   Bézier with an orthogonal route: straight drop when the anchors share an x,
   else a two-bend elbow (down out of the output → across at `mid_y` → down into
   the input) via a new `_rounded_polyline(pts, radius)` helper that rounds each
   interior corner (radius clamped to half the shorter adjacent segment). The
   horizontal run sits in the vertical gap between the two nodes, so the wire
   never overlaps a node body, and lateral offset yields the two requested
   rounded corners.

## Files touched (1.3)
- `widgets/node_board/node_item.py` — padded `boundingRect` + tight `shape()`.
- `widgets/node_board/edge_item.py` — orthogonal rounded-corner routing.

## Verification (1.3)
1. Headless: switching the previewed node from a wired chain to a disconnected
   node clears `_highlight`/`_previewed` on every old-chain node; `boundingRect`
   is padded (x<0) while `shape()` stays tight; a laterally-offset edge path has
   >2 elements (rounded corners) and its y-range stays within the node gap, while
   an aligned edge is a 2-element straight line.
2. `python scripts/_pipeline_graph_selftest.py` green; `MainWindow` boots clean.

# V1.45.8 — Preview navigation & refresh polish

## Goal
Make the Pipelines preview behave like a real viewer: navigate all M positions,
refresh on the right triggers, and center the graph on tab switches.

## Approach (`pages/pipelines_page.py`)
- **All M in the viewer.** `_channels_for_m(record, m)` reads the displayed M
  from `record._raw_volume.all_channels_as_lazy(m=…)` (Recipe-page pattern;
  falls back to `_raw_channels`); `_record_n_multipoints` and a `_preview_m`
  tracker let `set_channels` pass the real `n_multipoints` so the M slider works.
- **Refresh on frame change.** `_on_viewer_coords` recomputes on an M change for
  all stages; Analysis re-screens on any frame change + refreshes its base on M
  change; Processing skips T (full stack already loaded).

# V1.45.23 — Loading a new file refreshes the Pipelines tab

## Report
Loading a new file on top of an old file did not transfer to the Pipelines tab —
the board kept showing the previous file's data (input node channel count, viewer
base image, preview/overlay).

## Root cause
`PipelinesPage` only refreshed in `on_activated`, which `MainWindow` calls **on
page navigation only**. Every other page also implements `load_from_experiment(
exp)`, which `MainWindow._on_experiment_changed` calls on every active-record
change (`ExperimentManager.active_changed`). The Pipelines page implemented
neither a `load_from_experiment` nor any record-change hook, so a file loaded
while the tab was on screen never reached it. Additionally `_ensure_input_node`
no-ops once an input node exists, so the carried-over graph kept the old channel
count.

## Fix (`pages/pipelines_page.py`)
- **`load_from_experiment(exp)`** — drops stale per-file state
  (`_analysis_screen_results`, `_analysis_results_per_m`, `_processing_planes`,
  `_proc_volume`, `_results_overlay_result`, `_results_rows` + clears the table),
  refreshes each stage's source node title, and — only when Pipelines is the
  visible page — calls `_refresh_active_view`. The pipeline graph itself is
  preserved so a built pipeline carries to the new file.
- **`_refresh_active_view()`** — shared by `on_activated` and
  `load_from_experiment`: re-highlights, re-sets the merged view mode, shows the
  Analysis base, requests a preview, frames the graph.
- **`_refresh_input_node(stage)`** — updates an existing input node's title to the
  new channel count (or creates it via `_ensure_input_node` if absent).
- `on_activated` refactored to `_ensure_input_node` + `_refresh_active_view`.

## Verification
1. `python scripts/_pipeline_graph_selftest.py` green.
2. Offscreen import + `hasattr(PipelinesPage, 'load_from_experiment')` /
   `'_refresh_input_node'` both True.
3. In-app: load file A → Pipelines (input "(N ch)", preview shows A) → load file B
   while on Pipelines → input updates to B's channel count, viewer/preview now
   show B, graph preserved.
