# V1.77 — Prism channel-overlay node + view-only edges

> A new **Prism** node (`special:prism`) for the Pipelines node board, rendered as a
> "cool-looking" 2.5D faceted prism/gem (new `ShapeKind.GEM`). It splices into any
> analysis chain and, using the channel it is fed, can **add / remove / replace** the
> analysis channels flowing downstream, and/or **converge a channel into another node as
> a view-only overlay**. Paired with a generic, node-agnostic **view-only edge** (a
> dotted wire toggled by clicking it): a view-only channel is fed to the viewers only,
> never to analysis, so it can never confuse an analysis pipeline or its downstream
> effects.

## Goal

The flagship use (from the request):

```
Granule Volume Mask ─(solid, scope=Objects)────────────────▶ DVC   (correlates mCherry, per granule)
        └─────────▶ Granule Boundary ─▶ Prism(green) ─(dotted / view-only)─▶ DVC
```

- **Split**: the Granule Volume Mask fans out to two downstream branches.
- **Branch A** (solid, `scope=Objects`): DVC runs per-granule on **mCherry**.
- **Branch B** (view-only): Granule Boundary → **Prism** (fed the **green** channel via a
  rainbow channel-source pill) → **reconverges** into DVC on a **dotted** edge.
- DVC keeps correlating mCherry; the green channel is loaded into DVC's **3-D object
  overlay** (and the rest of the DVC viewer) as a **volumetric overlay auto-clipped to
  the shell between the volume-mask boundary and the boundary-extraction updated
  boundary**. Because DVC never *runs* on green, there is no correctness risk.

## Key user decisions (locked)

1. **Channel picker** — the prism reads the channel(s) wired into its **rainbow port**
   (the V1.48 channel-source pill idiom; consistent with DVC / mask3d / Registration).
2. **Overlay region** — **always auto-clip to the shell** when a Granule Boundary node is
   upstream of the prism. The shell already exists as data:
   `record._granule_bands_by_m[m][t][gid]` is exactly `(dilated mask) − (mask)`.
3. **Edge toggle** — **click the wire directly** to flip solid↔dotted (analysis↔view-only).
4. **Gem look** — **upright faceted prism**: flat top/bottom, angled shoulders, vertical
   facet seams with light/dark gradient faces (cleanest port anchoring).

## Why this fits the existing architecture

- There is already a **two-layer graph**: a structural layer (IMAGE/BINARY/DATA/ANY wires)
  and a **channel-flow layer** (rainbow `CHANNEL` ports, V1.48). `channel_sets()` already
  decides which channels each node computes on, by a topological **union**.
- **Split + reconverge** is already supported by `GraphRunner` (a node with two structural
  inputs runs once both live predecessors finish).
- **DVC already has a viewer-only overlay** — `dvc_panel._CONTEXT_MODES` includes
  `"Shell (iso)"`; `context_provider(m,t,ci)` + `set_context_channel(vol, mode, opacity)`
  draw a translucent channel cloud/shell around the object *after DVC compiles, never fed
  to correlation*. We route green through this.
- **Per-object DVC + the Frame/Object edge lever** (V1.68/V1.74) already run DVC
  per-granule. The prism does not re-implement any of it — it only *feeds* the overlay.

The one real gap the map surfaced: a plain channel-set **union** would hand DVC
`{mCherry, green}` and `_run_dvc` collapses that to `seg[0]` (ambiguous — it might
correlate green). Making the prism→DVC edge **view-only** resolves it: view-only edges are
excluded from `channel_sets`, so `channel_sets(DVC) == {mCherry}` (unambiguous), and green
rides a parallel display-only set into the context overlay.

## Design

### View-only edge (generic, node-agnostic)

- New edge flag `edge.params["view_only"] = True`, mirroring the V1.68 scope lever
  (`edge.params["scope"]`) — round-trips through `to_dict`/`from_dict` with **no schema
  bump**.
- **Analysis propagation ignores view-only edges.** `channel_sets()` skips any incoming
  edge flagged view-only → a view-only channel never enters a node's analysis and never
  propagates downstream as an analysis channel. Generic across **all** analysis nodes.
- A **parallel** `display_channel_sets()` collects the view-only channels arriving at each
  node, purely for the viewers.
- The still-present structural edge keeps `GraphRunner` ordering (source runs before dst),
  so the prism computes its overlay before DVC populates.
- Rendered **dotted** (`Qt.PenStyle.DotLine`), distinct from the channel wire's DashLine.
- Toggled by a plain left-click on the wire (eligible = interactive, non-loop, non-channel
  edge).

### Prism node (`special:prism`, `ShapeKind.GEM`, orange SPECIAL)

- Ports (copy the Registration recipe = Option A): structural **IMAGE in**, structural
  **ANY out**, rainbow **CHANNEL in/out** (via `spec_takes_channels`, which needs IMAGE in
  the input types). ANY out pairs with DVC's IMAGE input (like mask3d).
- Params:
  - `channel_op`: choice `add` / `remove` / `replace` (default `add`) — how the prism's
    **injected** (rainbow-wired) channels combine with the structural upstream channels
    for **analysis** (solid) edges.
  - `overlay_render`: choice `Shell (iso)` / `Cloud (volume)` / `Cloud (MIP)` (default
    `Shell (iso)`) — how a **view-only** overlay renders in the DVC viewer.
- `op_produces_objects` → **False** (the prism consumes/re-routes; it does not emit its own
  objects). No `io.py` bump.

### Channel propagation (`executor.channel_sets`)

Per node, split incoming (non-view-only) edges into structural vs rainbow-channel
contributions, then:
- non-prism node: `struct ∪ chan` (identical to today, minus view-only edges).
- prism `add`: `struct ∪ chan`; `replace`: `chan or struct`; `remove`: `struct − chan`.

New `display_channel_sets(sl, all_names)`: for each **view-only** edge, the destination's
display set gains the source's contribution — for a **prism** source that is its
rainbow-**injected** channels (so the overlay is exactly what you plugged in, e.g. green);
for any other source it is `channel_sets(src)`.

### DVC shell overlay

- `_run_prism(node)` (pass-through, like `_run_exclude`): publishes
  `record._prism_overlay_by_m[m] = {channel, channel_idx, shell:(Z,H,W) bool | None,
  render}`. `channel` = the prism's injected channel; `shell` = union of
  `record._granule_bands_by_m[m][t][gid]` when a Granule Boundary node is upstream (via the
  reference-T `_granule_entry` fallback), else `None`. Ordering is guaranteed by the
  view-only structural edge (DVC gates on the prism), so no pre-Run pass is needed.
- `_populate_dvc_panel`: when `record._prism_overlay_by_m[m]` exists, wrap the existing
  `context_provider` so the overlay channel volume is clipped to the shell
  (`np.where(shell, v, 0)`), and default the panel's context channel + mode to
  (green, render). Everything else (per-granule crop, surface, "All granules") is the
  existing V1.74 path.

## Post-review revisions (adversarial review, 6 confirmed findings)

A 4-dimension adversarial review (channel-logic reviewer found **nothing** — core routing
is correct) surfaced 6 confirmed issues, all fixed:

- **Reconvergence was too broad (medium ×3).** The first cut made *any* second wire into
  *any* non-channel input port a view-only overlay — which broke redrag-to-replace for every
  node and was order-dependent (prism-before-mask silently made the mask view-only → DVC
  correlates the wrong branch). **Fixed:** normal nodes keep one-wire replace; only a **DVC**
  port accepts a second convergent wire, and the **object-producing source (mask) is always
  the analysis wire regardless of order** (a later object-producer demotes an existing
  non-object feed to view-only). Verified order-independent by test.
- **View-only edge showed a (live) scope pill and couldn't be toggled back (medium).**
  **Fixed:** `_apply_edge_scope_lever` skips view-only edges, so no overlay wire carries the
  Frame/Objects pill and the click-the-wire toggle stays free to revert it.
- **`set_context_default` guard misread channel index 0 (medium).** `int(x or -1) >= 0`
  treats data `0` (the first channel) as "not chosen". **Fixed** with an explicit
  `is not None` check.
- **Single-click-to-toggle footgun (low, accepted).** A stray click on a structural wire
  flips it view-only (dropping its channel from analysis on channel-wired graphs). This is
  the locked user decision (#3: "click the wire directly"); it is reversible and visibly
  dotted. Left as-is; the flagship uses the DVC reconvergence path (auto view-only), so the
  manual toggle is a secondary affordance.
