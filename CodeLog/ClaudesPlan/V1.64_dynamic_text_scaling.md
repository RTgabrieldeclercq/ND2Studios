# V1.64 — Dynamic screen-size text scaling

## Goal

Make GUI text (buttons, labels, inputs, menus, dialogs) grow with the size of
the monitor so the app is legible on large lab displays, **without** letting
the enlarged text overflow the controls that contain it.

## Problem

- All GUI font sizes live in `nd2studios/core/theme.py` as fixed `pt` values
  (`font: 10pt "Helvetica Neue"`, etc.).
- `nd2studios/__main__.py` pins `QT_FONT_DPI=96`, which is PyDracula's
  workaround to keep chrome consistent — but it also means `pt` fonts do **not**
  grow with DPI. The only way font size changes is by rewriting the `pt` values.
- The existing `ui_scale()` / `scaled()` (in `widgets/icon_button.py`) tracks
  **DPI only**; it does not respond to physical screen size, so a big 4K desktop
  monitor at 100% scaling shows exactly the same small text as a 1080p laptop.

## Approach

One scale factor, applied to both text and the geometry that holds it, so
proportions never change and text cannot overflow.

1. **`screen_scale()`** (new, `widgets/icon_button.py`) — a clamped growth factor
   derived from the primary screen's available **logical height** relative to a
   1080p baseline:
   - `1.0` at/below 1080p (identical to today — zero regression on current
     setups).
   - Grows by `SCREEN_SCALE_SLOPE` (0.5) of the excess height, capped at
     `SCREEN_SCALE_MAX` (1.5). e.g. 1440p → ~1.17, 4K → 1.5.
   - Uses *height* (not diagonal/width) so an ultrawide aspect ratio does not
     inflate the factor.

2. **`ui_scale()`** = `dpi_factor × screen_scale()`. `scaled()` therefore grows
   all pixel geometry (button squares, spin-box widths, icon edges, spacing) by
   the same screen factor as the text. Because `dpi_factor ≥ 1`, any fixed-size
   text widget (e.g. a `QSpinBox`) grows at least as fast as its font → digits
   never clip.

3. **`build_stylesheet()`** (`core/theme.py`) — a scaling pass multiplies every
   QSS `pt` font size **and** every `px` dimension (`min-height`, `padding`,
   `border-radius`, `min/max-width`, arrow sizes) by `screen_scale()` before the
   arrow images are injected. Fonts and their containers scale together, so on a
   larger screen a button is both taller and larger-typed in the same ratio as
   today → no overflow. At factor `1.0` the stylesheet is returned unchanged.

4. **Chrome heights** (`core/main_window.py`) — the title-bar and bottom-bar
   `setFixedHeight(...)` values (raw constants, not `scaled()`) are multiplied by
   `screen_scale()` so their enlarged text has room. (Sidebar width constants are
   unused since the V1.44 top-tab-bar migration, so they need no change.)

## Files to modify

- `nd2studios/widgets/icon_button.py` — add `screen_scale()` + constants; fold it
  into `ui_scale()`.
- `nd2studios/core/theme.py` — add `_scale_qss()` pass in `build_stylesheet()`.
- `nd2studios/core/main_window.py` — scale the two text-bearing chrome heights.

## Key decisions

- **QSS scaled by `screen_scale()` only, not the full `ui_scale()`.** QSS `px`
  values were never DPI-multiplied by the app (Qt's own high-DPI path handles
  that), so applying only the *new* screen factor keeps the baseline (1080p)
  render byte-identical and avoids double-scaling on high-DPI panels.
- **Canvas/`QPainter`-drawn text** (node board, filmstrip thumbnails) is out of
  scope — those live on independently zoomable graphics views.
- Factor is **clamped** (`[1.0, 1.5]`) so the layout can never blow out past what
  the window can hold.

## Addendum — container clipping fix

**Symptom:** after the text scale-up, some panels (e.g. the LUT histogram tab)
rendered clipped/cut off.

**Cause:** ~125 `setFixed*` / `setMinimum*` / `setMaximum*` calls across the app
used **raw pixel literals** instead of `scaled()` (against the codebase's own
convention). Their text grew but the containers stayed baseline-sized, so the
content clipped — most visibly where a hard `setMaximumWidth(...)` / fixed height
capped a panel (LUT sidebar `EXPANDED_WIDTH = 340`, histogram canvas max-height,
spin-box widths, etc.).

**Fix:** wrap those raw-pixel geometry values in `scaled()` so containers grow in
lockstep with the text. Because `scaled()` folds in `screen_scale()`, this is a
no-op at the 1080p baseline. Scope: the geometry *setters* and pixel size
constants (incl. collapse-animation width endpoints); `setContentsMargins` /
`setSpacing` were intentionally left (they don't clip). `QGraphicsScene` /
matplotlib figure / numpy dimensions were deliberately **not** touched.
