# V1.47 — SerialTrack PTV Plots & Analysis Tab

## Goal

Surface SerialTrack's Particle-Tracking-Velocimetry (PTV) / digital-volume-correlation
analysis inside ND2Studios as a new **"SerialTrack" tab in the Pipelines image viewer
stack** (alongside the existing *Spatial Maps* tab). Bring ND2Studios to parity with the
plots already proven in the standalone `SerialTrack_Python` app, **plus** PTV-specific
views that neither that app nor Cell-Tracker currently has. Support both 2D and 3D data
as a first-class architectural concern.

Reference apps (siblings, same GitHub parent dir):
- `SerialTrack_Python` — the standalone PTV GUI whose plots we port.
- `Cell-Tracker` — the interaction model (slider ↔ viewer ↔ plot bidirectional pick).

## Key finding that shapes the architecture

In ND2Studios, SerialTrack currently runs **only to chain `track_id`** onto measurement
rows (`_link_group_serialtrack` in `backend/object_tracker.py` sets `strain_n_neighbors=0`
and discards the `TrackingSession`). The rich displacement/strain/deformation-gradient
fields SerialTrack can compute are **thrown away**. So a real PTV panel needs a **data
layer** that (re)builds those fields from the tracked rows.

Also: **ND2Studios collapses Z at load** (2D pipeline). The data layer is therefore written
**D-agnostic** (D = 2 or 3, inferred from presence of `centroid_z_px`). The 3D scatter /
iso-surface view activates only when 3D coordinates are present (imported 3D centroids or a
future 3D detector); it degrades gracefully to 2D. This keeps 3D first-class in code while
being honest that today's pipeline feeds 2D.

## Approach

### 1. Backend data layer — `nd2studios/backend/serialtrack_analysis.py` (Qt-free, new)

A pure numpy/scipy module (no PySide6), following backend-purity rules, that turns tracked
measurement rows into PTV analysis products. Reuses `backend/serialtrack/fields.py`
(`DisplacementField`, `StrainField`, `compute_gridded_strain`) and
`backend/serialtrack/regularization.py` (`scatter_to_grid_multi`).

Products (all keyed by frame `t`, per `(channel, m_position)` group):
- **Trajectories** — `(N_tracks, n_frames, D)` NaN-gapped matrix, chained from `track_id`.
- **Per-particle displacement vectors** — `disp[t]: (N, D)` = pos(t)−pos(ref) (cumulative)
  or pos(t+1)−pos(t) (incremental), toggleable.
- **Gridded `DisplacementField`** per frame via `scatter_to_grid_multi`.
- **Velocity** = displacement / `time_step` (honors `pixel_size_um`, `tstep`).
- **`StrainField`** — deformation gradient `F` and infinitesimal strain `ε` via
  `DisplacementField.gradient()` / `.strain()`.
- **Derived scalars** — displacement magnitude, effective strain, `det(F)` (Jacobian /
  volumetric change), **divergence** (dilatation) and **curl / vorticity** of the field.
- **Stress + Von Mises** — constitutive model (linear isotropic to start; extensible to
  Neo-Hookean / Mooney-Rivlin) ported from `SerialTrack_Python/pages/stress_page.py`.

Caching: a per-`(group, t, compute-signature)` cache so scrubbing/playback doesn't
recompute the griddata interpolation (mirror `SpatialMapsPanel`'s field cache).

### 2. UI panel — `nd2studios/widgets/serialtrack_panel.py` (new)

`SerialTrackPanel(QWidget)`, modeled on `widgets/spatial_maps_panel.py` (compact + full
sidebar layouts, `FrameStrip` T-scrubber, play/pause/FPS, cmap combos, scale bar,
auto/global scale, template save/load). `set_data(...)` receives tracked rows + channels +
`field_shape` + `n_frames` + `pixel_size_um`. Uses the Dracula-themed `MplCanvas`
(`widgets/common.py`) for 2D plots and a lazily-created **pyqtgraph `GLViewWidget`** for the
3D scatter/iso-surface (pyqtgraph is already a dependency).

**Plot / view modes** (a "View" combo):

*Ported from SerialTrack_Python (parity):*
1. Component **heatmap** (`imshow`) — displacement u/v/w, velocity, strain εij (Z-slice
   slider for 3D).
2. **Filled contour** / **line contour** (`contourf` / `contour`).
3. **Quiver vector field** (magnitude-colored) + **heatmap+quiver overlay**.
4. **Particle trajectories** — XY / XZ / YZ projections, colored by displacement or time.
5. **Von Mises + σij** stress maps.
6. **det(F) / Jacobian** and effective-strain scalar maps.
7. Multi-component side-by-side.

*PTV-specific additions (new to both apps):*
8. **Divergence (dilatation)** and **curl (vorticity)** maps.
9. **Principal-strain glyphs** (direction + magnitude crosses).
10. **Displacement-magnitude histogram / distribution** per frame; cumulative-vs-incremental
    toggle.
11. **Line-profile / kymograph** — mean/max/RMS displacement or strain along a user-drawn
    line vs frame (leverages the pick/ROI model).
12. **3D particle scatter / iso-surface** (pyqtgraph GL) when D==3.
13. Live tracking **dashboard** (tracking ratio, detected-vs-tracked, RMS-disp + timing) —
    from the per-frame summary already available.

### 3. Raw-image overlay — extend existing mechanism

`_paint_vectors_overlay` (`pipelines_page.py`) already draws per-cell and gridded velocity
arrows via `backend/track_overlays.py`. Add a **per-particle SerialTrack displacement
vector** overlay option (scattered `disp[t]`, magnitude-colored) so vectors sit on the
actual beads — fixing the gap where SerialTrack_Python only ever overlays *gridded* vectors.
Uses `MultiAxisViewer.set_frame_post_process`.

### 4. Bidirectional pick coupling (from Cell-Tracker)

Trajectory/plot lines drawn with matplotlib `picker=5` + `pick_event`; clicking a line
highlights that particle/track in the viewer overlay for the current frame, and clicking a
particle in the viewer selects its trajectory in the plot. Keyed on the panel's current T.

### 5. Session persistence (optional, later phase)

Retain the SerialTrack `TrackingSession` (or at least per-frame coords+disp) so
trajectories/vectors survive save/reload. `SerialTrack_Python/serialtrack/results.py` has a
full HDF5/.mat/CSV exporter (incl. MATLAB `parCoord_prev`/`uvw_B2A_prev`) that is unused —
port the parts we need. Until then, the panel recomputes from the persisted tracked rows.

## Wiring the tab (mirror the Spatial Maps tab)

`pipelines_page.py`:
- `_viewer_stack` (line ~694) already holds `viewer` (idx 0) and lazily the Spatial Maps
  panel. Add the SerialTrack panel as another stacked widget, created lazily like
  `_spatial_panel` (see lazy-create at line ~2335).
- Add a "SerialTrack" entry to the overlay/view tab row that swaps the stack to the panel.
- Feed it via the same `_overlay_rows()` / tracked-row source used by the vectors overlay.

No new sidebar page, no `Settings.PAGES` change (per user decision: new **tab**, not page).

## Key decisions

1. **Row-derived fields, not persisted session (phase 1).** Rebuild displacement/strain
   fields from tracked rows using SerialTrack's own `fields.py`, so the feature works on any
   existing tracked experiment with no engine change. Native-session retention is a later
   enhancement.
2. **matplotlib for 2D, pyqtgraph GL for 3D.** Both already dependencies; matches the repo's
   established split (matplotlib plots, pyqtgraph image canvas).
3. **Mirror `SpatialMapsPanel`.** Reuse its compact/full sidebar pattern, `FrameStrip`,
   caching, template system, and scale bar rather than inventing new chrome.
4. **D-agnostic data layer.** 2D today; 3D views light up automatically when `centroid_z_px`
   is present. Honest about the Z-collapse constraint.
5. **Reuse, don't resurrect.** The `nd2studios/widgets/results/*_view.py` files are dead
   code with broken imports — do **not** build on them.

## Phasing (each phase independently shippable)

- **P1 — Data layer + panel + tab. ✅ DONE.** `serialtrack_analysis.py` (verified against
  an analytic deformation), `SerialTrackPanel` (`widgets/serialtrack_panel.py`) wired into
  the Pipelines viewer stack as the "SerialTrack" tab. Shipped *more* than the P1 scope:
  trajectories (XY/XZ/YZ), all ~17 scalar fields (displacement/velocity/strain/stress/
  divergence/curl/det(F)/effective-strain/Von Mises), heatmap/contour/quiver/heatmap+quiver,
  displacement histogram, and tracking dashboard — all verified headless in 2D and 3D.
  Remaining for later phases: publication export polish (P2), principal-strain glyphs +
  line-profile kymograph + per-particle raw-image vector overlay + bidirectional pick (P3),
  pyqtgraph GL 3D scatter/iso-surface (P4), session persistence (P5).
- **P2 — Field parity.** Strain εij, det(F), Von Mises/stress, contours, multi-component,
  divergence/curl. Publication export via existing plot infra.
- **P3 — PTV extras + interaction.** Displacement histogram, principal-strain glyphs,
  line-profile kymograph, per-particle vector overlay on the raw image, bidirectional pick.
- **P4 — 3D.** pyqtgraph GL scatter / iso-surface for 3D datasets.
- **P5 — Persistence.** Retain/serialize the SerialTrack session so trajectories survive
  reload; wire `results.py`-style export.
