## Section 1 — Overall approach (one path, not five panels)

**Recommendation: implement all five as overlay *modes* on the existing Pipelines
viewer, NOT as new matplotlib side-panels.** Reuse the exact mechanism that
`segmentation` / `tracks` / `vectors_*` already use, and reuse the existing in-tab
2D↔3D toggle for the 3-D views.

### Why this and not the DVC/SerialTrack/Spatial *panel* pattern
The DVC / SerialTrack / Spatial-Maps panels (Report 2) are **standalone matplotlib
figures** in `self._panel_stack` (`MplCanvas`) — the right tool for *plots*
(trajectories, heatmaps, histograms). None of the five granule viewers is a plot:
every one of them is **marks burned onto the displayed microscopy frame**
(crosshairs, dots, lines, mask contours). Report 1 is emphatic that the only
portable way to draw onto the frame is the numpy post-process hook
`MultiAxisViewer.set_frame_post_process(fn)` — the QPainter callback is a **no-op on
the GPU canvas** (`gpu_image_canvas.py:462`). The existing `segmentation`/`tracks`/
`vectors_*` overlays already do exactly this via `_composite_pipeline_overlay`
(`pipelines_page.py:4005`). So the granule 2-D viewers are overlay modes, full stop.

For 3-D, reuse the existing in-tab toggle (`_btn_view3d` → `_toggle_view3d`
`pipelines_page.py:1532` → `_feed_view3d` `:1540` → `PyVista3DViewer`
`_view3d_stack` `:1443`), not the standalone `Viewer3DDialog` (which no page
currently instantiates — Report 3 §1).

### How each viewer is shown
- **A tab per node** on the existing `_overlay_tabbar`. Five keys appended to
  `self._overlay_tab_keys` (`pipelines_page.py:1157`) with index-aligned labels in
  the `addTab` loop (`:1360`). This mirrors how `tracks`/`vectors_cells`/
  `vectors_field` are three separate gated modes, so each granule node is
  individually inspectable.
- **Gated by data**: `_update_overlay_tabs_available` (`:4404`) shows a granule tab
  only when its store is non-empty — exactly like `"dvc": bool(self._dvc_series_by_m)`
  (`:4426`).
- **Auto-selected on Run**: the five granule ops all finish through the single
  shared handler `_finish_granule(result)` (`pipelines_page.py:6765`) — there is
  **no** per-node finish handler (unlike DVC's `_finish_dvc`). After it publishes
  the store via `_granule_publish` (`:6732`), add a dispatch that calls
  `_update_overlay_tabs_available()` then `_select_overlay_tab(<mode>)` — the same
  move `_finalize_dvc_publish` makes with `_select_overlay_tab("dvc")` (`:7082`).
- **On preview/double-click** (optional, nice-to-have): `_on_node_double_clicked`
  (`:1980`) promotes a node to "previewed". A granule op→mode map there mirrors how
  Spatial Maps opens from preview. Not required; the Run-finish auto-select is the
  primary path. Do **not** hook single-click selection (`_on_scene_selection`
  `:1907`) — by design it only opens the param popup and never changes the shown
  result (Report 2 §3).

### Important wiring subtlety (do not skip)
Granule modes are **hook modes, not panel modes** — so they do NOT need branches in
`_on_overlay_tab_changed` (`:4345`) or `_select_overlay_tab` (`:4378`). When the user
clicks a granule tab, `_on_overlay_tab_changed` falls through to its final
`self.viewer.set_frame_post_process(self._composite_pipeline_overlay)` (`:4376`),
which re-arms the hook and repaints — correct. **But** `_select_overlay_tab` sets the
tabbar index under `blockSignals(True)` (`:4389`), so it will NOT fire
`_on_overlay_tab_changed`. Therefore, whenever you programmatically select a granule
mode (in `_finish_granule`), you must **also** call
`self.viewer.set_frame_post_process(self._composite_pipeline_overlay)` explicitly
afterwards to invalidate the pp cache and repaint. (`set_frame_post_process` itself
calls `invalidate_post_process_cache()` + `_do_refresh()` — Report 1 §1.)

The overlay hook must be armed in the first place; `_update_merged_view_mode`
installs it (`pipelines_page.py:1894`). Granule modes ride the same install as
`segmentation`, so no new install logic is needed beyond the explicit re-arm above.

## Section 2 — Shared categorical coloring (stable per granule id)

**Requirement:** the mask node must use the SAME color per granule as the cluster
node, stable per id. Two facts make this non-trivial (Report 4 §3–§5):

1. `generate_track_colormap` (`backend/track_overlays.py:24`) is **set-dependent**:
   the color for id X depends on X's position in the sorted unique id list AND on the
   count `n` (it permutes `rng.permutation(n)/n` and draws S/V per id in order). Pass
   a different id set → X changes color. So it is **not** "stable per id" in
   isolation and must NOT be used per-node with different id sets.
2. The nodes live in **different id spaces**: cluster store = *initial GMM* labels;
   tessellation `point_labels` = *final merged* ids; mask/boundary `_labels` =
   *dense 1-based* ids re-keyed to `1..K` in ascending original-id order
   (`granule_mask.py:248-249`). These integers do **not** coincide.

### The helper — a PURE, set-independent, id-keyed color function
Add to `nd2studios/backend/analysis/granule_types.py` (backend-pure, Qt-free — it is
already the "single source of truth"; avoids a backend→page import of
`analysis_page._LABEL_PALETTE`):

```python
# granule_types.py  (append)
# Fixed categorical palette (RGB 0-255). Copy of the 20-tuple used by
# analysis_page._LABEL_PALETTE so 2-D and 3-D granule overlays agree; kept here so
# backend stays Qt-free. If you touch one, touch both (see verification §7).
GRANULE_PALETTE: Tuple[Tuple[int, int, int], ...] = ( ... 20 RGB tuples ... )
NOISE_COLOR = (128, 128, 128)

def granule_color(gid: int) -> Tuple[int, int, int]:
    """Deterministic, set-INDEPENDENT color for a granule id.

    Same id -> same color, regardless of what else is on screen. gid<=0
    (background / NOISE_LABEL) -> gray. This is what makes the mask node match the
    cluster node: both call granule_color(<the same id>).
    """
    g = int(gid)
    if g <= 0:
        return NOISE_COLOR
    return GRANULE_PALETTE[(g - 1) % len(GRANULE_PALETTE)]
```

Copy the 20 RGB values verbatim from `analysis_page.py:2091` (`_LABEL_PALETTE`) so
the palette is identical. (Do **not** import the page into backend.)

### Making cluster and mask share the SAME color for the SAME granule
Because the id spaces differ, "same color as cluster" is only literally true if both
nodes key on the same integer. Guidance, in order of preference:

- **Cluster node**: color beads by the tessellation **final** ids
  (`GranuleTessellation.point_labels`) **when the tessellation store exists**;
  otherwise fall back to the cluster store's GMM labels. (Report 4 §3 explicitly
  recommends preferring `point_labels` once Node 3 has run.)
- **Mask / Boundary nodes**: color by their own dense 1-based `_labels`.
- **Exact cluster↔mask identity** requires the dense→final map. The re-key is
  deterministic (surviving granules → `1..K` ascending original-id order,
  `granule_mask.py:248-249`), so it *can* be reconstructed as
  `dense_k → sorted(tess.boundaries.keys())[k-1]` **iff every candidate granule
  survives voxelization**. Some may drop (empty voxelization), which would shift the
  mapping. **Safest path:** ship `granule_color` keyed on each node's native id
  (guarantees per-id stability and one consistent palette look), and treat exact
  bead↔mask color identity across the id-space boundary as a follow-up that must be
  verified against `granule_mask.py`'s survivor set before relying on it. Note this
  caveat in the CHANGELOG so it is not mistaken for a guarantee.

`granule_color` is the single helper reused by the cluster 2-D painter, the mask 2-D
painter (per-label fill/outline color), the boundary painter, and every 3-D
per-label actor (Section 3). Draw noise (`NOISE_LABEL = -1`) with `NOISE_COLOR` or
skip it.

## Section 3 — Per-node implementation

All 2-D painters are methods on `PipelinesPage`, dispatched from
`_composite_pipeline_overlay` (`pipelines_page.py:4012`, which currently ends with
`return rgb`). Each: copy the array first (`out = np.ascontiguousarray(rgb).astype
(np.uint8)` — never mutate the cached base), read the current plane with
`_m, _t, z = self.viewer.coords()`, read the store via
`self._granule_read_store(self._active_record(), ATTR)`, resolve the `(m,t)` entry
with the fallback in Section 6, draw, return `out`. `cv2` colors are written in the
same channel order as the array (R=0), so pass `granule_color(...)` tuples directly
(Report 1 §6).

**Per-Z filtering rule (all point-based overlays):** the Z slider is a real slice
only when `z_mode == "none"` (Report 1 §3; slider shown only at
`multi_axis_viewer.py:766`). Read the record's z mode
(`getattr(record, "z_view_mode", "max")`). If it is a projection (`max/mean/min`),
draw **all** points (the frame is a projection — no meaningful plane). If `"none"`,
filter to the plane: `abs(pt_z - z) <= 0.75`.

**Coordinate mapping (all point-based overlays):** store points are `(z,y,x)` voxel
indices in **registered FULL-FRAME** pixels (Report 4 §2). The displayed frame may be
cropped. Invert the crop offset the detect worker added: `_run_bead_detect`'s worker
adds `pts[:,1]+=oy; pts[:,2]+=ox` (`pipelines_page.py:934-935`) where `(oy,ox)` comes
from `_read_registered_cropped` (`:881`, `off_y,off_x = y0,x0` at `:907`) driven by
`self._crop_rect()` (`:3002`, `Optional[Tuple[int,int,int,int]]`). So in the painter,
derive `(oy,ox)` from `self._crop_rect()` the **same way** the worker does and
**subtract**: `x_disp = x - ox; y_disp = y - oy`. Draw at `(int(round(x_disp)),
int(round(y_disp)))` (cv2 point order is `(x,y)`; array index is `[y, x]`).
> Verify: confirm the exact tuple order of `_crop_rect()` at `pipelines_page.py:3002`
> and reuse `_read_registered_cropped`'s decomposition rather than re-deriving, so the
> inverse exactly cancels the worker's forward add.

### Node 1 — Bead Detection (`_paint_granule_beads`)
- **Read:** `GRANULE_POINTS_ATTR` → `(N,3)` `(z,y,x)` voxels.
- **2-D:** for each in-plane point, `cv2.drawMarker(out, (x,y), color=(255,255,0),
  markerType=cv2.MARKER_CROSS, markerSize=scaled-ish 11, thickness=1,
  line_type=cv2.LINE_AA)` (Report 1 recipe b). Crosshairs are single-color (no id
  yet at detect stage).
- **3-D:** crosshair glyphs at world `(x,y,z)` µm. Backend adapter builds a
  `GranuleScene` with `points_um` and `draw_points_as="crosshair"`; widget merges
  three `pv.Line` arms and `.glyph(geom=cross, scale=False, orient=False)`
  (Report 3 recipe a). Simplest fallback if glyphs misbehave:
  `add_points(pts, render_points_as_spheres=True, point_size=8)`.

### Node 2 — Granule Clustering (`_paint_granule_clusters`)
- **Read:** points (`GRANULE_POINTS_ATTR`) + labels. Prefer `point_labels` from
  `GRANULE_TESS_ATTR` when present, else `GRANULE_LABELS_ATTR` (Section 2).
- **2-D:** `cv2.circle(out, (x,y), radius=3, color=granule_color(label),
  thickness=-1, lineType=cv2.LINE_AA)` per in-plane point. Skip/gray `label<=0`.
- **3-D:** `GranuleScene` with `points_um` + `point_labels`; widget draws one
  `add_points`/glyph actor per unique label colored `granule_color(id)/255`
  (Report 3 recipe a/d — per-label actors guarantee palette match with 2-D).

### Node 3 — Granule Tessellation (`_paint_granule_tess`)
- **Read:** points + `point_labels` from `GranuleTessellation`; `mode` (`.mode` =
  `"alpha_shape"|"voronoi"`) selects the edge geometry (Section 4).
- **2-D:** dots (as Node 2, colored by `point_labels`) + tessellation lines. Because
  edges span z, do NOT z-filter the *edges*; compute the 2-D tessellation on the
  projected `(x,y)` of all points and draw the full edge set as a neutral overlay:
  `cv2.line(out, (xa,ya), (xb,yb), color=(0,255,255), thickness=1,
  lineType=cv2.LINE_AA)` (Report 1 recipe c). Dots may still be z-filtered in
  `z_mode="none"`.
- **3-D:** `GranuleScene` with `points_um`, `point_labels`, and `edges (E,2)`; widget
  builds explicit VTK line connectivity `[2,i,j]` per edge → `pv.PolyData(pts,
  lines=...)` → `.tube(radius=...)` (Report 3 recipe b).

### Node 4 — Granule Volume Mask (`_paint_granule_mask`)
- **Read:** `GRANULE_MASKS_ATTR` → entry dict; use `entry[COMBINED_LABELS_KEY]`

- **2-D per-plane:** slice `lbl_z = labels_vol[z]` (or the projected max-label plane

  `granule_color(gid)`. Two build options:
  - **Reuse** `analysis_page._overlay_labels(out, lbl_z, alpha=..., color=None,

    (Section 2 palette copy). Honors the user overlay-style controls
    (`self.viewer.overlay_style()`), matching existing painters.
  - **Or** a small local painter that, per unique label, blends `granule_color(gid)`
    at `self._overlay_style()` alpha and/or draws the label's boundary via
    `skimage.segmentation.find_boundaries(lbl_z, mode="inner")` + `_thicken`
    (`analysis_page.py:2123`). This is the surest cluster↔mask palette match because
    it calls `granule_color` directly.
- **3-D (assembled mask):** `GranuleScene.label_volume = labels_vol`; widget renders

## Section 4 — Tessellation edges (pure-numpy adapter)

`GranuleTessellation` stores per-granule boundary **meshes** + `point_labels` +
`merged_from`. It does **NOT** store inter-centroid edges, Voronoi ridges, or a
global Delaunay (Report 4 §4; `.delaunay` on a `GranuleBoundary` is a per-granule
member-point triangulation, not this). You must derive the edges.

Add a pure builder to `backend/viz3d/overlays.py` (numpy + `scipy.spatial`):

```python
def granule_centroid_edges(points_zyx: np.ndarray, mode: str) -> np.ndarray:
    """Undirected edge index pairs (E,2) among the input points for a tessellation
    view. mode="alpha_shape" -> Delaunay edges; mode="voronoi" -> Voronoi ridges.
    Operate on the raw point cloud ("lines between all centroids"). Degenerate-safe.
    """
    from scipy.spatial import Delaunay, Voronoi
    pts = np.asarray(points_zyx, float).reshape(-1, 3)
    n = pts.shape[0]
    if n < 2:
        return np.zeros((0, 2), np.int64)
    # Collapse near-degenerate Z (a planar/near-planar cloud) to a 2-D triangulation
    # so QHull doesn't fail; otherwise triangulate in 3-D.
    use3d = n >= 4 and np.ptp(pts[:, 0]) > 1e-6
    P = pts if use3d else pts[:, 1:3]          # (y,x) when planar
    if mode == "voronoi":
        vor = Voronoi(P)
        edges = vor.ridge_points                # (R,2) adjacent input-point pairs
    else:
        tri = Delaunay(P)
        # all unique pairs within each simplex (triangle in 2-D, tetra in 3-D)
        s = tri.simplices
        from itertools import combinations
        pairs = np.vstack([s[:, list(c)] for c in combinations(range(s.shape[1]), 2)])
        edges = np.unique(np.sort(pairs, axis=1), axis=0)
    return np.ascontiguousarray(edges, np.int64)
```

Notes / guards:
- `mode` comes from `GranuleTessellation.mode`; use Voronoi ridges for `"voronoi"`,
  Delaunay edges for `"alpha_shape"` (Report 4 §4 — geometrically consistent pairing).
- QHull needs ≥ d+1 points and non-coplanar input; the `use3d`/planar fallback and
  the `n<2` guard cover the small-N and flat-cloud cases. Wrap the `scipy` call in
  `try/except` and return `(0,2)` on `QhullError` so a pathological cloud renders as
  dots-only.
- The **alternative** (lighter) reading of "centroids" = one centroid per final
  granule: `centroid[g] = points[point_labels==g].mean(0)`, then the same
  Delaunay/Voronoi over those K centroids. Offer this only if the per-point edge set
  is too dense; the primary interpretation is edges over all input points.
- **2-D** uses `granule_centroid_edges(points_zyx[:, [0,1,2]], mode)` but with the
  planar branch effectively giving `(y,x)` edges to project; **3-D** uses the same
  `(E,2)` indices into the `(x,y,z)` µm point array in `GranuleScene`. Compute once,
  reuse for both.

## Section 5 — Boundary node: previous (dotted) vs new (solid)

**Where "previous" comes from (Report 4 §5):** the boundary node (Node 5) is
computed FROM the Node-4 masks. So:
- **Previous (pre-node) mask** = Node-4 `_labels`:
  `self._granule_read_store(record, GRANULE_MASKS_ATTR)[m][t][COMBINED_LABELS_KEY]`.
- **This node's output** = Node-5 band `_labels`:
  `self._granule_read_store(record, GRANULE_BANDS_ATTR)[m][t][COMBINED_LABELS_KEY]`.
- Both share the **same dense 1-based ids** (bands inherit Node-4 ids —
  `granule_boundary.py:148,183`), so per-granule contours line up.

The Node-5 band is an **outward shell** ("not this granule"), so the "updated mask"
whose boundary you draw solid is most faithfully the **union** of the granule mask
and its band: `new_labels`, where `new = (node4_labels>0) | (node5_labels>0)` carrying
the node-4 id (per-granule: `new_g = node4_mask_g | node5_band_g`). Draw its outer
boundary solid; draw the node-4 `_labels` boundary dotted.
> Semantic choice to confirm: if "updated mask boundary" is meant to be the band's
> own contour (not mask∪band), draw `node5_labels` directly instead of the union.
> Report 4 describes the band as an outward shell; union-then-boundary is the
> defensible default. Confirm against the node's intended output before finalizing.

### 2-D (per plane) — dotted vs solid
`cv2` has no dashed-line primitive, so:
- **Solid new:** `find_boundaries(new_labels[z], mode="inner")` → `_thicken(..., 2)`
  → blend `granule_color(gid)` per label (reuse the Node-4 mask painter path with
  `outline=True, thickness=2`). Or `cv2.findContours((new_g>0).astype(uint8),
  RETR_EXTERNAL, CHAIN_APPROX_SIMPLE)` + `cv2.drawContours(out, cnts, -1,
  granule_color(gid), 2, cv2.LINE_AA)`.
- **Dotted previous:** get the prev contour the same way, then draw it dashed with a
  small helper that walks the contour polyline and draws every other short segment:

```python
def _draw_dashed_contour(out, contour, color, dash=4, gap=4, thickness=1):
    pts = contour.reshape(-1, 2)
    acc = 0.0
    for i in range(len(pts)):
        a = pts[i]; b = pts[(i + 1) % len(pts)]
        seg = float(np.hypot(*(b - a))); 
        if seg < 1e-6: continue
        d = (b - a) / seg; t = 0.0
        while t < seg:
            on = (int((acc // dash)) % 2 == 0)   # alternate dash/gap by arc length
            t2 = min(t + (dash if on else gap), seg)
            if on:
                p0 = (a + d * t).astype(int); p1 = (a + d * t2).astype(int)
                cv2.line(out, tuple(p0), tuple(p1), color, thickness, cv2.LINE_AA)
            acc += (t2 - t); t = t2
```

(Get contours from `cv2.findContours((prev_g>0).astype(np.uint8), cv2.RETR_EXTERNAL,
cv2.CHAIN_APPROX_SIMPLE)` per granule so dashes follow the ring.) Same per-Z filter
and crop-offset rules do not apply here — masks are already full `(Z,H,W)` at display
resolution; slice by plane `z` when `z_mode=="none"`, else use a projected boundary
(`find_boundaries(new_labels.max(axis=0))`).

### 3-D — dotted vs solid
Build both boundaries as surfaces and put them on the `GranuleScene`
(`boundary_label_volume` = new/union, `prev_label_volume` = node-4). In
`_add_granule_scene_overlay`:
- **Solid new:** `p.add_mesh(new_mesh, style="wireframe", color=granule_color(gid)/255,
  line_width=2.0)` (or opaque `build_object_surface` mesh per label — Report 3 (d)).
- **Dotted previous:** `edges = prev_mesh.extract_feature_edges()` (or
  `extract_all_edges()`); `actor = p.add_mesh(edges, color=(.6,.6,.6),
  line_width=1.5)`; then on the returned actor's VTK property
  `prop = actor.GetProperty(); prop.SetLineStipplePattern(0xF0F0);
  prop.SetLineStippleRepeatFactor(1)` (Report 3 recipe e — the only reliable dotted
  mechanism; PyVista has no `linestyle=`).
  > Fallback if `SetLineStipplePattern` is unavailable in the installed VTK build:
  > approximate "previous" with lower `opacity`, thinner `line_width`, and a muted
  > gray. Detect by `hasattr(prop, "SetLineStipplePattern")`.

Per-label meshes come from `build_object_surface(mask_g, voxel_size_um)`
(`backend/viz3d/surface.py:161`, pure numpy, returns `(x,y,z)` µm) — keep that call
backend-side; only `pv.PolyData`/`add_mesh` in the widget.

## Section 6 — Files to add / modify + build order

### The `(m,t)` fallback helper (add to `PipelinesPage`, reused by every painter)
There is exactly **one** `t` key per `m` (the detect-time timepoint; Report 4 §6). Add:
```python
def _granule_entry(self, attr, m, t):
    store = self._granule_read_store(self._active_record(), attr)
    bt = store.get(int(m)) if store else None
    if not bt: return None
    return bt.get(int(t)) or next(iter(bt.values()))   # fall back to the sole t
```
