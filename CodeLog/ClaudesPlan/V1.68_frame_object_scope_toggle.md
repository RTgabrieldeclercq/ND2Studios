# V1.68 — Frame / Object scope toggle (per-object pipeline execution)

## Context

User request: *"For any node/data, if there is a mask or object created, have a
lever toggle after that node (i.e., on the bridge line to the next node in the
pipeline) that switches analysis between whole frame, and object(s) as the
boundaries of analysis. If whole frame is toggled on, it runs the pipeline on the
whole frame, regardless of objects determined from the previous node for the rest of
the pipeline. If object(s) is toggled on, it runs the pipeline on each object in
parallel (if possible), automatically cropping the whole file to these objects in
the backend (conservating T, M, Z, etc...) and reports the same way, but just with
the cropped object boundaries on the viewer."*

This is a **companion to `V1.68_dvc_surface_mdm.md`** but a fully generic feature: it
governs *every* downstream node, not just DVC. The toggle rides on the **edge
(bridge line)** leaving any node that produces objects.

**What already exists (reuse, don't reinvent).**
- **`Edge` carries `params: Dict[str,Any]`** (`pipeline_graph/model.py`) and
  round-trips it through `to_dict`/`from_dict` — a schema-free home for the scope
  flag.
- **Crop-scoped Runs (V1.46/V1.59).** The Pipelines page already scopes a Run to a
  rectangle: `_crop_rect()` / `_effective_run_crop()` / `_maybe_crop_volume()`, and
  `_DVCJob(rect=...)` crops **inside `_read_volume`** *before* handing volumes to
  `method.run(...)`. So DVC already runs on a crop with the correlation maths
  untouched — per-object scoping is the **multi-rect generalization** of this exact
  seam.
- **`CroppedVolume`** (`pipeline_graph/executor.py`) — a lazy XY sub-rectangle
  wrapper on the `get_frame` read protocol that **preserves M/T/Z/C** and only
  reports a smaller `height`/`width`. The per-object wrapper is a direct extension.
- **Coalesced, cancellable background jobs** — `JobRunner` (`compute/runner.py`,
  keyed submit + pool) and the generation-guarded per-object worker pattern
  (`dvc_panel._ObjectFieldWorker`); CPU fan-out via `compute/parallel/process_map.py`.
- **Object sources already in the graph** — `special:mask3d` (drawn mask,
  `record._mask3d_by_m`), analysis nodes (`AnalysisResult.label_masks`
  `{name:(T,H,W) int32}`), and `special:track` (tracked objects).

## Goal

1. A per-edge **scope** setting — `whole_frame` (default) or `objects` — stored on
   `Edge.params["scope"]`, meaningful only on edges whose **source node produces
   objects**.
2. A **lever toggle** widget drawn on the edge (bridge line) in the node canvas,
   shown only when the upstream node yields objects; click flips it; state persists.
3. Backend: when `objects`, **auto-crop the whole file to each object** (conserving
   T/M/Z/C) via a lazy `ObjectCropVolume`; run the downstream sub-pipeline **once per
   object**.
4. **Parallel** per-object execution where possible (JobRunner / process_map),
   coalesced + cancellable.
5. **Reporting unchanged** — per-object rows/fields/overlays merge into the same
   tables/series (tagged `object_id`); overlays are offset back so object boundaries
   appear in-place on the viewer.
6. **Generic**: any object-producing node, any downstream node type (analysis / DVC
   / results / export), any data.

## Approach

### 1. Model — `pipeline_graph/model.py` (modify; no schema bump)

- Constants `SCOPE_WHOLE = "whole_frame"`, `SCOPE_OBJECTS = "objects"`.
- `edge_scope(edge) -> str` — `edge.params.get("scope", SCOPE_WHOLE)` (absent ⇒
  whole-frame ⇒ **legacy graphs behave exactly as before**).
- `set_edge_scope(edge, scope)` — writes `edge.params["scope"]`. Since `Edge.params`
  already serializes, scope **persists in the saved `.nd2s_pipeline`** with no
  `schema_version` change and no `io.py` migration.

### 2. Object-source capability — `pipeline_graph/registry_adapter.py` (modify)

- `node_produces_objects(node) -> bool` — `True` for `op_key == SPECIAL_MASK3D_OP_KEY`
  or `SPECIAL_TRACK_OP_KEY`, or an analysis node whose pipeline yields
  `label_masks` (looked up via the analysis registry). Drives whether an outgoing
  edge shows the lever.

### 3. Object enumeration — `backend/analysis/object_scope.py` (new, Qt-free)

- `@dataclass ObjectRegion`: `object_id: int`, `bbox: (z0,z1,y0,y1,x0,x1)`,
  `mask (zc,yc,xc) bool` (object within its box), `source: str`.
- `iter_objects(obj, voxel_size_um, *, min_voxels=1, pad=0) -> List[ObjectRegion]`:
  - `(Z,H,W) bool` drawn mask → `scipy.ndimage.label` → per-component bbox + mask.
  - `(T,H,W) int32` label masks → per-label bbox **unioned over T** so an object
    keeps one stable crop across the timelapse (conserves T).
  - tracked objects → per-track bbox union over its frames.
  - `pad` dilates the box (keep surrounding matrix context — see caveat); tiny
    objects (`< min_voxels`) are dropped with a status note.
- Pure numpy/scipy; no Qt, no DVC import.

### 4. Lazy per-object volume — `ObjectCropVolume` in `pipeline_graph/executor.py` (new, beside `CroppedVolume`)

- `ObjectCropVolume(raw_volume, region: ObjectRegion, *, mask_out=False)` — same
  `get_frame`/`get_volume` read protocol as `CroppedVolume`, but:
  - crops **XY** to the bbox **and Z** to `[z0:z1]` (for a 3-D object); slices apply
    uniformly across **all T, all M, all channels** — so T/M/C are conserved and Z
    is a contiguous sub-stack;
  - reports cropped `height`/`width`/`n_zslices`; passes through
    `n_timepoints`/`n_multipoints`/`channel_names`/`pixel_size_um`/`z_step_um`;
  - `mask_out=True` optionally zeroes voxels outside `region.mask` (object as a hard
    boundary); **default `False`** — a rectangular crop that keeps surrounding
    context (required for correlation nodes like DVC; see caveat).
- This is the literal "automatically cropping the whole file to these objects in the
  backend (conserving T, M, Z, …)."

### 5. Execution — `pages/pipelines_page.py` + `pipeline_graph/executor.py::GraphRunner` (modify)

- **Detecting the branch.** During the topological Run walk, when a completed node
  has outgoing structural edge(s) with `edge_scope(e) == SCOPE_OBJECTS`, the page
  resolves that node's published objects (`record._mask3d_by_m` / analysis
  `label_masks` / tracks) via `iter_objects(...)`.
- **Per-object sub-runs.** For each `ObjectRegion`, wrap the record volume in an
  `ObjectCropVolume` and run the **downstream sub-graph** (nodes reachable from that
  edge) scoped to the crop. This **generalizes the existing single-crop seam**: today
  `_effective_run_crop()` yields one rect consumed by `_DVCJob(rect=...)` /
  `_maybe_crop_volume` / analysis; we add `self._object_scope: Optional[List[
  ObjectRegion]]` and iterate, setting the active crop (+Z-range +optional mask) per
  object. **No node's compute code changes — it just receives a cropped volume.**
- **DVC specifically.** Submit **one `_DVCJob` per object**, each with the object's
  bbox as its `rect` (+ a Z-range) — keyed `f"{_RUN_DVC_KEY}:obj{object_id}"` so the
  `JobRunner` runs them **concurrently** across its pool instead of coalescing them
  together. `_finish_dvc` aggregates each object's field series under its
  `object_id`. `method.run(...)` is unchanged (honors the "don't touch DVC" caution).
- **Parallelism.** Independent objects → parallel jobs (JobRunner pool; heavy CPU
  analysis can fan out via `compute/parallel/process_map.py`). All cancellable and
  coalesced through the existing token machinery.
- **Aggregation / reporting.** Each object's measurement rows carry `object_id`
  (already how tracked/per-object rows flow into `_populate_results_table`); fields
  and label masks are **offset back to global coordinates** by the bbox origin, so
  overlays draw the object boundary **in place** on the viewer (the crop is a backend
  detail). For the DVC 3-D object view this dovetails with Doc 1 — one surface + MDM
  per object.

### 6. Lever widget — `widgets/node_board/edge_item.py` + `node_scene.py` (modify)

- **`EdgeItem`** gains a small **lever** drawn at the wire midpoint — a rounded pill
  with two states, `▭ Frame` and `◈ Objects` (Objects tinted `Settings.ACCENT_ORANGE`
  to read as "special"). `set_scope_toggle(visible: bool, scope: str)` shows/positions
  it; the pill has its own hit region (mirroring the existing widened
  `QPainterPathStroker` grab + hover on the wire). A click emits to the scene. It sits
  alongside the existing edge decorations (loop arrowhead, channel strands) and stays
  hidden on non-object edges and the transient drag wire.
- **`NodeScene`** computes object-capability per edge (`node_produces_objects` on the
  source node), shows/places the lever, writes `set_edge_scope(edge, …)` on toggle,
  and emits a new `edge_scope_changed(edge_id, scope)` signal → the page marks the
  graph dirty (`graph_changed`) and, if a Run is active, re-scopes. Tooltip explains
  the two modes.

### 7. Persistence — `pipeline_graph/io.py` (no change needed)

- `Edge.params` already serializes, so scope survives save/load. Absent ⇒ whole-frame
  keeps every existing pipeline behaving as before (documented in the plan; asserted
  in tests).

## Data flow

```
[node produces objects] ──edge (scope lever)──▶ [next node] ──▶ … downstream sub-graph
   (mask3d / label_masks / tracks)   │
                                     ├─ scope = whole_frame  → run downstream once on the full frame (today)
                                     └─ scope = objects
                                             iter_objects(mask/labels/tracks) → [obj1, obj2, …]
                                             for each object  (parallel, if possible):
                                                 ObjectCropVolume(raw, bbox[,mask])   # conserves T/M/Z/C
                                                 run downstream sub-graph on the crop
                                                    • DVC → one _DVCJob per object  (key …:objN)
                                                    • analysis/results/export → cropped-volume run
                                             aggregate rows/fields (+ object_id),
                                             offset overlays back to global coords
```

## Key decisions / caveats

- **Scope on `Edge.params` — no schema bump.** Round-trips today; default absent ⇒
  `whole_frame`, so every existing graph is unaffected. Fully back-compatible.
- **Generalizes the existing crop seam, so DVC (and every node) stays untouched.**
  Per-object = N crops where V1.46/V1.59 had one; nodes receive a cropped volume and
  are otherwise unchanged. `backend/dvc/` is neither imported nor modified — directly
  honoring the user's caution.
- **`mask_out` defaults to *off* (bbox crop, not a hard object mask).** Correlation
  nodes (DVC) measure displacement in the matrix *surrounding* the object, so zeroing
  everything outside the object would destroy the signal DVC needs (and the Doc-1
  surface integral samples `u` on the boundary from that surrounding field). Bbox
  crop keeps the surrounding context; `mask_out=True` is opt-in for pure
  inside-object intensity analysis.
- **Conserve T/M/Z/C** — the object crop restricts only the spatial footprint (XY,
  plus the object's Z-range for 3-D); the lazy wrapper preserves the time, multipoint
  and channel axes and their indexing.
- **Parallelism is best-effort** ("in parallel, if possible"): bounded by the
  JobRunner pool; per-object keys prevent the coalescing that same-key jobs get;
  heavy CPU steps can use `compute/parallel/process_map.py`. Everything remains
  cancellable via the existing tokens.
- **Reporting parity** — per-object results merge into the same tables/plots/series
  as whole-frame (tagged `object_id`), and overlays are offset back so the viewer
  shows object boundaries in place; the crop is invisible to the user except as the
  scoped analysis region.
- **Lever placement** reuses the edge's existing interaction model (midpoint, widened
  hit area, hover) and visual vocabulary (like the loop arrowhead / channel strands),
  so it feels native and never collides with the wire's double-click-to-disconnect.

## Verification

- **Backend**: `iter_objects` on synthetic multi-blob masks (2-D and 3-D) → correct
  component count, bboxes, and per-object masks; label-source unions over T; track
  source. `ObjectCropVolume` returns correct sub-boxes and **conserves
  T/M/Z/C** (shape/index assertions); `mask_out` zeroes exterior when enabled.
- **Model/persistence**: `edge_scope` default is `whole_frame`; `set_edge_scope`
  round-trips through `Edge.to_dict/from_dict` and a full pipeline save/load; a legacy
  graph with no `scope` key runs identically to pre-V1.68.
- **Toggle UI**: the lever appears **only** on edges leaving object-producing nodes;
  click flips `whole_frame ↔ objects`; color/tooltip update; `edge_scope_changed`
  fires and marks the graph dirty.
- **Execution**: a 2-object mask feeding DVC → **two concurrent** `_DVCJob`s (distinct
  keys), each on its object crop; results carry `object_id`; overlays land at correct
  global positions; whole-frame vs objects give consistent per-object numbers on a
  controlled fixture; mid-run cancel unwinds all object jobs.
- **DVC caution regression**: `git diff` under `backend/dvc/` is empty; a per-object
  DVC field equals the whole-frame field restricted to that object's box (up to
  border effects), proving only the *input volume* changed.

## Deferred / follow-on (not in this plan)

- A scope lever on **stage bridges** (`Bridge`), not just node-to-node edges, for
  cross-stage per-object scoping.
- Per-object **progress rows** in the Run panel (one bar per object) beyond the
  aggregate progress.
- Object **re-identification across T** for label sources whose ids are not stable
  (today handled by union-over-T bbox; a tracking-aware crop is a later refinement).
