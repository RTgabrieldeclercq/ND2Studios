# V1.57 — Export cropped data from the Import (first) tab

## Goal

Let the user export the currently-loaded dataset **directly from the Import tab**
(the `FilePanel`), honoring both crops:

1. The existing **T / M / Z tile-strip crop** (already baked into
   `record._raw_volume` by `CropWorker` when the user crops from the axis strips).
2. A **new spatial XY ROI crop** — a rubber-band rectangle drawn on the Import
   viewer (mirroring the Recipe tab's crop tool), stored as a rect and applied at
   export time.

Export formats offered (all reusing the existing `ExportWorker` / exporters):
- **TIFF hyperstack** (`tiff_stack`, or `tiff_zstack` when the file is an
  unprojected multi-Z stack).
- **Movie** (MP4 / GIF) via the shared `ExportPreviewDialog`.
- **Image sequence** (PNG, one per T frame of the current M/Z view).

Previously the only export path was: Import → Confirm → **Export tab**. This adds a
self-contained export on the first tab that works for **any** panel (primary *and*
secondary side-by-side panels), each against its own `record`.

## Approach

All changes live in `nd2studios/widgets/file_panel.py` (a widget — may import
Qt/workers/exporters; backend purity rule does not apply).

### XY ROI crop (display stays full-frame; rect stored for export)
- New state: `self._xy_crop: Optional[Tuple[int,int,int,int]]` (x, y, w, h in
  full-frame image pixels).
- The XY crop is **not** applied to the live viewer (the viewer keeps browsing the
  full M/T/Z volume). It is applied to the channels handed to the exporter, so the
  output file is cropped. A status label makes the pending crop explicit.
- Wire `viewer.crop_rect_selected` → `_on_xy_crop_drag` and
  `viewer.canvas.clicked` (guarded by the crop-mode toggle) → `_on_xy_canvas_click`,
  both routing through `_show_xy_crop_dialog` (spinbox confirm/edit, clamped to
  frame bounds — mirrors `RecipePage._show_crop_dialog`).

### Export source builder
- `_export_source_channels()` → `OrderedDict[name, lazy/array]`:
  - If `record._raw_volume` is set: `vol.all_channels_as_lazy(m, z_mode, z_index)`
    at the viewer's current coords (this already reflects the T/M/Z crop, since the
    cropped volume replaced `_raw_volume`).
  - Else: `dict(record._raw_channels)`.
  - Apply XY crop via each channel's `.crop(y0, y1, x0, x1)` (present on
    `LazyND2Channel` / `LazyTIFFChannel` / `MultiFileLazyChannel`), falling back to
    `np.asarray(ch)[..., y:y+h, x:x+w]`.
- `_colors_enabled_lut(names)` → colors (`CHANNEL_COLORS`), enabled flags, and
  per-channel LUT `(lo, hi, gamma)` read from `viewer.channel_state()` — same
  mapping the Export page uses.

### Export dispatch (`ExportRequest` + `ExportWorker`)
- **TIFF:** unprojected multi-Z (`n_zslices > 1` and z_mode == "none") →
  `mode="tiff_zstack"` with `raw_volume`, `m_index` (current), `crop_rect=xy`.
  Otherwise → `mode="tiff_stack"` with the XY-cropped lazy channels.
- **Movie:** materialize the cropped channels, open `ExportPreviewDialog`
  (T-scrub + brightness/contrast/etc.), then `mode="movie"` with default
  `MovieOptions(fps=10, codec=mp4|gif, scale bar/timestamp/labels on)`.
- **Image sequence:** same preview, `mode="image_sequence"` over the current M/Z
  T-series (crop already applied to channels; `iterate_volume=False`).
- `_run_export` / `_on_export_done` mirror the Export page's worker plumbing, but
  route progress/status through the panel's existing `_cb_progress`/`_cb_status`.

### UI (per widget-layout skill)
- New **"Export"** `QGroupBox` in the controls sidebar (after Confirm/Stitch/Revert):
  - Row: `btn_crop_xy` (checkable, `fa5s.crop-alt`, `" Crop XY"`) +
    `btn_reset_xy` (`fa5s.undo`, `" Reset"`), via `icon_button`.
  - `lbl_xy_crop_status` ("No XY crop").
  - `btn_export` (`primaryBtn`, `fa5s.download`, `" Export cropped…"`) opening a
    `QMenu`: TIFF hyperstack / Movie (MP4) / Movie (GIF) / Image sequence (PNG).
- Export button + crop button disabled until a file loads (enabled in `_on_loaded`
  alongside `btn_confirm`); reset XY crop on each fresh load.

## Files
- `nd2studios/widgets/file_panel.py` — all UI + logic.
- `CodeLog/Updates/CHANGELOG.md`, `CodeLog/Architecture/ARCHITECTURE.md`.

## Key decisions
- **XY crop is a stored rect, not a mutation of the volume** — keeps the M/T/Z
  browsing model intact and avoids fighting the lazy-volume design; the crop is
  realized only in the exported file. (T/M/Z crop already mutates `_raw_volume` via
  `CropWorker`, so both crops compose naturally.)
- **Reuse `ExportWorker`/exporters wholesale** — no new export backend; the import
  tab is just a new front-end that assembles an `ExportRequest`.
- **Fixed movie defaults (fps 10, overlays on)** for a lightweight first cut; the
  full Movie-tab controls remain on the Export tab for fine-grained needs.
