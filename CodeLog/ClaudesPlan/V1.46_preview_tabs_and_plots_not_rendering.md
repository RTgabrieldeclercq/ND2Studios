# V1.46 — Fix: preview plots & overlay tabs don't render after a preview

## Symptom

After the preview-crop / full-preview-coverage work, running a **preview**
(Analysis tab, results mode) computes fine but the **bottom-panel plots** and the
**overlay tabs** (Segmentation / Tracks / Vectors) don't appear with the data.
Confirmed by the user: happens **with no crop active** too, and **silently** (no
error/traceback). So this is a general preview-refresh gap, not a crop shape bug.

## Root cause (confirmed by reading, cross-checked against the Run path)

The async preview completion path never refreshes the overlay-tab availability or
builds the track-overlay state — both of which the Run path *does* do:

1. **Segmentation/Spatial tabs.** The `_PV_SCREEN_KEY` handler sets
   `_analysis_screen_results` + `_results_rows`, populates the table, walks
   downstream, and (new) builds preview plots — but never calls
   `_update_overlay_tabs_available()`. Tab visibility (`has_seg`, `spatial`) is
   only recomputed on node-promotion / stage / mode changes and in the Run paths
   (`_advance_run_m` → :3307). Those fire *before* the async result exists, so the
   Segmentation tab is computed as hidden and never re-revealed when results land.
2. **Tracks/Vectors tabs.** `_preview_execute_walk_node` (SPECIAL_TRACK_OP_KEY)
   links `track_id`s onto `_results_rows` but never sets `_track_colormap` /
   `_track_overlay_rows`. `_update_overlay_tabs_available` gates Tracks/Vectors on
   `has_tracks = bool(self._track_colormap)`, so those tabs stay hidden in preview.
   The Run path builds this state in `_build_track_overlay` (:3488).

Plots: `_update_preview_plots()` *is* wired into the handler, so once (1)/(2) are
fixed and rows are present it renders; a diagnostic log is added so an
empty-rows / preview-off no-op is visible rather than silent.

## Fix

- **Factor** the Run's track-overlay state-building out of `_build_track_overlay`
  into a shared `_set_track_overlay_state(rows) -> bool` (colormap + long-track set
  + frozen `_track_overlay_rows` + `_update_overlay_tabs_available()`), keeping the
  Run-only bits (auto-select "tracks" tab + playthrough animation) in
  `_build_track_overlay`.
- **Preview Track Objects walk:** after linking, call `_set_track_overlay_state`
  so the Tracks/Vectors tabs light up in preview exactly as in a Run.
- **`_PV_SCREEN_KEY` handler:** reset the track-overlay scratch when fresh results
  arrive (so a graph *without* tracking clears stale track tabs), then after the
  downstream walk + preview plots, call `_update_overlay_tabs_available()` so the
  Segmentation/Spatial tabs reveal now that results exist.
- **`_reset_analysis_preview`:** also drop `_track_colormap` / `_track_overlay_rows`
  (clean slate on a new previewed node).
- **Diagnostics:** log the produced results/row counts in the handler and the
  no-op reason in `_update_preview_plots`, so a future "nothing rendered" is
  attributable from the console.

  appears; Cells/frame + Area plots render.
