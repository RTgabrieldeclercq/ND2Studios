# V1.52 — SerialTrack PTV field: bounded (Cell-Tracker) scatter-to-grid

## Goal

Fix the discrepancy where **per-particle displacement vectors are small (< 20 px)
but the gridded "field" vectors are enormous** in the SerialTrack PTV panel
(quiver / scalar / strain / stress views).

## Root cause

The per-particle displacements from `particle_displacement` are correct and
bounded. The **field** is a gridded interpolation of those same vectors, and the
interpolation was extrapolating without bound:

- `compute_field_bundle` and the panel defaulted `smoothness` to `1e-3` (> 0).
- In `scatter_to_grid` (regularization.py), **any `smoothness > 0` takes the RBF
  branch**: `RBFInterpolator(kernel="thin_plate_spline", degree=1)`. Only
  `smoothness == 0` used bounded linear interpolation.
- Thin-plate-spline is a global interpolant whose kernel grows like `r²·log r`.
  The grid spans the **bounding box** of the particles, so its corners and
  inter-cluster gaps lie *outside the convex hull* of the tracked cells. There
  the RBF extrapolates with no bound and no hull mask.

Reproduced (all inputs < 21 px): two clustered groups → RBF field reached
±134 px in the empty gap while linear interpolation stayed at ±14 px.

The original **Cell-Tracker** (`CellTracker/backend/fields.py`) never shows this:
it uses `scipy.griddata(method="linear")` (NaN outside the convex hull),
`np.nan_to_num(..., nan=0)`, then a Gaussian blur — so the field can never
exceed the range of the input values, and there is no extrapolation.

## Approach — wire back the Cell-Tracker approach

Only the **field-output** path is changed. The tracking global-step solvers
(`solve_regularization`, `ADMMLSolver`) still use the RBF `scatter_to_grid`
because there `smoothness` is a genuine iterative regulariser and results are
interpolated back at particle positions (inside the hull) — untouched.

1. **`serialtrack/regularization.py`** — new bounded, no-extrapolation
   scatter-to-grid, mirroring Cell-Tracker:
   - `scatter_to_grid_bounded(coords, values, grid_step, smoothing_sigma=0.0,
     grid_coords=None)` — linear inside the convex hull (via the existing
     `_linear_or_nearest_interpolate`, which fills `0.0` outside the hull and
     falls back to nearest on degenerate input), then an optional
     `gaussian_filter` of `smoothing_sigma` grid cells.
   - `scatter_to_grid_multi_bounded(...)` — multi-component wrapper.
   - Added `from scipy.ndimage import gaussian_filter`.

2. **`serialtrack/fields.py`** — `compute_gridded_strain` now calls
   `scatter_to_grid_multi_bounded`. Its `smoothness` argument is now interpreted
   as a **Gaussian sigma in grid cells** (Cell-Tracker's `sigma`), not an RBF
   weight. This is the single choke point used by both the PTV panel and the
   post-processing strain in `tracking.py`.

3. **`serialtrack_analysis.py`** — `compute_field_bundle` default `smoothness`
   `1e-3 → 0.0`; docstring updated to the bounded / Gaussian-σ semantics.

4. **`widgets/serialtrack_panel.py`** — the "Smooth" spinbox now represents a
   Gaussian σ in grid cells: `decimals 4→1`, `step 0.001→0.5`, `default
   0.001→1.0`, plus a tooltip explaining the bounded model.

## Verification

`compute_gridded_strain` on the clustered repro (per-particle |u| max 20.7 px):

| smoothness (σ) | field \|u\| max | comp range | strain \|ε\| max |
|---|---|---|---|
| RBF (old) | ~134 px | ±134 | — |
| 0.0 (bounded) | 17.1 px | [-13.1, 14.1] | 0.57 |
| 1.0 (bounded) | 13.0 px | [-9.0, 10.5] | 0.20 |

The field is now bounded by the per-particle displacement range, matching
Cell-Tracker.

## Key decisions

- **Did not** change `scatter_to_grid` / the tracking solvers — the fix is
  scoped to the field-output path to avoid perturbing tracking convergence.
- Reused `_linear_or_nearest_interpolate` (already `fill_value=0.0` + QhullError
  fallback) rather than re-implementing `griddata`, keeping one bounded path.
- Kept the public arg name `smoothness` (avoids churn in the panel/tracking
  callers) but redefined it as a Gaussian σ and documented it everywhere.
