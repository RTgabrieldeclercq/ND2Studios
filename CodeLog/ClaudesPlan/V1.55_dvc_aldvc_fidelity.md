## Why

The V1.51 DVC node is faithful to ALDVC's **core solver** (12-DOF IC-GN local step
+ F-coupled augmented-Lagrangian FD global step + ADMM + strain, verified sub-voxel
on synthetic data), but it omits ALDVC's **large-deformation / time-series robustness
layer**. On the real 121 GB confocal series (≈40-voxel motion at ÷16) this showed up as
weak correlation (ZNCC ≈0.4–0.5, ADMM not converging). The three missing pieces, each
grounded in `main_ALDVC.m`:

- **A. Incremental→cumulative accumulation** (lines 631–706): incremental mode is a
  *technique to compute the cumulative field* — ALDVC composes the per-step increments
  into a cumulative displacement `U_accum` by Lagrangian point-tracking (`interp3`
  makima of each increment at the drifting nodal positions, `U_accum = coordCurr −
  coord`), and strain uses `U_accum`. Ours only stored/showed the raw increment.
- **B. Cross-frame warm-start** (line 196): ALDVC FFT-seeds only frame 2, then
  warm-starts every later frame from the previous frame's solution
  (`U0 = ResultDisp{ImgSeqNum-2}.U`), re-seeding only if `newFFTSearch`. Ours re-seeds
  every frame independently.
- **C. Multigrid integer seed** (line 143, `IntegerSearch3Multigrid`): coarse-to-fine
  FFT search brackets large displacement. Ours was single-scale → can't seed large
  motion → IC-GN starts outside its basin.

(The ADMM math itself is already equivalent — MATLAB's `RHS = β·Dᵀ(F−udual)+μ(U−vdual)`,
`dual += (z−x)` equals our `+w`, `dual += (x−z)`; the local F feeds the global solve.)

## Plan

### A. Accumulation — new `backend/dvc/tracking.py`
- `accumulate_incremental(grid, increments)`: port lines 655–697. Track the reference
  grid points through the ordered increment fields with
  `scipy.interpolate.RegularGridInterpolator` (linear; makima-equivalent cubic if the
  field is smooth), advancing `coordCurr += interp(increment @ coordCurr)`; return the
  per-frame cumulative `U_accum` on the grid. Light outlier guard + `nan_to_num` in place
  of MATLAB's median±σ clip + `inpaint_nans3`.
- `build_accumulated_results(grid, increment_results, voxel, strain_type)` → `{t:
  DVCResult}` with the accumulated displacement + strain recomputed via
  `strain.compute_strain`.

### B. Warm-start — `engine.run_aldvc` + `_DVCJob`
- `run_aldvc(..., u0_seed=None, use_fft_seed=True)`: when `u0_seed` (an `(ndim,*grid)`
  field) is given and `use_fft_seed` is False, use it as the seed (clean + inpaint) and
  skip the integer search. Grid shape must match (same volume + subset params ⇒ it does);
  fall back to FFT on mismatch.
- `_DVCJob`: keep the previous frame's compatible `û`; pass it as `u0_seed` for the next
  frame (FFT only frame 1, or every frame when `newFFTSearch`).

### C. Multigrid seed — `integer_search.py`
- Add `u0_center` to the per-subset search (offset the deformed window by
  `round(u0_center[subset])`; the returned displacement carries the offset).
- `integer_search_multigrid(ref, defm, grid, subset, radius, *, levels)`: coarse→fine.
  Downsample by 2 per level (XY always; Z when deep enough), seed on the coarsest with a
  large downsampled radius + `u0_center=0`, upsample ×2 into the next level's `u0_center`,
  refine with a small radius. `levels=1` ⇒ the current single-scale path.
- `engine` calls the multigrid seed; new `seed_levels` param (default 3).

### Params (registry_adapter DVC branch + method + DVCParams)
- `newFFTSearch` (bool, default off) — re-seed every frame vs warm-start.
- `seed_levels` (int, default 3) — integer-search pyramid levels.

### Panel — `dvc_panel.py`
- Incremental mode now carries **two** series (accumulated cumulative + raw increment);
  add a **"Show: Cumulative / Increment"** toggle (visible only in incremental) that
  swaps the active series. Default = cumulative (matches ALDVC's `U_accum`).
- Page `_dvc_series_by_m` (primary) + `_dvc_incr_by_m` (raw increments, incremental only).
