# V1.75 — Exclude node (`special:exclude`)

## Context & user request

> *"Create a new node called exclude. If the user has any object as a mask/area/region,
> then it can be connected to exclude, which prevents any analysis node from taking it
> into consideration. For example, connecting exclude to 3D Mask drawing will cause all
> areas in all Z and all M and all T to be ignored as long as they are within the masks
> drawn."*

So: a region-producing node wires **into** Exclude (`3D Mask Drawing --ANY--> Exclude`),
and every downstream analysis then **ignores** the voxels inside that region, across all
Z / M / T. This is the semantic **inverse** of the V1.68 Frame/Object scope lever (which
crops analysis *to* the object); Exclude removes a region *from* the analysis domain.

## Goal

Add a `special:exclude` node ("Exclude") to the Pipelines node board that:

1. Accepts an `ANY` input, so any object/mask/region producer wires into it — the
   flagship being **3D Mask Drawing** (`special:mask3d`), plus **Granule Volume Mask**
   (`special:granule_mask`). Emits an `ANY` pass-through output so it can be a leaf
   (`mask3d → Exclude`) *or* sit mid-chain (`mask3d → Exclude → DVC`).
2. On Run, unions the wired region(s) into a per-multipoint boolean exclusion volume
   `record._exclude_by_m = {m: (Z,H,W) bool}` (True = ignore).
3. Causes **every** analysis node to ignore those voxels — with **no per-node edits** —
   by zeroing the excluded voxels at the shared image-read chokepoints (exactly how the
   Crop node's rect reaches every downstream node via `_crop_rect()`).

## Key decisions

- **Node type = a SPECIAL pass-through (`special:exclude`)**, mirroring the **Crop node**
  (`special:crop`) — the closest precedent. Input `[PortType.ANY]`, output `[PortType.ANY]`,
  `ShapeKind.HEXAGON`, `NodeCategory.SPECIAL`. `ANY` input is required because the mask
  producers emit `ANY` (mask3d/granule) — the real region data is a **record side-artifact**,
  never a wire payload (same as V1.65/V1.68). No rainbow CHANNEL ports (input is `ANY`, not
  `IMAGE`), which is correct — Exclude consumes a region, not a channel.

- **Publish-on-record + central-read-chokepoint** (the Crop-node mechanism). Exclude
  publishes `record._exclude_by_m`; the shared readers zero the excluded voxels. This is
  what makes it visible to **all** analysis, not just directly-wired nodes — satisfying
  "prevents *any* analysis node."

- **A pre-Run resolution pass** (`_resolve_run_exclusions`, called from `_on_run`). Exclude
  sits on a **side-branch** (`channel → mask3d → Exclude`), independent of the analysis
  branch, so the topological Run walk does **not** guarantee Exclude runs before the
  analysis nodes. The pre-pass rasterizes the mask3d node's drawn shapes from
  `node.params["mask_shapes"]` **up front** (reusing the extracted
  `_build_mask3d_by_m`), so exclusion is ready before *any* analysis node runs —
  **order-independent** for the flagship case. Granule/analysis/track sources are read from
  the record when already present (prior Run / checkpoint), otherwise picked up when the
  Exclude node itself runs (`_run_exclude`) — best-effort, documented as a follow-on.

- **"Ignore" = zero the excluded voxels at the read seam** (not touching any analysis
  compute, and never `backend/dvc/`). For the Z-projected analysis channels the exclusion
  is projected over Z (`.any(axis=0)` → `(H,W)` footprint) so the mask's XY footprint is
  ignored ("all areas in all Z"); for true-3-D DVC the full `(Z,H,W)` mask is applied.
  Mirrors the existing `ObjectCropVolume.mask_out` idiom (`np.where`), inverted (zero
  *inside* the region).

- **Applied to analysis reads only.** Wired seams: `_processed_channels_for_m` (all
  `AnalysisPipeline` nodes — segmentation, spots, histogram, nuclei, StarDist, tear, mask
  analysis, measurements), `_DVCJob._read_volume` (DVC), `_materialize_channels_for_m`
  (Spatial Maps / validation). **Deliberately NOT** `_zstack_channels_for_m` (Save Data) or
  Export — those write the *real* dataset; the user said "analysis." Tracking is covered
  transitively (objects can't be detected in a zeroed region, so they're never tracked).

- **Crop-aware.** The exclusion footprint is sliced to the active `_crop_rect()` before it
  is applied, so it aligns with a cropped Run (register → crop → exclude), consistent with
  every other downstream reader.

## Data flow

```
channel ──▶ [3D Mask Drawing] ──ANY──▶ [Exclude]        (leaf, or → DVC/analysis)
   (or [Granule Volume Mask])              │
                                           │  _resolve_run_exclusions (pre-Run, up front):
                                           │    rasterize mask3d shapes → union per-m
                                           ▼
                              record._exclude_by_m[m] = (Z,H,W) bool  (True = ignore)
                                           │
        every analysis read ──────────────┤  _processed_channels_for_m (analysis: zero (H,W) footprint)
        funnels through and zeroes         ├  _DVCJob._read_volume      (DVC: zero (Z,H,W))
        the excluded voxels                └  _materialize_channels_for_m (spatial maps)
```

## Verification

- **Unit** (`tests/exclude/`): `_apply_exclusion_channels` zeros exactly the mask footprint
  across all T and leaves the rest untouched; crop-aligned slice; 2-D and 3-D masks; no-op
  when nothing published. Exclusion-volume union over multiple sources / multipoints.
- **Headless**: `py_compile`; GUI-module import + `_run_exclude`/`_resolve_run_exclusions`
  method presence; the node appears in `special_specs()` and round-trips through
  `save_pipeline`/`load_pipeline`.
- **Live-GUI QA (pending)**: import the test ND2, wire `channel → 3D Mask Drawing → Exclude`,
  draw a mask, add a segmentation/DVC node, Run; confirm no objects/field inside the region,
  across all Z/M/T; confirm removing the Exclude node restores full-frame analysis.

## Deferred / follow-on

- **Analysis / Track nodes as exclusion sources** (exclude based on a segmentation label
  mask or tracks). The first cut supports the two `(Z,H,W)` region families the user named
  (drawn 3-D mask + granule mask); label-mask/track sources need `(T,H,W)`→all-Z broadcast
  and live availability, so they're order-dependent — deferred.
- **Viewer overlay** of the excluded region (a tinted footprint on the base image), like the
  Crop node redraws the cropped view. First cut is functional + status messages only.
- Making non-mask3d live sources fully order-independent (a second pre-pass after their
  producers complete).
