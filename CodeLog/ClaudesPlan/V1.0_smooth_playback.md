# V1.0 — Smooth Playback: Pre-Render Cache & FPS Improvements

## Goal

Since V1.41, all ND2 data is materialized in RAM. The image slider and FPS
playback were still sluggish because the old 50ms T-slider debounce and the
per-frame LUT+compositing pipeline (designed for lazy I/O) were still in place.

Intended outcome: after materialization completes, slider dragging is
instantaneous and FPS playback reaches up to 60fps for cached datasets.

## Bottlenecks Addressed

1. **50ms T-slider debounce** — designed for lazy loading; reduced to 5ms.
2. **Per-frame compose cost** — LUT + channel multiply + additive sum on every
   slider tick. For 2048×2048 × 3 channels this was ~50ms → ~20fps ceiling.
3. **FPS timer cap** — `max(50, ...)` capped playback at 20fps.
4. **No display caching** — `QImage` + `QPixmap` created on every frame change.

## Approach

### `PreRenderWorker` (`nd2studios/workers/pre_render_worker.py`)

Background `QThread` that replicates `_compose_current_frame()` off the GUI
thread. Runs after `LoadWorker` completes and the volume is wired to the viewer.

- Signals: `progress(int)`, `frame_cached(int, int)`, `finished()`, `error(str)`
- Constructor takes LUT and chip state snapshots (captured on the main thread)
  and a shared `cache: dict[(m, t) → (H, W, 3) uint8]` written directly.
- Priority order: all T frames for `priority_m` first, then other M positions.
- Emits `finished()` exactly once — after the priority-M series, so the viewer
  can start QPixmap conversion before other M positions are done.
- Memory guard: if `n_m × n_t > 500` frames, caches only `priority_m`.

### Cache State in `MultiAxisViewer`

- `_render_cache: dict[(m, t) → np.ndarray]` — numpy uint8 composites
- `_pixmap_cache: dict[t → QPixmap]` — pre-converted pixmaps for current M
- `_cache_m: int` — which M position the pixmap cache covers
- `_cache_ready: bool` — True once priority-M series is cached

### Display Fast-Paths (in priority order)

1. **QPixmap cache** (`_pixmap_cache`) — pure paintEvent swap, zero numpy work
2. **numpy cache** (`_render_cache`) — skips LUT+compose, still needs
   `QImage→QPixmap` (~1ms vs ~50ms for live compose)
3. **Live compose** — original path, always available as fallback

### Other Changes

- T-slider debounce: 50ms → 5ms
- FPS spinbox range: 0.1–30 → 0.1–60
- `_set_axis_playing`: min interval 50ms normally, 16ms when cache is ready
- `_axis_tick`: blocks `valueChanged` signal during playback to avoid debounce;
  calls `_do_refresh()` directly (saves 5ms of added latency per tick)
- Cache invalidated on LUT contrast change or channel color/enable change;
  worker restarted with new LUT snapshot
- `ImageCanvas.set_pixmap_direct()` added for zero-copy pixmap display

## Key Decisions

- **Shared dict, no lock**: CPython's GIL makes `dict[key] = value` atomic;
  no additional synchronization needed for the worker→GUI read pattern.
- **QPixmap on main thread only**: numpy→QImage→QPixmap conversion runs in
  `_build_next_pixmap_batch()` on the main thread in 5-frame batches to avoid
  blocking the event loop.
- **GPU path unchanged**: `_start_pre_render_worker()` returns early when
  `_use_gpu_canvas=True`; the GPU canvas handles compositing GPU-side.
- **Recipe-page unaffected**: `set_channels()` sets `_volume = None`;
  `_start_pre_render_worker()` returns early on `volume is None`.
