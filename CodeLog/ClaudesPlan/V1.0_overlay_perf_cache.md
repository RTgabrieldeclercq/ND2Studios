# V1.0 Overlay Performance Cache

## Goal

Eliminate the 30–80 ms lag when a polygon mask (or any analysis overlay) first
appears on a frame, and make T-slider scrubbing with overlays active as fast as
it is without overlays.

## Problem

`MultiAxisViewer._do_refresh()` guards every fast path with
`_frame_post_process is None`.  The moment an overlay is registered all three
tiers (GPU path, QPixmap cache, render cache) are skipped, falling through to
the most expensive path: full CPU LUT+compose (~20–50 ms for multi-channel 2K
images) plus `_composite_overlay()` (rasterize + blend, ~10–30 ms).

The `_render_cache` already holds pre-composited base RGB frames filled by
`PreRenderWorker` — those are silently ignored whenever an overlay is active.

## Approach

Parallel to the slider optimization (materialized RAM + three-tier render
cache): add two new cache tiers specifically for the post-processed overlay
result, and opportunistically fill the render cache even on the live-compose
fallback path (benefits GPU-canvas users who never run PreRenderWorker).

### MultiAxisViewer changes (`nd2studios/widgets/multi_axis_viewer.py`)

- `_pp_cache: Dict[(m, t, pp_version), ndarray]` — stores the overlay-composited
  frame for a given (m, t) at a specific overlay version.
- `_pp_version: int` — incremented whenever the overlay content changes.
- `invalidate_post_process_cache()` — public; increments version + clears cache.
  Called by AnalysisPage whenever shapes change.
- `set_frame_post_process()` now calls `invalidate_post_process_cache()` before
  `_do_refresh()` so stale results are never shown.
- `_invalidate_render_cache()` and `_start_pre_render_worker()` both clear
  `_pp_cache` alongside render/pixmap caches (LUT change → stale base → stale overlay).
- `_do_refresh()` gains two new tiers (inserted before the live-compose fallback):
  1. **pp_cache hit**: zero numpy work if (m, t, pp_version) cached.
  2. **render_cache + post-process**: skips LUT/compose, only pays for overlay.
- `_compose_current_frame()`: fills `_render_cache` on-demand for the current
  (m, t) if not already present, then caches the post-processed result in
  `_pp_cache` before returning.

### AnalysisPage changes (`nd2studios/pages/analysis_page.py`)

- `_raster_cache: Dict[(m, t, z_slot, raster_version), ndarray]` — caches the
  rasterized int32 mask per (frame, z, shape-version).
- `_raster_version: int` — incremented when drawn shapes change.
- `_invalidate_mask_cache()` — helper; increments `_raster_version`, clears
  `_raster_cache`, calls `viewer.invalidate_post_process_cache()`.
- `_composite_overlay()` Manual Mask branch: checks `_raster_cache` before
  calling `rasterize_shapes()`; caches result; bounds cache at 200 entries.
- `_invalidate_mask_cache()` called before `_update_overlay()` in:
  `_on_shape_drawn`, `_on_clear_current_frame`, `_on_vertex_moved`,
  `_on_apply_expand`.

## Performance Impact

| Scenario | Before | After |
|---|---|---|
| Polygon appears (cold, base cached) | 30–80 ms | 10–30 ms |
| Same frame revisited, overlay unchanged | 30–80 ms | ~1 ms |
| T-slider with overlay active | 30–80 ms/frame | ~15 ms first, ~1 ms repeat |
| Vertex drag | 30–80 ms/event | ~15–25 ms/event |
| All non-manual pipelines (spots, threshold) | 30–80 ms | same gains via pp_cache |
