# V1.70 · P0 — Granule Separation: shared contracts (BLOCKS P1–P7)

**Feature:** separate a 3-D point cloud of bead centroids into the hydrogel
**granules** they belong to (cluster → tessellate → mask → view/boundary), reusing
the V1.65–V1.68 mask/object/viewer/DVC machinery for the back half.

**This sub-plan defines the interfaces every other sub-plan depends on. It must be
implemented first and then held stable.** P1–P5 (backend modules) can then be built
fully in parallel against these contracts; P6 (shared-file integration) and P7
(viewer + docs + compaction) come after.

## 1. Node chain & ports

Five new **special** nodes (`ShapeKind.HEXAGON`, `NodeCategory.SPECIAL`). Node 4
("volume viewer") is **not** a node — it is a "View in 3-D" path on the existing
`PyVista3DViewer`. Per the executor model, **artifacts flow via shared record/page
state, not through edge payloads** (exactly as `special:mask3d` publishes to
`record._mask3d_by_m`); ports exist only for wiring validation (`can_connect`,
`pipeline_graph/model.py:461`).

```
raw (Z,H,W) ─CHANNEL─▶ [Bead Detect] ─DATA─▶ [Cluster] ─DATA─▶ [Tessellate] ─ANY─▶ [Mask] ─┬─ANY─▶ [Boundary]
                                                                                           └────── "View in 3-D"
```

| Node | op_key | input_types | output_types | produces objects? |
|------|--------|-------------|--------------|-------------------|
| Bead Detect | `special:bead_detect` | `[IMAGE]` (rainbow channel) | `[DATA]` | no |
| Cluster | `special:granule_cluster` | `[DATA]` | `[DATA]` | no |
| Tessellate | `special:granule_tessellate` | `[DATA]` | `[ANY]` | no |
| Mask | `special:granule_mask` | `[ANY]` | `[ANY]` | **yes** |
| Boundary | `special:granule_boundary` | `[ANY]` | `[ANY]` | no |

Rationale for `ANY` on Mask/Tessellate/Boundary out: mirrors `special:mask3d`
(output `[PortType.ANY]`) so they wire in front of DVC/analysis and the viewer;
`BINARY→IMAGE` is rejected by `can_connect`, `ANY` is the wildcard (see the V1.65
mask node's corrected port typing).

## 2. Record storage keys (the real data channel)

All keyed **per `(m, t)`** exactly like `record._mask3d_by_m` (`{m:{t:…}}`), set on
both the page (`self._granule_*_by_m`) and the record (`record._granule_*_by_m`) for
cross-Run reuse — follow `_run_mask3d_node` (`pipelines_page.py:6278`, publish
`:6368`).

| Key | Value shape | Producer |
|-----|-------------|----------|
| `record._granule_points_by_m` | `{m:{t: np.ndarray (N,3) float}}` voxel coords, **`(z,y,x)` order** (+ a parallel `List[Dict]` DATA rows, §3) | P1 Detect |
| `record._granule_labels_by_m` | `{m:{t: np.ndarray (N,) int}}` per-point granule id (**initial** GMM labels; `-1` = noise) | P2 Cluster |
| `record._granule_tess_by_m` | `{m:{t: GranuleTessellation}}` (boundaries + densities + **final merged** per-point labels) — see §4 | P3 Tessellate |
| `record._granule_masks_by_m` | `{m:{t: {granule_id:int → (Z,H,W) bool}}}` **plus** `["_labels"] → (Z,H,W) int32` combined | P4 Mask |
| `record._granule_bands_by_m` | `{m:{t: {granule_id:int → (Z,H,W) bool}}}` **plus** `["_labels"]` combined band | P5 Boundary |

`record._granule_masks_by_m[m][t]` intentionally has the **same value type** as
`record._mask3d_by_m[m][t]` for a single object — a `{id:(Z,H,W) bool}` dict — so the
scope lever / `iter_objects` / DVC-on-object read it with no special-casing.

## 3. Point-cloud DATA row schema (P1 → P2/P3)

Point clouds ride the existing `PortType.DATA` = `List[Dict]` measurement-row
convention (`model.py:32`). P1 writes the **first `centroid_z_px` in the app**; the
read path already exists (`serialtrack_analysis.py:58-67`). Each row:

```python
{
  "bead_id": int,            # 0..N-1 within (m,t)
  "m_position": int,         # multipoint
  "frame": int,              # T index
  "centroid_z_px": float,    # NEW writer (voxel/plane index, sub-voxel ok)
  "centroid_y_px": float, "centroid_x_px": float,
  "centroid_z_um": float, "centroid_y_um": float, "centroid_x_um": float,
  "granule_id": int | None,  # filled by P2 (initial), overwritten by P3 (final); None until clustered
}
```

`_um = _px * (z_step_um | pixel_size_um)`. The bare `(N,3)` array in
`_granule_points_by_m` is the fast path for P2/P3 maths; the rows are for the Results
tab / DATA-port consumers.

## 4. `GranuleTessellation` dataclass (P3 output, consumed by P4)

Pure dataclass in a new `backend/analysis/granule_types.py` (Qt-free, imported by
P3/P4 and the page):

```python
@dataclass
class GranuleBoundary:
    granule_id: int
    vertices_um: np.ndarray      # (Nv,3) world (x,y,z) µm  — matches viz3d convention
    faces: np.ndarray            # (Nf,3) int  (alpha-shape / hull triangles)
    delaunay: object | None      # scipy.spatial.Delaunay for fast inside-test (P4); None if unavailable
    enclosed_volume_um3: float
    n_points: int
    density: float               # n_points / enclosed_volume_um3  (or Voronoi cell density)

@dataclass
class GranuleTessellation:
    mode: str                    # "alpha_shape" | "voronoi"
    boundaries: Dict[int, GranuleBoundary]   # final (post-merge) granule_id -> boundary
    point_labels: np.ndarray     # (N,) int  final merged granule id per input point
    merged_from: Dict[int, list] # final_id -> [original GMM ids merged into it]
    voxel_size_um: tuple         # (dz,dy,dx) the boundaries are expressed against
```

## 5. Coordinate & unit conventions (pin once, obey everywhere)

- **Point cloud storage order = `(z,y,x)`** to match the app-wide measurement/track
  convention (`serialtrack_analysis.py:18-24`). `ParticleDetector.detect` returns
  **`(x,y,z)`** (in-file convention, `detection.py:43`) — **P1 transposes** and this
  is the ONLY place the flip happens.
- **Mesh vertices = world `(x,y,z)` µm** to match `viz3d` (`surface.py:37`,
  `overlays.py`) so P4/Node-4 feed the existing surface stack unchanged.
- **Voxel size = `(dz,dy,dx)` µm** everywhere (`prep.Spacing`, `prep.py:35`);
  `dz=z_step_um`, `dy=dx=pixel_size_um`, read via `prep.spacing_from_volume(vol)`.
- **Mask/label bbox = `(z0,z1,y0,y1,x0,x1)` half-open** (`object_scope.ObjectRegion`).

## 6. `iter_objects` extension contract (implemented in P6; specified here)

`backend/analysis/object_scope.iter_objects(obj, …)` currently dispatches on dtype:
`(Z,H,W) bool` → 3-D connected components; `(T,H,W) int` → per-label over T
(`object_scope.py:133`). A combined `(Z,H,W) int32` granule-label volume would be
**mis-read as `(T,H,W)`**. Two-part contract:

1. **P4 sidesteps it**: the mask node publishes per-granule **`(Z,H,W) bool`**
   volumes (each dispatches correctly as a single 3-D object), so the scope lever /
   DVC-on-object work today with zero `object_scope` changes.
2. **P6 makes the label volume first-class**: add an explicit
   `iter_objects_3d_labels(labels_zhw_int32, voxel_size_um, …)` (or a `zdim=True`
   flag) that treats a `(Z,H,W) int32` as **one 3-D region per label id** (bbox via
   `find_objects`, mask = `labels==id`). Assert parity with the per-granule-bool path
   in `tests/scope/`.

## 7. Optional-dependency gating (obey `CLAUDE.md`)

`scikit-learn` (P2 GMM) is optional/lazy, `importlib.util.find_spec("sklearn")`,
friendly `ImportError`, **not** in `requirements.txt` (cellpose/stardist/pyvista
precedent). `scipy.spatial` (P3 Voronoi/Delaunay/ConvexHull) is already installed
(Qhull present) — no gating needed, but catch `scipy.spatial.QhullError`
(`serialtrack/regularization.py:24` already imports it) for degenerate clouds.
