# V1.59 — Pause-node crop preview on the registered image

## Goal

Make the **Pause** node a proper troubleshooting checkpoint: when a Run pauses
(dropping the page back to editor mode), the user can arm the **Preview Crop**
tool, draw a rectangle on the viewer, and have the *downstream* pipeline
**preview** on that cropped sub-region. This is especially useful right after an
**Image Registration** node, which reconstructs the viewer to the drift-corrected
image — the user wants to crop the *registered* image and preview segmentation /
tracking on that crop to check it works before committing to a full Run.

Scope (confirmed with the user):
- **Preview only.** The crop drives live preview during the pause; resuming the
  Run stays full-frame (the frozen upstream Run state was computed full-frame, so
  a cropped resume would mix frame sizes). Cropped *full* Runs remain available
  via the existing Run ▾ menu from a fresh (non-paused) start.
- **Consistent for any Pause.** The crop-preview flow works for every Pause;
  registration is simply applied when transforms exist. No special-casing.

## Key findings (code survey)

Registration already reconstructs the viewer: `_finish_register`
(`pipelines_page.py`) stores per-M transforms on `record._registration_by_m`,
writes aligned channels into `record._processed_channels`, and repaints the main
viewer via `_apply_registration_writeback` → `viewer.set_channels(...)`. Run-time
downstream reads apply the transforms in `_processed_channels_for_m` →
`_apply_registration_to_channels` (recipe → **crop** → registration).

Three gaps break the paused-crop-on-registered workflow:

1. **Preview never applies registration.** The Analysis/Results preview readers
   (`_extract_processed_frame` → `_read_processed_planes` / `_do_analysis_preview`,
   and `_materialize_channels_for_m`) go raw → recipe → crop with no registration
   step; preview even explicitly skips it. So a downstream *preview* after a
   registration+pause runs on the **un-registered** image.

2. **Arming the crop reverts the viewer to un-registered.** `_show_base_image`
   rebuilds the base from `ProcessedFrameVolume(raw_volume, recipe)` (no
   registration) and the crop toggle calls it with `force=True`. So arming the
   crop overwrites the registered image the writeback painted — the user would be
   cropping the raw+recipe picture, not the registered one.

3. **Crop-vs-registration order is backwards for a crop of the registered image.**
   `_processed_channels_for_m` crops *before* registration. A full-frame transform
   applied to an already-cropped array misaligns. For "a crop of the registered
   image" the order must be **register the full frame, then crop**, so a rectangle
   drawn in registered-display coordinates maps directly onto the sliced region.

## Approach

### Backend — `nd2studios/backend/registration/estimate.py`
- Add `apply_frame(frame, transforms, t, interp_order=1)`: apply the *t-th*
  per-frame shift/warp from a `transforms` dict to a single 2-D frame (the
  single-plane analogue of `apply_series`). Returns the frame unchanged for an
  identity/absent transform or an out-of-range `t`. Reuses `apply_shift` /
  `apply_warp`.

### Backend — `nd2studios/pipeline_graph/executor.py` (+ `__init__.py`)
- Add `class RegisteredFrameVolume`: a lazy wrapper (mirroring
  `ProcessedFrameVolume` / `CroppedVolume`, `bypass_pyramid = True`) that wraps a
  base volume and applies the per-`(m, t)` transform in `get_frame` via
  `estimate.apply_frame`. No-op for an M without transforms. Mirrors the
  `channel_names` / `n_*` / `height` / `width` / `dtype` / `pixel_size_um` /
  `z_step_um` attributes so the viewer's `get_frame` path drives it.
- Export `RegisteredFrameVolume` from `pipeline_graph/__init__.py`.

### Page — `nd2studios/pages/pipelines_page.py`
- **Register-then-crop order.** In `_processed_channels_for_m`, apply registration
  to the full-frame recipe output *before* the crop when a crop is active (register
  full → crop), keeping the existing crop-then-register only when no crop is set is
  unnecessary — simplest is always register full, then crop. Restructure so the
  crop slice happens last.
- **New helpers:**
  - `_register_frame(record, frame, m, t)` — apply the stored `(m, t)` transform to
    a `(1,H,W)`/`(H,W)` frame (no-op when no transforms / identity). Import
    `estimate` lazily.
  - `_maybe_register_volume(record, vol)` — wrap `vol` in `RegisteredFrameVolume`
    when `record._registration_by_m` is populated, else pass through.
- **Preview readers apply registration (full frame), then crop:**
  - `_extract_processed_frame`: register the lazy-volume-derived frame before
    return (the `_processed_channels` fallback is already registered by the
    writeback, so only the raw→recipe branch needs it). Its two call sites
    (`_read_processed_planes`, `_do_analysis_preview`) already `_crop_frame` after,
    giving register→crop.
  - `_materialize_channels_for_m`: assemble the full-frame `{channel:(T,H,W)}`
    dict, run it through `_apply_registration_to_channels`, then `_crop_frame` each
    (Spatial Maps / validation preview on the registered crop).
- **Base image stays registered under the crop:** `_show_base_image` wraps the
  base in `_maybe_register_volume` *before* `_maybe_crop_volume` (lazy-volume
  path), and in the in-RAM fallback prefers `record._processed_channels` (already
  registered by the writeback) over `_raw_channels` when registration is active.
  This fixes the crop-toggle reversion (gap 2).
- **Pause status hint:** update `_pause_run`'s status to mention crop-preview
  (“…Preview Crop to troubleshoot a sub-region, then Run to resume”).

## Key decisions / notes
- Register-then-crop is the correct order for a crop *of the registered image*;
  it also matches what the user sees in the reconstructed viewer.
- Registration transforms persist on the record through the pause (they are only
  cleared at the next fresh Run start), so preview can reuse them with no
  recompute.
- Preview-only: a resumed Run ignores the crop (unchanged), avoiding a size
  mismatch between full-frame frozen upstream state and a cropped downstream.
- All new registration in preview is gated on `record._registration_by_m` being
  populated, so graphs without a Registration node are completely unaffected.
