# V1.46 — Restore CellTracker's segmentation speed (≈2× slower → parity)

## Report

CellTracker's original repository runs the same StarDist segmentation ~2× faster
than ND2Studios. Go back to CellTracker's way of running the analysis.

## Two divergences from CellTracker (both restored)

CellTracker's segmentation is `celltracker/segmentation.py:segment_frame`
(normalize → `predict_instances`, with tiling for big frames) called per frame by
`segment_timeseries` — load model once, store `label_stack[t] = labels`, nothing
else per frame. ND2Studios vendored `segment_frame` **byte-for-byte**, so the
inference itself matches. The slowdown came from two ND2Studios-only additions:

1. **Per-frame post-processing was O(n_objects × pixels).** Both the StarDist and
   Cellpose nodes did the area filter with `mask[mask == region.label] = 0` *per
   out-of-range object* and then `_relabel_contiguous` with
   `out[mask == old_id] = new_id` *per object* — a full-frame scan per object. On a
   4096² frame with thousands of nuclei this is ~50 s/frame. CellTracker has no
   such loop.

2. **TensorFlow pinned to one inter/intra-op thread** (`_ensure_tf_threading`),
   roughly halving StarDist inference on a multi-core CPU. CellTracker leaves TF
   threading at its default.

## Changes

- **add** `nd2studios/backend/analysis/source_utils.py:filter_and_relabel(mask,
  min_area, max_area)` — area filter **and** contiguous relabel in one `O(pixels)`
  pass: `np.bincount` for per-label areas, a LUT mapping surviving labels →
  contiguous ids, `lut[mask]` to apply both at once. Bit-identical to the old
  filter→relabel.
- `analysis/stardist_segmentation.py`, `analysis/nuclei_segmentation.py` — call
  `filter_and_relabel`; drop the per-object loop + the duplicated
  `_relabel_contiguous`.
- `backend/celltracker/segmentation.py` — `_ensure_tf_threading` → `_ensure_tf_ready`:
  keep the pre-import `CUDA_VISIBLE_DEVICES` GPU handling, drop the two
  `set_*_op_parallelism_threads(1)` calls so TF uses all cores (CellTracker's way).

## Key correction — TF threading must STAY single inter/intra-op

An interim revision *removed* the single-thread cap on the theory that CellTracker
ran with TF's multi-threaded default. That was wrong and made segmentation **~10×
slower**. Checking the actual repo
(`C:\Users\gabri\Documents\GitHub\Cell-Tracker\CellTracker\backend\segmentation.py`)
shows CellTracker **explicitly** pins TF to one inter/intra-op thread
(`_ensure_tf_threading`), and its module docstring stresses this must be configured
before any TF op. StarDist tiles a large frame into many small `predict_instances`
passes; multi-threaded intra-op oversubscribes the cores and thrashes on those small
ops, so single-threaded is dramatically faster.

Final state: `_ensure_tf_threading` keeps the
`set_inter/intra_op_parallelism_threads(1)` cap (CellTracker's way), plus the
ND2Studios-only GPU-flag handling (`CUDA_VISIBLE_DEVICES` cleared before the first
TF import). The lazy call works in ND2Studios (TF isn't imported before the first
model load — confirmed because the cap measurably took effect), so no
process-startup config is needed.

## Cross-check against the real repo

- `measurement.py:measure_frame` extracts intensity per object from the **bbox
  slice** (`ch_frame[p.slice][mask]`), not a full-frame `mask == label` scan — so
  the earlier `compute_measurements` vectorisation (single `ndimage` pass) and
  `filter_and_relabel` match CellTracker's efficiency; both kept.
- `segment_timeseries` does no area filter / relabel — `filter_and_relabel` is an
  ND2Studios feature kept, now at `O(pixels)` so it adds negligible per-frame cost.

## Verification

- `filter_and_relabel` vs. the old filter→relabel: identical masks across area
  ranges `(4,5000)`, `(1,10)`, `(20,40)`, including deleted-label gaps.
- Timing (2048², ~6 k labels): 12.81 s → 0.030 s (~430×); at 4096² the old path
  was ~50 s/frame.
- `py_compile` + import clean; both segmentation pipelines still register;
  `_ensure_tf_ready` present, `_ensure_tf_threading` gone.
- StarDist/Cellpose inference unchanged (vendored `segment_frame` untouched; only
  TF op-parallelism default and the post-processing changed).
