# V1.42 — Viewer Optimizations from Industry Comparison

## Goal

Adopt five concrete techniques from popular microscopy viewers (Nikon
NIS, Fiji/Bio-Formats, BigDataViewer, napari) that ND2Studios doesn't
yet do. These are the highest-ROI items from the V1.41 comparative
research report.

## Approach

### M1. Shader-LUT decoupling (napari pattern)

**Problem:** Today, any LUT/contrast change calls
`MultiAxisViewer._invalidate_render_cache()` which throws away the
entire PreRenderWorker output (~6 GB of uint8 RGB) and restarts the
worker. The user experiences a stall on every contrast slider drag.

**Fix:** When the GPU canvas is active, LUT/contrast changes already
have a fast path via `GpuImageCanvas._ChannelLayer.set_lut_levels(lo,
hi)` which calls pyqtgraph's `ImageItem.setLevels()` (a GPU uniform
update). The cache invalidation is only needed when the data
*structure* changes (channel enable/disable, color choice). Split
`_invalidate_render_cache()` into:

- `_invalidate_render_cache(*, lut_only: bool = False)` — when
  `lut_only=True` on a GPU-canvas-enabled session, no-op. The pyqtgraph
  canvas re-applies the new LUT on its next paint via existing levels
  state. On the CPU-canvas path, full invalidation still runs.

Hook this through `lut_histogram`'s `lut_changed` signal so contrast
drags route through the cheap path while channel toggles keep the
expensive invalidation.

**Files:** [multi_axis_viewer.py](nd2studios/widgets/multi_axis_viewer.py),
[gpu_image_canvas.py](nd2studios/widgets/gpu_image_canvas.py),
[lut_histogram.py](nd2studios/widgets/lut_histogram.py)

### M2. Pyramid-by-zoom at view time (BigDataViewer pattern)

**Problem:** `PyramidStage` builds a multi-level zarr pyramid but the
viewer only reads level 0. `PyramidReader.pick_level_for_viewport`
already exists ([pyramid_stage.py:509](nd2studios/pipeline/stages/pyramid_stage.py#L509))
and computes the smallest level whose width exceeds the viewport.

**Fix:** In `MultiAxisViewer._compose_current_frame` and the GPU
render path, after a viewport change, ask the attached `PyramidReader`
for the best level given the current `ViewBox` rect, then source
frames from that level. Use level 0 (full ND2) only when zoomed in.

For the in-RAM materialized path: we keep `MaterializedDataset.get_frame`
at level 0 by default but accept an optional `pyramid_reader` argument
that the viewer passes through.

**Files:** [multi_axis_viewer.py](nd2studios/widgets/multi_axis_viewer.py)
(query viewport → pick level → swap source), pyramid_stage.py
(already has `pick_level_for_viewport` and `PyramidReader.get_frame`)

### M3. `.nd2idx` sidecar (Bio-Formats Memoizer pattern)

**Problem:** `read_nd2_metadata_extended()` opens the ND2 and walks
chunks every time. For multi-GB files this is 1–5 seconds per open.

**Fix:** After a successful metadata read, persist the result as
`<file>.nd2idx.json` next to the file. On next open, if the sidecar
exists AND its `mtime` is newer than the ND2's, load it and skip the
scan. Stored fields: everything `read_nd2_metadata_extended` produces
(metadata is small — a few KB max).

**Files:** new helper `read_or_cache_nd2_metadata(filepath)` in
[nd2_loader.py](nd2studios/backend/nd2_loader.py); wire it into
[load_worker.py:_load_nd2](nd2studios/workers/load_worker.py#L93) at
the metadata-read site.

### M4. Cancel-first slice request queue (napari NAP-4)

**Problem:** Slider drags emit `frame_changed` for every value; the
existing debounce timer (`_t_debounce`) helps but doesn't cancel in-
flight composite work. On a slow path (live compose fallback)
intermediate compositing wastes CPU and the GUI feels laggy.

**Fix:** New `nd2studios/utils/request_queue.py` with a
`SingleSlotRequest` pattern: when a new request arrives, mark any
in-flight request as cancelled (sets a flag the worker checks at
known cancellation points). Mailbox of size 1 — only the most
recent request is honored. Optional second lane (low priority) for
prefetch.

Integrated into `MultiAxisViewer` for `frame_post_process` and
`_compose_current_frame` paths.

**Files:** new `nd2studios/utils/request_queue.py`,
[multi_axis_viewer.py](nd2studios/widgets/multi_axis_viewer.py)

### M5. Tile-LRU on LazyND2Channel (BDV CellCache pattern)

**Problem:** `LazyND2Channel` reads a frame on every access. Repeated
reads of the same frame (e.g., user scrubs back and forth) pay full
decode cost each time.

**Fix:** Wrap `LazyND2Channel._read_frame` with an LRU cache keyed by
`(t_local,)` (and `(t_local, crop)` if cropped). Cache size respects
`recommended_cache_budget_bytes()`. Eviction policy: LRU on byte
budget. When `_invalidate_render_cache(*, lut_only=False)` runs, also
clear this cache.

**Files:** [nd2_loader.py](nd2studios/backend/nd2_loader.py)
`LazyND2Channel`.

## Implementation Order

1. **M3** — `.nd2idx` sidecar (smallest, biggest user-visible win on
   re-opens).
2. **M1** — Shader-LUT decoupling. Single biggest improvement to
   contrast-slider responsiveness.
3. **M5** — LazyND2Channel LRU. Self-contained; helps any code path
   using the lazy proxy.
4. **M2** — Pyramid-by-zoom. Requires viewport plumbing.
5. **M4** — Request queue. Polishing step.

## Verification

- **M3**: `time python -c "from nd2studios.backend.nd2_loader import
  read_nd2_metadata_extended; read_nd2_metadata_extended('big.nd2')"`
  on first run vs second run. Expect ≥10× speedup on re-open.
- **M1**: Open a 100-frame 4-channel file, drag the LUT histogram.
  Without M1 → playback warm-up stalls. With M1 → contrast updates
  in <16 ms.
- **M5**: Use `LazyND2Channel` directly, fetch the same frame twice;
  second access should be sub-millisecond.
- **M2**: Open a large mosaic file, build pyramid, zoom out. Memory
  consumption should not spike because we're rendering from a coarse
  level.
- **M4**: Slider drag, verify intermediate frames don't accumulate
  via `ND2_PERF_LOG=1` log.

## Out of Scope

- **Texture atlas / full octree** — heavy infrastructure for
  whole-slide data. Defer until a user asks.
- **OME-Zarr as canonical store** — strategic question, not a perf
  one.
- **Dask wrap of nd2.to_dask()** — useful for analysis pipelines,
  not view-time.
