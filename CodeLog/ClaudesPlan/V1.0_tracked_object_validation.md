# V1.0 — Tracked Object Validation

## Goal

Add cross-frame object tracking and an interactive validation workflow to the
Results tab so users can review, accept, and reject objects that appear across
multiple time frames.

## Problem / Motivation

All five analysis pipelines produce independent label masks per frame — objects
are not linked across T.  For live-cell imaging, the same physical object
appears in many frames, and the user needs a way to (a) confirm it is the same
object, and (b) decide whether to include its measurements in the exported
dataset.

## Approach

### 1. Hungarian linker (`nd2studios/backend/object_tracker.py`)

`link_objects(rows, max_displacement_px=100)` is called once in
`ResultsPage._on_compute()` immediately after `compute_measurements()`.  It
groups rows by `(segmentation_channel, m_position)`, sorts each group by frame,
and runs `scipy.optimize.linear_sum_assignment` on pairwise Euclidean centroid
distances between consecutive frames.  Pairs whose distance exceeds
`max_displacement_px` are not linked.  Tracks that span ≥2 frames receive a
stable integer `track_id`; single-frame detections get `track_id = None`.

New columns added to every row:
- `track_id` — int or None
- `track_length` — number of frames the track spans
- `track_validation` — "unvalidated" | "accepted" | "rejected" | None

### 2. Validation dialog (`nd2studios/widgets/track_validation_dialog.py`)

`TrackValidationDialog` opens at 90% of the primary screen size.  It iterates
through unvalidated tracks in frame-order.  For each track it:

1. Computes a fixed crop region: union of all per-frame bounding boxes expanded
   2× (center ± object height/width), clamped to image bounds.
2. Pre-renders all T frames using `_composite_frame` (same pipeline as the
   viewer and exports) with a yellow-orange mask highlight
   (RGB 255, 200, 50 at α 0.55) drawn over the object's pixels.
3. Exposes a T slider, play/pause button, and FPS spinbox.

Accept → mark `track_validation = "accepted"`.
Reject → mark `track_validation = "rejected"`.
After each decision the dialog auto-advances to the next unvalidated track.
When all tracks have been reviewed, `exec()` returns.

### 3. Results page (`nd2studios/pages/results_page.py`)

- Added "Tracking" column group: `track_id`, `track_length`, `track_validation`.
- Added `Max disp. (px)` spinbox (range 1–9999, default 100) to the controls
  row; its value is passed to `link_objects` on every compute.
- Added "Validate Tracked Objects" button (export row); enabled only after
  compute produces ≥1 multi-frame track.
- After the dialog closes, rows belonging to rejected tracks are removed from
  `self._measurements`; accepted rows get `track_validation = "accepted"`.

## Key Decisions

- Tracking is **on-demand** (computed each time "Compute Measurements" is
  clicked) and is **not persisted** to the `.nd2s` session file.  The user
  re-validates after each compute.  This avoids schema changes and keeps the
  pipeline simple for V1.

- For **multi-M experiments**, only M-position 0 data is shown in the
  validation dialog (labeled as V2 enhancement).

- `link_objects` uses a **greedy nearest-neighbour** approach via the
  full Hungarian algorithm rather than Munkres, so no new dependency is
  needed (scipy is already required).

- The validation dialog **pre-renders all T frames** per track on load.  This
  is fast for the typical crop size (2× object bbox).

## Testing

1. Load a multi-T ND2 file.
2. Run any pipeline on the Analysis page.
3. Results page → Compute Measurements → verify `track_id`, `track_length`,
   `track_validation` columns appear.
4. Confirm "Validate Tracked Objects" is enabled only when tracks exist.
5. Click "Validate Tracked Objects" → dialog opens at ~90% screen.
6. Scrub T slider, play/pause, adjust FPS — verify playback works.
7. Accept one track, reject another → verify rejected rows absent from table.
8. Reduce `max_displacement_px` to 1 → verify no tracks form.
