# V1.53 — Checkpoint Node (freeze upstream, iterate downstream)

## Goal

Add a **Checkpoint** node to the merged Analysis pipeline graph: a special
white node that, when a Run passes through it, *freezes* everything computed
upstream (StarDist / analysis label masks, measurement rows, tracks). On the
next Run — as long as the upstream graph is unchanged — the run **starts at the
checkpoint** with the frozen data restored, so the expensive upstream work
(segmentation, tracking) never re-runs. This lets the user iterate on the
downstream pipeline (add / change / rewire nodes after the checkpoint) with
instant Runs.

Design decisions (confirmed with the user):
- **Auto invalidation via upstream hash.** Freeze stores a hash of the upstream
  subgraph (ancestor nodes + params + wiring + the Processing recipe + crop). On
  Run, if the current upstream hash matches a checkpoint's stored hash, resume
  from that checkpoint; otherwise re-run from Input and re-freeze.
- **Session RAM, plus per-node disk persistence (V1.53 follow-up).** Frozen masks
  / rows live in memory for the session (like `record.analysis_results`), cleared
  on file change / close. Each checkpoint node has a **`persist_to_disk` bool
  param** (default off = session-only): when on, saving the pipeline persists
  *that* checkpoint's frozen data to a companion `<pipeline>.checkpoints/` cache
  (compressed NPZ of label masks + an `index.json` manifest); loading the pipeline
  restores it, so the checkpoint survives app restarts. Session-only checkpoints
  are never written; toggling one back off deletes its stale cache on the next
  save. Validity is still gated by the upstream hash — now including a
  **source-file signature** — so a cache reloaded against a different file or an
  edited graph re-runs harmlessly rather than serving stale masks. Serialization
  lives in the Qt-free `pipeline_graph/checkpoint_io.py`; the page calls it from
  `_on_save` / `_on_load` (`_save_checkpoint_cache` / `_load_checkpoint_cache`),
  filtering the store by each node's `persist_to_disk` param.

## Approach

### Model / registry (Qt-free)
- `model.py`: new `NodeCategory.CHECKPOINT` (color/grouping only; dispatch stays
  keyed on op_key).
- `registry_adapter.py`: new `SPECIAL_CHECKPOINT_OP_KEY = "special:checkpoint"`,
  added to `_SPECIAL_OPS` as a hexagon, `PortType.ANY` in/out (pass-through, like
  Pause), category `CHECKPOINT`. No params. Exported from
  `pipeline_graph/__init__.py`.
- `io.py`: `_normalize_special_categories` already re-derives category from
  `special_specs()` on load, so a saved checkpoint node picks up the CHECKPOINT
  category automatically. No schema bump needed (a new op_key does not break old
  files; older builds would treat it as an unknown pass-through node).

### GraphRunner (executor.py) — resume support
- Add an optional `frozen: Optional[set]` param to `GraphRunner.__init__`. Each
  frozen node is marked reached + done + dispatched, and its structural
  successors are reached — so a topological walk from Input treats the frozen
  ancestors as already complete: they never become `next_ready`, but the
  checkpoint (their successor) is reached and runs, and reconverging downstream
  nodes still gate correctly on the frozen (done) upstream. A run with
  `frozen=None`/`set()` behaves exactly as today.

### UI (node_board)
- `settings.py`: `ACCENT_WHITE = "#ffffff"`.
- `node_scene.py`: map `NodeCategory.CHECKPOINT -> Settings.ACCENT_WHITE`.
- `node_item.py`: new run-state `"cached"` (dimmed body + white border) so the
  frozen upstream nodes read as "won't re-run".

### Run flow (pipelines_page.py)
- `__init__`: `self._checkpoint_store: Dict[str, dict] = {}`
  (`node_id -> {"hash": str, "data": snapshot}`).
- Dispatch: `_run_execute_node` gains `elif op == SPECIAL_CHECKPOINT_OP_KEY:
  self._run_checkpoint(node)`.
- `_run_checkpoint(node)`: ensure run rows exist, then snapshot the current run
  accumulators (`_run_results_by_m`, `_run_all_rows`, `_run_context`
  rows/result/results_by_m, `_results_rows`, `_run_results_crop`, and the track
  overlay state `_track_colormap` / `_track_long_ids` / `_track_overlay_rows`)
  into `_checkpoint_store[node.id]` alongside the upstream hash. Complete the
  node. AnalysisResult / mask arrays are held by reference (session RAM).
- `_checkpoint_upstream_hash(node_id)`: BFS the structural ancestors of the
  checkpoint; hash their (op_key, sorted params), the edges feeding them
  (structural + channel, so the wired channel counts), any loop-edge config
  touching them, plus the Processing recipe / per-channel recipes / normalized
  flag and the run crop. sha1 hex.
- `_on_run`: after the Pause-resume branch, pick the **furthest-downstream**
  checkpoint whose stored hash equals its current upstream hash (highest
  topological index among valid checkpoints). If found, restore its snapshot
  into the run accumulators + `_run_context`, build
  `GraphRunner(sl, frozen=<structural ancestors of the checkpoint>)`, shade the
  frozen ancestors `"cached"` and the rest `"shaded"`, refresh table / overlays,
  and pump. Otherwise behave exactly as today (fresh `GraphRunner(sl)`).
- Invalidation: drop a node's entry from `_checkpoint_store` when the node is
  deleted and clear the whole store on file change / load / close (session
  scope). Hash mismatch auto-invalidates by simply re-running.

## Key decisions / notes
- Conservative hashing: a param that doesn't affect output still triggers a
  re-run when changed. Acceptable — correctness over cache aggressiveness.
- Multiple checkpoints are supported; resume picks the deepest valid one.
- Loops upstream of a checkpoint are frozen as their combined result (the
  checkpoint sees the post-combine accumulators), so resuming skips the loop.
