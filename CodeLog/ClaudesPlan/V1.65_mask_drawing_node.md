# V1.65 — 3D Mask Drawing node (Phase 1 of "DVC-on-object rendering")

## Context & scope

This is **Phase 1** of a two-phase feature. The end goal (user request) is: let
the user draw a 3D object mask across the Z-stack, then re-render an already-computed
DVC displacement/strain field *onto that object* — surface boundary + interior —
as a new subtab in the DVC viewer, interpolating the sparse DVC subset grid up to
the mask's native resolution.

The user redirected the design: **the mask creation must be its own pipeline-graph
node — a "3D Mask Drawing" node — not a DVC-viewer option.** The DVC-on-mask
rendering (surface/interior visualization, interpolation onto the mask, the new DVC
subtab, and the 3D backend choice) is **Phase 2**, explicitly deferred until the
user asks for it.

**Phase 1 deliverable (this doc):** a "3D Mask Drawing" node that lets the user
draw/edit a 3D mask over the wired channel's raw `(Z,H,W)` volume, supporting all
**three** creation modes, and publishes a per-`(m,t)` `(Z,H,W)` boolean mask volume
that a downstream node (Phase 2 DVC render) can consume.

## Goal

Add a `special:mask3d` node ("3D Mask Drawing") to the Analysis node board that:

1. Wires a **channel** in (rainbow `IMAGE` port) to pick which volume to draw over,
   and emits an **`ANY`** output (pass-through, like Registration) so it wires *in
   front of* DVC/analysis — `input → 3D Mask Drawing → DVC`. *(Originally speced as
   `BINARY`, but `BINARY → IMAGE` is rejected by `can_connect`, so it could not wire
   to DVC; corrected to `ANY` — see the V1.67 plan.)*
2. Opens an **interactive per-Z editor** (a modal dialog embedding `ImageCanvas`)
   over the raw `(Z,H,W)` volume for the current multipoint, with a Z scrubber.
3. Supports **three mask-creation modes**:
   - **Manual (per-plane)** — draw an independent rect / ellipse / polygon on each
     Z plane; only drawn planes are filled.
   - **Propagate across Z** — draw on a few planes; the volume is filled either by
     *copying* the drawn footprint to all Z, or by *interpolating* between the
     nearest drawn planes (signed-distance-field morph) so the surface is smooth
     and higher-resolution than the drawn planes.
   - **Threshold seed + edit** — seed each Z's outline from an intensity threshold
     (0 = Otsu) of the raw plane, converted to editable polygons, then hand-correct
     (draw more, erase, or clear).
4. Rasterizes the drawn shapes into a `(Z,H,W)` boolean mask volume per `(m,t)` on
   Run, stores it on the page (`self._mask3d_by_m`) and the record
   (`record._mask3d_by_m`) for cross-Run reuse.

## Key decisions

- **Node type = a SPECIAL op** (`special:mask3d`), like DVC / Registration — not an
  `AnalysisPipeline`. Rationale (from the subsystem map): it needs the raw `(Z,H,W)`
  volume via `record._raw_volume.get_volume(c,m,t)` and produces a **volumetric**
  artifact, which the `AnalysisResult.label_masks` contract (`{channel:(T,H,W)}`,
  Z already projected) cannot represent. `AnalysisResult` is intentionally *not*
  overloaded.
- **Input = `[PortType.IMAGE]`** (7th `_SPECIAL_OPS` tuple element) so `build_node`
  auto-appends the rainbow `CHANNEL` ports (user wires a channel). **Output =
  `[PortType.ANY]`** (corrected from `BINARY`) — a pass-through so it wires in front
  of DVC/analysis, since `can_connect` needs `ANY` (or an exact match) to pair with
  DVC's `IMAGE` input. `ShapeKind.HEXAGON`, `NodeCategory.SPECIAL`.
- **Drawn data = vector shapes stored inline on `node.params["mask_shapes"]`**
  (a `hidden` ParamSpec), keyed `{str(m): {str(t): {z_key: [shape,…]}}}` with
  `z_key` an int Z index or `"all"` — the exact schema used by
  `backend/analysis/manual_mask.py`. Follows the **Registration ROI** precedent
  (drawn geometry lives on the node, auto-serialized via `Node.to_dict/from_dict`).
  Polygons are small vector data, so inline storage does not bloat the graph JSON
  the way a dense label volume would.
- **Dedicated editor dialog**, not the shared viewer. The Registration ROI reuses
  the app viewer for a *single* 2D shape; a 3D per-Z mask needs a Z scrubber and a
  per-plane overlay, so we ship a self-contained `Mask3DEditorDialog` embedding the
  reusable `ImageCanvas` (`widgets/image_viewer.py`) + a Z (and T) slider. No new
  drawing primitives — reuse `ImageCanvas.set_draw_mode` / `shape_drawn` and the
  `manual_mask` rasterization/edit helpers.
- **Run is synchronous** (polygon rasterization is cheap) — no worker/`_DVCJob`
  machinery. `_run_mask3d_node` builds the volume(s) and calls `_run_finish_node`
  directly.
- **Backend purity**: all mask maths live in a new pure module
  `backend/analysis/mask3d.py` (no PySide6). The dialog is the only Qt piece.

## Files to add / modify

### Add
- `nd2studios/backend/analysis/mask3d.py` — pure helpers:
  - `rasterize_plane(shapes, H, W) -> (H,W) bool` — union of add-shapes minus
    erase-shapes for one plane (wraps `manual_mask._rasterize`).
  - `build_mask_volume(shapes_by_z, Z, H, W, propagate) -> (Z,H,W) bool` — rasterize
    per-Z + `"all"` planes; `propagate ∈ {"none","copy","interpolate"}`. Interpolate
    uses `scipy.ndimage.distance_transform_edt` signed-distance morph between the
    nearest drawn planes.
  - `threshold_seed_shapes(volume_zhw, threshold=0.0) -> {z:int -> [polygon]}` —
    per-Z Otsu/explicit threshold → largest components → `find_contours` →
    resampled editable polygons.
- `nd2studios/widgets/node_board/mask3d_editor_dialog.py` — `Mask3DEditorDialog`.

## Data flow

```
wired channel ──IMAGE──▶ [3D Mask Drawing] ──ANY──▶ [DVC] (Phase 2: 3-D Object render)
                              │
         node.params["mask_shapes"] {m:{t:{z_key:[shape]}}}   (drawn, serialized)
                              │  Run → mask3d.build_mask_volume
                              ▼
   self._mask3d_by_m[m][t] = (Z,H,W) bool   +   record._mask3d_by_m   (Phase 2 input)
```

## Phase 2 (deferred — not built here)

Consume `record._mask3d_by_m` in the DVC render: `RegularGridInterpolator` upsamples
the DVC `grid_coords`/`displacement_field` onto the mask voxels; `marching_cubes`
extracts the surface colored by the field; interior via a cut-plane (or chosen
backend). New "3D Object" subtab in `DVCPanel`. Backend (matplotlib vs PyVista/VTK)
to be chosen with the user then.
