# V1.46 — Track-persistence rework + terminal Dismiss

## Goal

Fix two related defects in the per-object if-else / Dismiss flow that made
per-track filtering behave unpredictably:

1. **Track persistence** currently exposes *two* thresholds (`min_frames`
   **and** a `comparator`+`value` count of tracks). It is a whole-frame
   population test masquerading as a per-track filter, which is confusing and
   meaningless in the "Each object / Per track" lens. Rework it to a single
   **minimum-or-maximum frame count** test that is genuinely per-track, and
   only offer it in an object-lens if-else.

2. **Dismiss** keys off `track_validation == "rejected"`, a tag no row ever
   carries (Review *drops* rejects, only tags *accepted*). On a Run it silently
   deletes the whole branch; in preview it is a no-op. Redefine Dismiss as a
   **terminal discard**: every object routed to it (and its track) is removed
   from the results table, the tracks/vectors overlays, the segmentation label
   masks, and therefore from every downstream node and viewer tab.

## Approach

### 1. `pipeline_graph/conditions.py`

- Rewrite `_eval_track_persistence` to a per-track min/max test: count each
  track's frame appearances within the evaluated group; `mode="min"` passes when
  every track lasts **≥ frames**, `mode="max"` when every track lasts **≤ frames**.
  In the per-track lens each group is one track, so this reads as "keep this track
  if it persists at least / at most N frames".
- New param schema: `mode` (choice `At least`/`At most`) + `frames` (int). Drop
  `min_frames`, `comparator`, `value`.
- Mark the block `"object_lens_only": True` in `BLOCK_KINDS` and expose a helper
  `is_object_lens_only(kind)` so the builder can gate it.
- Update the `summary` lambda.

### 2. `widgets/node_board/condition_builder_dialog.py`

- Accept a `lens` kwarg. In `_build_add_menu`, skip any block whose spec is
  `object_lens_only` when `lens != LENS_OBJECT`, so track-persistence only
  appears for a per-object if-else.

### 3. `pages/pipelines_page.py`

- `_edit_if_else_condition`: pass `lens=node.params.get("lens")` to the dialog.
- New helper `_discard_objects(drop_rows)`:
  - remove the rows (by `id()`) from `_run_context["rows"]`, `_results_rows`,
    and `_track_overlay_rows`;
  - zero each dropped object's `label_id` out of the primary
    `label_masks[seg_channel][frame]` in `_run_results_by_m[m]` (so the
    segmentation/masks overlay stops painting it);
  - rebuild overlay state from the surviving tracked rows and refresh the
    results table + viewer frame.
- `_run_dismiss`: discard **all** incoming (branch-scoped) rows via the helper;
  drop the dead `"rejected"` logic. Terminal node — output carries nothing.
- Preview `_preview_execute_walk_node` Dismiss branch: same `_discard_objects`
  call so preview and Run agree.

## Key decisions

- **Persistence = frame-appearance count**, not the `track_length` column, so it
  works even if Cell-Tracker metrics never populated `track_length`.
- **Dismiss mutates the committed Run masks in place** for the session. This is
  intentional — a terminal discard must erase the object everywhere, and the
  masks are the source of truth for the segmentation overlay and exports.
- Overlays render from a frozen row snapshot + raw masks, so both must be purged;
  filtering `_results_rows` alone would leave ghosts in the viewer.
