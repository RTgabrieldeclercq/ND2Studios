# V1.0 Macro Recorder

## Goal
Let users record a sequence of meaningful actions (recipe steps, analysis runs, exports) into a named macro, inspect and reorder those actions in a visual block editor, replay the macro on the current file, and optionally apply it to all files in the Batch page.

## Problem / Need
Repetitive workflows (e.g., apply CLAHE → run Histogram Threshold → export movie) must currently be re-executed manually for each new ND2 file. Macros automate this without requiring scripting.

## Key Decisions

1. **Action-level recording, not mouse-event recording.** Hooks are placed at semantic boundaries (Recipe Accept, Analysis Run, Export button) rather than intercepting raw Qt events. This makes actions meaningful, editable, and portable across files.

2. **`.nd2s_macro.json` file format.** One JSON file per macro with `version`, `name`, `created`, and `actions` list. Each action has `action_type`, `label`, `params`, `enabled`, `timestamp`.

3. **Non-modal dialog during recording.** `MacroDialog` is shown via `.show()` so the user can interact with the main window while the recording controls float alongside. The live feed updates via `MainWindow.macro_action_recorded(dict)` Signal.

4. **Three-panel dialog:** Manage → Record → Edit. The Edit panel uses `QListWidget` with `InternalMove` drag-drop for reordering, with custom item widgets for the Edit/Delete buttons per block.

5. **Replay is synchronous + fire-and-forget.** `replay_macro_action()` dispatches each action to the appropriate page method. Async workers (Recipe, Analysis) are started but not awaited — the UI shows progress normally. This is adequate for V1.0.

6. **Batch macro** iterates the Batch page's file list, loading each file and applying all enabled actions. Uses `QCoreApplication.processEvents()` between steps to keep the UI responsive.
