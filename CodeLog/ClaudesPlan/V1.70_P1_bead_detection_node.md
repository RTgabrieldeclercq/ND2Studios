# V1.70 · P1 — Bead Detection node (`special:bead_detect`)

**Depends on:** P0 contracts. **Concurrent with:** P2–P5. **Pure backend + one
page handler.**

## Goal

Produce the 3-D point cloud the whole feature starts from: detect bead centroids in
the wired channel's raw `(Z,H,W)` volume per `(m,t)` and publish them as `(N,3)`
`(z,y,x)` voxel coords + DATA rows carrying **`centroid_z_px`** (the app's first
3-D-centroid writer; the read path already exists).

## Backend — `nd2studios/backend/analysis/bead_detect.py` (Qt-free)

Reuse, do not reinvent, `backend/serialtrack/detection.py::ParticleDetector`
(`detect(img, roi_slices=None) -> (N,ndim)`, `detection.py:214`; LoG/CC centroids via
`ndimage.center_of_mass` + radial-symmetry sub-voxel refine, `:322/:382`).

```python
def detect_beads(volume_zhw, voxel_size_um, params) -> tuple[np.ndarray, list[dict]]:
    """volume_zhw: (Z,H,W) float/uint. Returns ((N,3) (z,y,x) voxel coords, rows)."""
```

- Build a `DetectionConfig` (`serialtrack/config.py:60`) from params (`win_size`,
  `dccd` spacing, `abc` anisotropy from `voxel_size_um`, intensity threshold /
  min-distance, LoG vs CC mode).
- Call `ParticleDetector.detect(volume_zhw)` → `(N,3)` in **detector order `(x,y,z)`**
  (`detection.py:43`). **Transpose to `(z,y,x)`** — per P0 §5 this flip lives ONLY
  here.
- Emit rows per P0 §3 (`bead_id`, `m_position`, `frame`, `centroid_{z,y,x}_px/_um`,
  `granule_id=None`). `_um = coord * (dz|dy|dx)`.
- 2-D fallback: if `Z==1`, `centroid_z_px=0.0`, coords `(N,3)` with z-col zeros
  (keeps the downstream chain uniform; clustering degrades to 2-D).

**Params** (`param_specs_for`, wired in P6): `detect_mode` (choice: `log|components`),
`min_distance_px` (int), `threshold` (float, 0=auto/Otsu), `min_intensity` (float),
`subpixel` (bool, default True), `all_multipoints` (bool).

## Page handler — `pages/pipelines_page.py::_run_bead_detect(node)`

Model on `_run_mask3d_node` (`:6278`): synchronous (detection is fast); read the
wired channel via `_analysis_run_spec(node, names)` / `_analysis_channels_for`; get
the raw `(Z,H,W)` per `(m,t)` from `record._raw_volume.get_volume(c,m,t)`; spacing
via `prep.spacing_from_volume`. Loop `(m,t)` (respect `all_multipoints`), call
`detect_beads`, store `(N,3)` → `record._granule_points_by_m[m][t]` and rows onto the
Results/DATA feed; end with `self._run_finish_node(node.id, port_rows=…)`.
If large `(Z,H,W)` per-M makes it slow, fall back to the async `_DVCJob`-style pattern
(set `self._run_pending`, resume in a `_finish_*`).

## Verification

- Synthetic `(Z,H,W)` with K planted Gaussian blobs at known `(z,y,x)` → detected
  centroids within sub-voxel tolerance; count == K; **axis order asserted `(z,y,x)`**
  (regression against the detector flip).
- Anisotropic voxel size → `_um` scaling correct per axis.
- `Z==1` → 2-D fallback yields `centroid_z_px==0` and N rows.
- Headless import; row schema matches P0 §3 exactly.
