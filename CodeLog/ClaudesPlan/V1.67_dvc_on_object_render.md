# V1.67 — DVC-on-object 3D render (Phase 2 of the DVC-on-object feature)

## Context

**Phase 2** of the user's original request: *"render the DVC spatial map as an
object — draw a 3D mask on each Z plane, then re-render the already-computed DVC
field onto that mask, showing the surface boundaries and the inside of the object,
interpolated up to the mask resolution, as a new subtab in the DVC viewer."*

- **Phase 1 (V1.65, done)** — the **3D Mask Drawing node** (`special:mask3d`) that
  draws the object mask across Z and publishes `record._mask3d_by_m` =
  `{m:{t:(Z,H,W) bool}}`. See `V1.65_mask_drawing_node.md`.
- A **PyVista 3-D viewer** was built separately (`V1.65_pyvista_3d_viewer.md`):
  `widgets/viewer3d/PyVista3DViewer` (off-screen VTK → QLabel), pure-numpy adapters
  in `backend/viz3d/`, and `set_overlay(DVCField | PtvTracks)`. Phase 2 **reuses**
  this viewer rather than building matplotlib 3-D.

## Goal

Interpolate the sparse DVC subset grid onto the Phase-1 object mask and render the
object — **surface boundary + interior**, colored by a chosen DVC scalar — as a new
**"3D Object"** subtab in the DVC viewer (`DVCPanel`).

## Approach (builds on existing infra)

1. **Backend adapter** (`backend/viz3d/overlays.py`, pure numpy + scipy):
   - `MaskedField` dataclass — the object mask (bbox-cropped), a dict of DVC scalar
     volumes interpolated onto its voxels (NaN outside), µm `spacing` + world
     `origin_um`.
   - `dvc_object_field(result, mask, mask_voxel_size_um, *, z_offset_um=0,
     scalar_keys=None, max_box_voxels=4e6)` — reuses `dvc_field()` for the DVC
     scalars, then **linearly interpolates** each onto the mask voxels via
     `scipy.interpolate.RegularGridInterpolator`. Alignment is in **physical µm**:
     DVC nodes at `grid_coords × voxel_size_um` (which folds in any XY downsample),
     mask voxels at `index × mask_voxel_size_um` — so anisotropy and downsampling
     are handled without extra bookkeeping. Cropped to the object bbox and strided
     to `max_box_voxels` to stay renderable; extrapolates past the DVC grid inset.
     2-D DIC / single-Z grids interpolate in-plane and broadcast over Z.

2. **Viewer render** (`widgets/viewer3d/pyvista_viewer.py`):
   - `_add_masked_field_overlay(mf)` — builds a `pv.ImageData` of the cropped block,
     contours the mask to the **boundary surface** colored by the scalar, and shows
     the **interior** per render mode: **Iso** = opaque surface; **Slices** =
     translucent shell + orthogonal interior slices; **Volume/MIP** = translucent
     shell + a volume render of the field inside the object. So "surface boundaries
     + inside" is a single view; the existing mode buttons pick the interior style.
   - **Overlay-only render path** (`_render_overlay_only` / `_rerender_current`) so
     the object renders with no raw image volume loaded (the viewer previously
     required a `VolumeBuildResult`). `set_overlay` / `set_render_mode` /
     `set_master_opacity` route through it.

3. **DVC subtab** (`widgets/dvc_panel.py`):
   - `"3D Object"` added to `_VIEWS`. The matplotlib canvas is wrapped in a
     `QStackedWidget` with a **lazily-built `PyVista3DViewer`**; selecting the view
     swaps to the 3-D viewer in place.
   - A `Colour:` selector (`cmb_obj`) picks which DVC scalar colors the object.
   - `set_data(..., masks, mask_voxel_size)` receives the per-frame mask series +
     raw voxel spacing; `_render_object3d()` builds a `MaskedField` (cached by
     `(incr, t, scalar)`) and feeds `view.set_overlay(mf, scalar)`. No mask on a
     frame → a clear "add a 3D Mask Drawing node upstream" hint.

4. **Page wiring** (`pages/pipelines_page.py`): `_populate_dvc_panel` passes
   `masks = record._mask3d_by_m[m]` and `mask_voxel_size = (z_step, pixel, pixel)`
   (raw) to `DVCPanel.set_data`.

## Key decisions / caveats

- **Reuse the PyVista viewer** (surface + interior) rather than matplotlib 3-D —
  handles millions of triangles and true volume rendering; gated/optional exactly
  like the rest of the 3-D subsystem (placeholder when pyvista is absent).
- **Physical-µm alignment** makes the DVC↔mask mapping robust to XY downsample and
  anisotropic Z. A DVC **`z_start` crop** (rare) needs a `z_offset_um` (default 0,
  correct for the common full-Z run); documented on `dvc_object_field`.
- DVC results are page-local (`self._dvc_series_by_m`) and the mask is on the record
  (`record._mask3d_by_m`); both are read at panel-populate time, no new storage.

## Verification

- Backend: interpolation is **exact** on a synthetic linear field; anisotropic +
  XY-downsample alignment verified (µm-space); NaN masking + 2-D broadcast.
- Widget: **off-screen PyVista render** of the masked object in all four modes
  produces non-uniform images; empty-mask path is graceful.
- Panel: full path — select "3D Object" → build + render, scalar switch rebuilds,
  switch back restores the 2-D canvas, no-mask hint fires.
