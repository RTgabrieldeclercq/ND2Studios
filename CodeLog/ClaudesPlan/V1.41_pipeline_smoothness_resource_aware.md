# V1.41 — Pipeline Smoothness + Resource-Aware Loading

## Goal

Close two integration gaps that already-existing infrastructure leaves open:

1. **Playback bottleneck.** `PreRenderWorker` produces a cache of pre-composited
   frames and `ImageCanvas.set_pixmap_direct()` exists as a hot-path bypass,
   but `VideoPlayer._advance()` never queries the cache — every playback tick
   runs `composite_channels()` on the GUI thread.
2. **No resource pre-flight.** `LoadWorker` calls `materialize_nd2()`
   unconditionally regardless of file size vs. available RAM. `psutil` detection
   exists in `nd2studios/utils/resources.py` but is never consulted before
   allocation. There's also no runtime monitor for memory pressure during a
   session.

## Approach

Phased rollout, **playback first** (highest user-visible ROI), then
diagnostics + adaptive loading.

### Part A — Playback Smoothness

- **A4** — `nd2studios/utils/perf.py` lightweight CSV timing decorator gated
  by `ND2_PERF_LOG=1`. Land first so A1's win is measurable.
- **A1** — `ImageViewer` owns the `Dict[(m,t), np.ndarray]` cache;
  `VideoPlayer` peeks it in `_advance()` and uses `set_pixmap_direct()` on
  hit. Invalidation on LUT change, channel toggle, color change, z-mode,
  dataset reload. Play() pre-rolls `[t, t+30]`.
- **A2** — Idle look-ahead worker fills `[t-2, t+3]` after 200 ms idle into
  the same cache.
- **A3** — Streaming exports: per-frame `tifffile.TiffWriter.write()` loop,
  `imageio.append_data()` generator for movie/GIF. RAM peak drops from
  full-stack to single-frame. Cancellation checks a `threading.Event` between
  frames.
- **A5 (deferred)** — CompositionWorker + GPU LUT in pyqtgraph, only if
  A1–A4 don't hit smoothness target.

### Part B — Resource-Aware Loading + Diagnostics

- **B1** — New `nd2studios/utils/resource_strategy.py`. `LoadStrategy` enum
  (`EAGER_FULL`, `EAGER_REDUCED`, `LAZY_CACHED`), `StrategyDecision` dataclass,
  `choose_strategy(meta, path)` decision matrix using existing
  `resources.detect()`. Hard cap: refuse files where even projected footprint
  exceeds 2× available RAM. `ND2_FAKE_RAM_GB` env var as test seam.
- **B2** — `LoadWorker._load_nd2()` calls `choose_strategy()` between metadata
  read and `materialize_nd2()`. `materialize_nd2(..., decision=...)` branches
  on strategy. New `strategy_chosen` signal so GUI can show the active mode.
- **B3** — `nd2studios/core/memory_monitor.py` singleton. QTimer polls
  `psutil.virtual_memory().percent` every 1500 ms. Signals: `warning` (80%),
  `critical` (90%, drop pre-render cache), `emergency` (95%, modal warning
  + block new ops), `recovered` (back below 70%). Hysteresis: 75/85/90.
  Decision: **no mid-session demotion** — modal-warn only.
- **B4** — Extend `should_dispatch_to_gpu(array)` in
  `nd2studios/compute/gpu/array.py` to proactively check free VRAM via cached
  `memGetInfo()` (200 ms TTL) with a 2.5× safety factor.
- **B5** — Convert minimal Performance dialog into tabbed `QDialog`: GPU,
  Memory, Storage, Diagnostics (Run Benchmark + Save Snapshot).
- **B6** — Windows storage probe (read 16 MB chunk, classify ≥400 MB/s as
  fast); cache result per drive letter in `%APPDATA%/nd2studios/storage_probe.json`.
- **B7** — `nd2studios/utils/user_config.py` for user prefs in
  `%APPDATA%/nd2studios/preferences.json`.
- **B8** — `__main__.py` startup diagnostic sequence after the existing
  `log_gpu_status()` call: log RAM/CPU/storage class, apply safe defaults
  (disable pyramids on <8 GB RAM machines, disable GPU display on <2 GB VRAM
  cards).

## Key Decisions

- **Modal-block over mid-session demotion.** Swapping eager ndarrays for
  `LazyND2Channel` proxies mid-session risks tearing references held by
  in-flight recipe/analysis workers. Surface a clear modal and disable new
  ops until pressure drops instead.
- **WSL2 deferred.** cuCIM would unlock GPU paths for `gaussian` and
  `threshold_otsu`, but only the two tear-detection ops are affected and
  WSL2 setup is heavy. Revisit once we have profiling data justifying it.
- **No new abstractions for the playback cache.** `PreRenderWorker` already
  owns the dict pattern; A1 just adds a reader on the `VideoPlayer` side.
- **Reuse `recommended_cache_budget_bytes()` and `recommended_worker_count()`**
  from `resources.py` rather than inventing parallel budgeting.

## Verification

- Manual: 4-channel 100-frame ND2 at 60 FPS; Task Manager GUI thread <30% CPU,
  no skipped slider positions.
- `ND2_PERF_LOG=1` baseline-vs-after timings in `~/.nd2studios/perf.csv`.
  Target: cache-hit frames complete in <3 ms.
- Streaming-export RAM check: 50-frame movie peak stays flat.
- `ND2_FAKE_RAM_GB=4` on a ~1 GB fixture → `strategy_chosen` emits
  `LAZY_CACHED` and `LoadWorker` returns lazy proxies.
- Pressure test: load app + Chrome + VS Code to push ≥95%, confirm modal
  fires and Run Recipe button disabled until recovered.
- GPU guard: synthesize a too-large array, confirm CPU fallback with single
  warning logged.

## Addendum — Frame-Accurate Progress Contract (QoL initiative)

The smoothness work above removed GUI-thread blocking, but progress bars still
*lied*: most exporters reported `(t+1)/n_t`, ignoring M and Z, so a 4-position,
40-slice file showed 100 % after the first position. Added a single contract so
every long op reports against the real `T·M·Z·C` total.

- **New `nd2studios/utils/progress.py`** — `FrameProgress(total, emit_cb, *,
  lo, hi)` counts frames and emits integer percent only on change (1 %
  thresholds; ≤101 emissions ever). `total_frames_for(meta, …)` derives
  `T·M·Z·C` from `ND2Metadata`.
- Threaded through all exporters and `RecipeWorker` / `ExportWorker` /
  `PreRenderWorker`. `LoadWorker` was already frame-accurate — the backend
  `materialize_nd2` counts `C·M·T` and throttles to 1 %.
- Fixed a residual GUI-thread freeze: the export page's z-reprojection no longer
  calls `.materialize()` on the GUI thread (passes lazy channels to the worker).

Known follow-ups (not addressed here): `results_page.py` and `analysis_page.py`
still have a few `.materialize()` calls on the GUI thread for measurement
assembly — lower-frequency actions, deferred.
