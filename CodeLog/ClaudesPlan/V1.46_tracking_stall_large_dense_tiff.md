# V1.46 — "Tracks not computed" on a large, dense nuclei TIFF

## Report

With `Cell-Tracker_Test_speed_nuclei.tif` (ImageJ TIFF, 10× 4096×4096 uint16,
single channel "H2B-iRFP670"), segmentation produced objects but **no tracks**.

## Investigation (what was ruled out vs. found)

Reproduced each stage on the real file data:

- **Loading — OK.** `read_tiff_meta_fast` reports `n_timepoints=10`, the lazy
  channel is `(10, 4096, 4096)`, and per-frame reads return distinct frames. Not a
  T-vs-Z projection problem.
- **Tracking algorithm — OK.** Threshold-segmented the real frames and ran
  `link_objects` on the genuine centroids: all four methods produce tracks
  (Centroid 6169, CT-Topology 6172, CT-Fingerprint 6191, SerialTrack 5648). Median
  frame-to-frame nearest-neighbour displacement is ~8 px, so the 100 px default is
  ample. The linker is not broken.
- **SerialTrack — very slow.** 400 s for 4 frames of ~22 k objects (numba topology
  PTV); on the full 10-frame stack it would run 15–30 min and look hung. Opt-in
  method, so a secondary concern — flagged, not changed.
- **Channel name — BUG.** Loaded as `"H"` instead of `"H2B-iRFP670"` (see below).
- **Measurement — BUG (the stall).** `compute_measurements` took **~52 s per
  frame** (~520 s / 8–9 min for the stack). Since measurement feeds tracking, the
  pipeline appeared to hang and produced no tracks in any reasonable time.

## Root cause of the stall

Per-channel intensity was extracted with a full-frame boolean scan **per object**:
`pixels = frame_data[mask_frame == prop.label]`, inside `for prop in props:`. That
is O(n_objects × frame_pixels) — on a 4096² frame with ~4.5 k objects, ~7.5×10¹⁰
comparisons per frame.

## Fixes

- `nd2studios/backend/results_engine.py:compute_measurements` — compute per-label
  intensity **once per channel** in a single labelled pass with
  `scipy.ndimage.mean` / `scipy.ndimage.standard_deviation` over the label image,
  then look up each object's stat by label. ~52 s → ~6 s per frame (≈8×),
  bit-identical values (verified against the old scan on 50 random labels + a
  synthetic 2-object frame). Honors the existing `want_mean` / `want_std`
  selective-metrics gating.
- `nd2studios/backend/tiff_loader.py:read_imagej_tiff_metadata` — when ImageJ
  `Labels` is a bare string (single label), wrap it in a one-element list before
  `labels[:n_c]`; coerce to `str`. Previously `"H2B-iRFP670"[:1]` → `"H"`.

## Not changed (flagged)

- SerialTrack scaling on thousands of dense objects is inherently slow. If a user
  needs SerialTrack on dense nuclei, that is a separate optimization (or use the
  Centroid / Cell-Tracker linkers, which run in ~4 s here).
- The remaining ~6 s/frame is regionprops shape props (perimeter / eccentricity /
  solidity) on thousands of objects — acceptable, pre-existing.

## Verification

- 1-frame timing on the real file: 51.9 s → 6.3 s; 0 mismatches in a 50-label
  sample (mean+std).
- Synthetic 2-object frame: mean/std match the per-object scan exactly.
- `py_compile` + import clean for both modules.
- Channel name resolves to `"H2B-iRFP670"` through `read_imagej_tiff_metadata`,
  `read_tiff_meta_fast`, and `_SingleFileTIFFView`.
