# V1.45 — Interpolated Spatial Maps node + migrate Cell-Tracker Spatial Maps to Results

## Goal

Add a second, *generic* spatial-map node to the Pipelines tab, distinct from the
existing CellTracker "Spatial Field Maps" node, and re-home both under the
**Results** node category.

- **New node — "Interpolated Spatial Maps"**: linearly interpolate *any* recorded
  measurement column, sampled at object centroids, onto a grid → one heatmap per
  `(M, frame)`, written as PNG/TIFF. First (optionally) fills each track's value
  **over time** before mapping.
- **Migration**: the CellTracker node ("Spatial Field Maps" → "Cell-Tracker
  Spatial Maps") and the new node both live in `NodeCategory.RESULTS` (green,
  Results tab) instead of `SPECIAL` (orange).

## Why the special-op pattern (not a `results:` op)

Both nodes *produce images and write files* — they are sinks, not the
`BINARY → DATA` measurement ops that `results_engine` backs. The codebase already
models image-producing nodes (`ct_fields`, Export) as **special ops with custom
Run/preview handlers**. So "in the Results category" = override `NodeCategory` to
`RESULTS` while keeping the special-op dispatch + handlers. No new `results:` op
machinery.

## How the new node differs from CellTracker Spatial Maps

| | Cell-Tracker Spatial Maps (`ct_fields`) | Interpolated Spatial Maps (`interp_map`) |
|---|---|---|
| Value | fixed menu (density, velocity, divergence, curl, intensity, fold) | **any** measurement column (chosen from the rows) |
| Time | per-frame; velocity uses prev-frame tracks | per-frame **+ per-track temporal fill** of the value |
| Backend | `backend/celltracker/fields.compute_spatial_fields` | `backend/interp_maps` (generic griddata) |

## Decisions

- `temporal_fill` uses `np.interp` per `(m_position, segmentation_channel,
  track_id)` over the track's observed frames — no extrapolation; untracked rows
  pass through. Needs an upstream Track Objects node to have any effect.
- `compute_interp_map` reuses the `griddata` + `gaussian_filter` pattern from
  `fields.py`; selectable method (`linear` default), falling back to `nearest`
  with fewer than four objects.
- Rendering reuses `celltracker_bridge.render_field_figure` / `draw_field_on_ax`
  (the `field=="speed"` quiver branch never fires for this node; `velocity=None`).
- Preview skips the temporal fill (it needs the whole time series — runs in full
  on Run); it interpolates the current `(M, T)` plane and pops a heatmap on a
  deliberate double-click.
- No `schema_version` bump (op keys unchanged, no model change). Old saved graphs
  get their special nodes' category re-derived from the spec on load
  (`io._normalize_special_categories`).
