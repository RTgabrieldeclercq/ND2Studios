# V1.0 — Results Page: Column Selector Sidebar + Config Dialog

## Goal

Improve the Results tab usability by:
1. Adding a permanent column-selector sidebar so users can choose exactly which measurement columns appear in the table.
2. Replacing alternating row colors with consistent dark styling (white border lines, no alternate shading).
3. Adding a "Configure…" button that opens a guided two-step dialog for selecting the analysis pipeline and result columns.
4. Persisting the column selection in `exp.results_config` alongside the existing pipeline/format settings.

## Approach

### Column selector sidebar (left pane)
- Static groups: Identity, Size, Change (Δ), Position, Shape, Bounding box — with every column key/display label in `_COLUMN_GROUPS`.
- Dynamic Intensity group: populated at compute time via `_sync_intensity_columns()` when `mean_intensity_*` / `std_intensity_*` keys first appear in the measurement rows. The group is hidden until at least one intensity column is added.
- "All" / "None" buttons at the bottom for quick batch toggling.
- Toggling any checkbox immediately re-renders the table via `_on_column_toggled(_checked)`.

### Table filtering
`_update_table(rows)` calls `_get_selected_column_keys(rows)` which iterates over `rows[0].keys()` in order, keeping only keys whose checkbox is checked (or keys with no checkbox, which default to visible). Rows are then filtered to these keys before constructing `_MeasurementsModel`.

### Configure dialog (`_ResultsConfigDialog`)
- A `QDialog` with a `QListWidget` nav sidebar on the left and a `QStackedWidget` on the right.
- Page 0 — Analysis Pipeline: `QComboBox` of `exp.analysis_results.keys()`.
- Page 1 — Result Columns: mirrors the page sidebar with the same grouped checkboxes; two-way bound to `_col_checkboxes` in the page so changes are live.
- Cancel restores all checkbox states via `_original_states` snapshot taken at dialog open.
- Accept propagates the pipeline change to `_combo_pipeline` and triggers a table re-render.

### Table styling
- `setAlternatingRowColors(False)`
- Explicit `setStyleSheet` with `BG_PRIMARY` background, `FG_PRIMARY` text, `BORDER_COLOR` grid lines and bottom borders, `BG_HOVER` for selection. Matches the Dracula theme without alternating tones.

### Save/load
`save_to_experiment` stores `selected_columns` as a list of checked keys alongside `pipeline` and `image_format`. `load_from_experiment` restores checkbox states from `selected_columns` if present; first-open uses `_DEFAULT_COLUMNS`.

## Files modified
- `nd2studios/pages/results_page.py` — flat sidebar, table styling, column filter, save/load
- `nd2studios/widgets/config_wizard.py` — new: ConfigWizard, SavePreviewDialog, helpers
- `nd2studios/core/main_window.py` — remove New button, Save/Load → config ops, add Configure

## Key decisions
- Column filtering happens at the dict level before `_MeasurementsModel` sees the data, so the model stays simple.
- Intensity columns are added dynamically (not statically catalogued) because their keys depend on the channel names in the active experiment.
- `ConfigWizard` keeps its own `_wizard_col_checkboxes` separate from the results-page sidebar and live-syncs on toggle; Cancel restores via `_original_col_states` snapshot — no separate data copy during the wizard session.
- `_cfg_data` on MainWindow tracks the last loaded/saved config as the diff baseline for `SavePreviewDialog`. Configure wizard does not update `_cfg_data` — only Load and Save do, so the diff always reflects file-vs-live state.
- Save with no baseline (`_cfg_data is None`) opens the Configure wizard first (direct path to set-and-save in one action), then skips the diff dialog and goes straight to a file picker.
