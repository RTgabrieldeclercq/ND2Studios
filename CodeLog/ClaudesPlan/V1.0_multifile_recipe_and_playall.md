# Plan: Multi-File Recipe Page + Play All + Symbol Fixes

## Goal
1. Fix invisible button symbols on Windows (Unicode glyphs not in Helvetica Neue).
2. Add "Play All" toolbar control on the Import page to drive T-axis playback
   on all open file panels simultaneously.
3. Expose confirmed import records to downstream pages via
   `ImportPage.get_confirmed_records()` and `MainWindow.get_confirmed_records()`.
4. Refactor RecipePage to show all confirmed files side-by-side with dynamic
   before/after layout orientation (1 file = horizontal; >1 files = vertical
   per column, columns side-by-side).

## Approach

### Symbol fixes
- `image_viewer.py` line 126: `QPushButton("−")` → `QPushButton("-")`
- `multi_axis_viewer.py` line 333: `QPushButton("▶")` → `QPushButton(">")`
- `multi_axis_viewer.py` lines 696/699: `"⏸"` → `"||"`, `"▶"` → `">"`
- Root cause: Unicode codepoints U+2212, U+25B6, U+23F8 are absent from
  "Helvetica Neue" on Windows; Qt renders them as empty glyphs.

### `set_t_playing()` on MultiAxisViewer
New public method at the bottom of `MultiAxisViewer`:
```python
def set_t_playing(self, playing: bool, fps: Optional[float] = None) -> None:
    if fps is not None:
        self._t_fps.setValue(fps)
    if self._t_play.isChecked() != playing:
        self._t_play.setChecked(playing)
```
This drives the existing `_set_axis_playing("t", ...)` via the `toggled` signal.

### Play All toolbar (ImportPage)
- Add `QDoubleSpinBox` (FPS, 0.1–60) and checkable `"> Play All"` button.
- `_on_play_all_toggled(playing)` iterates `self._panels`, calls
  `panel.viewer.set_t_playing(playing, fps=...)` on each.
- Button label toggles to `"|| Stop All"` when active.

### `get_confirmed_records()`
- `ImportPage.get_confirmed_records()`: filters `_panels` by
  `panel.record.status in {imported, preprocessed, analyzed, exported}`.
- `MainWindow.get_confirmed_records()`: delegates to ImportPage; falls back
  to `[exp_manager.active]` if ImportPage not built or returns empty list.

### RecipePage multi-file columns
New `_RecipeColumn` class (before `RecipePage`):
- Holds `record`, `viewer_raw`, `viewer_proc`, `widget`, `worker`.
- Constructor accepts `vertical: bool`:
  - `vertical=False` → `widget = QSplitter(Horizontal)` (Raw | Processed)
  - `vertical=True` → `widget = QSplitter(Vertical)` (Raw / Processed)

`_rebuild_columns()` method on `RecipePage`:
1. Calls `main_window.get_confirmed_records()`.
2. Compares result to `[col.record for col in self._columns]` — skips rebuild
   on exact match.
3. Disconnects crop signals from old primary `viewer_raw`.
4. Removes all children from `self._viewer_area` (new `QSplitter(Horizontal)`
   replacing the old static `right`).
5. Creates one `_RecipeColumn` per confirmed record; adds `.widget` to
   `_viewer_area`.
6. Reconnects crop signals to new primary `viewer_raw`.

`on_activated()` calls `_rebuild_columns()` then
`_populate_viewers_from_records()`.

Trial: primary column uses existing `_run_recipe_on` / `_worker` path;
secondary columns use `_run_recipe_on_secondary` which stores per-column
workers and a flat `_extra_workers` list for bulk cancel.

`viewer_raw` / `viewer_proc` become properties pointing to
`self._columns[0].viewer_raw/proc` for backward compatibility with crop code.

## Key Decisions
1. **`_rebuild_columns` fast path** — comparing record lists means switching
   tabs back and forth is cheap (no widget churn).
2. **Crop only on primary** — crop dialog requires `exp_manager.active`; wiring
   crop to secondary records would need per-column crop dialogs (deferred).
3. **Secondary workers isolated** — `_extra_workers` list allows bulk cancel on
   Reject / Remove Last / Clear without touching the primary `_worker`.
4. **`viewer_raw` / `viewer_proc` remain as properties** — all existing crop
   code and callers outside the class continue to work unchanged.
5. **No fallback placeholder column** — if no confirmed records exist the columns
   list is empty and an `ND2StudiosRecord()` placeholder is inserted so the UI
   always renders something rather than crashing.
