# V1.46 — Pipelines viewer overhaul: all-frame + live overlays, overlay/plot tabs, track displays

## Goal

Bring the CellTracker viewing experience to the Pipelines page:
1. Fix overlays so they show on **every** frame after a Run (not just the Run-start frame).
2. **Live per-frame** overlay + Live-Stats plots as each frame is computed (all analyses).
3. **Tabbed overlays** on the image (Image / Segmentation / Tracks / Vectors), switching
   cheaply over the same cached processed base.
4. **Tabbed plots/data** panel (Measurements + cells/frame, area, track stats).
5. CellTracker **track-colored solid overlay**, **track-stats plots**, and **velocity
   vectors with arrowheads** (per-cell and gridded), with frames building up during tracking.

## Root cause of the original bug
`_composite_*_overlay` only read `self._analysis_screen_results[(m,t)]` (the *previewed*
planes); the full per-M Run result in `_run_results_by_m` was never consulted, so every
non-previewed frame rendered raw.

## What changed (by phase)

**Phase 1 — all-frame overlays.** New `_overlay_result_for(m,t)` prefers previewed planes,
else falls back to `_run_results_by_m[m].label_masks[ch][t]`. `_paint_segmentation_overlay`
indexes by that frame. Run finalization calls `_update_merged_view_mode()` to re-apply the
hook + drop stale overlay tiles so all frames repaint.

**Phase 2 — overlay tabs.** A `QTabBar` above the viewer (Image / Segmentation / Tracks /
Vectors: cells / Vectors: field). One dispatcher `_composite_pipeline_overlay(rgb,t,m)`
draws the active layer; `_on_overlay_tab_changed` re-applies the hook
(`invalidate_post_process_cache` → recompute overlay only; base render cache untouched).
The legacy `_composite_analysis_overlay` / `_composite_results_overlay` now route through it.

**Phase 3 — plot/data tabs.** The bottom of the right split is a `QTabWidget`
(`_data_tabs`) with the Measurements table + lazily-built `MplCanvas` plot tabs
(`_plot_canvas`/`_clear_plot_tabs`): `_update_analysis_plots` (Cells/frame line + Area
histogram) and `_update_track_plots` (Tracks/frame line + Track-length histogram).
`_set_results_view_mode` toggles `_viewer_container` / `_data_tabs`.

**Phase 4 — live per-frame streaming.**
- `compute/progress.py`: `ProgressReporter.frame` signal + `report_frame(m,t,labels)`.
- `compute/runner.py`: `JobRunner.job_frame` signal, connected from each job's reporter
  in `submit` (and disconnected on finalize).
- `backend/analysis/plane_runner.py`: `run_planes_to_labels(..., frame_cb=None)` calls
  `frame_cb(t, labels)` per finished frame; `make_frame_cb(params)` reads reserved
  `params["_frame_cb"]`. All five analysis pipelines pass `frame_cb=make_frame_cb(params)`.
- `compute/pipeline_jobs.py`: `PipelineCommitJob.run` injects
  `params["_frame_cb"]=lambda t,lbl: progress.report_frame(self.m_index,t,lbl)`.
- `pipelines_page`: `job_frame → _on_run_frame` stashes the frame's labels in `_live_seg`,
  navigates the viewer to `(m,t)` (`MultiAxisViewer.set_current_frame`, new), and extends
  the live Cells/frame plot. `_paint_segmentation_overlay` paints `_live_seg` first (red
  outline) until the committed result takes over (`_live_seg` cleared at run end).

**Phase 5 — tracks + vectors.** New Qt-free `backend/track_overlays.py`:
`generate_track_colormap` (HSV spread, from CellTracker), `make_colored_overlay` (solid
track-colored fill, from CellTracker), `draw_cell_vectors` / `draw_grid_velocity`
(arrowheads via `cv2.arrowedLine`). `_run_track_objects` builds the colormap + long-track
set (`len >= max(10, T//10)`), switches to the Tracks tab, and runs a `QTimer`
play-through (`_start_track_playthrough`) so the colored cells build up frame-by-frame,
ending on frame 0. `_paint_tracks_overlay` / `_paint_vectors_overlay` render from the
committed masks + tracked rows.

## Key decisions
- Overlays computed **lazily per (m,t)** from already-stored masks/rows — no extra
  full-stack RGB buffers (low RAM); tab switches recompute only the overlay layer.
- Per-frame `labels` cross the thread boundary by reference via the queued Qt signal;
  `plane_runner` emits a fresh array per frame (no mutation race).
- Tracking is computed globally (fast) then **streamed as a per-frame colored reveal**
  (visual "builds up as we go"; identical end state to incremental linking).
- No schema bump; one pre-existing unused import (`Optional` in `pipeline_jobs.py`) left as-is.
