# V1.50 — Track displacement / motility: measure basis + per-frame outlier rejection

## Context

The if-else **"Track displacement / motility"** condition block
(`pipeline_graph/conditions.py::_eval_track_displacement`) currently measures a
single quantity per track — the **net** (first→last) displacement — aggregates it
across tracks (`mean/median/min/max`) and compares to a user threshold. In an
object-lens if-else each track routes to the TRUE/FALSE branch **as a whole**
(`partition_rows`).

Two capabilities are missing:

1. **Measure basis.** Net displacement hides fast-but-returning motion and
   erratic tracks. The user wants to also measure:
   - the **accumulation** over the whole track (cumulative path length = sum of
     every frame-to-frame step), and
   - the **single-frame instance** (a per-step / frame-to-frame displacement).

2. **Outlier-frame rejection.** With a per-frame measure, "if an object has one
   frame-to-frame step higher than the threshold, this object is flagged" — today
   that can only reject the *whole* track. The user wants an option to reject
   **only that outlier frame** and keep the rest of the track (a mis-linked jump
   is a data error, not a reason to discard the cell).

## Approach

All changes are in `pipeline_graph/conditions.py` (backend, Qt-free). No page or
dialog changes are required: both `partition_rows` call sites in
`pages/pipelines_page.py` already route the `(keep, drop)` it returns, and the
condition builder dialog renders whatever params the block declares.

### New block params (`BLOCK_KINDS["track_displacement"]`)

- `basis` — `Measure`: `["Net (first→last)", "Cumulative path", "Per-frame step"]`
  (default `Net (first→last)` ⇒ back-compatible).
- `outlier` — `Per-frame exceed`: `["Reject object", "Reject frame only"]`
  (default `Reject object`). Only meaningful when `basis = Per-frame step`.

Existing `aggregate` / `comparator` / `value` are kept. Saved conditions with no
`basis`/`outlier` default to the old behavior.

### Per-track value by basis (`_track_metric_value`)

For a track's frame-ordered points:
- **Net** → distance(first, last) (unchanged).
- **Cumulative** → Σ consecutive step distances.
- **Per-frame** → **max** consecutive step distance. Using the max makes
  `max_step > value` equivalent to "any step > value", so the existing
  aggregate/comparator machinery expresses the user's "one step exceeds" rule.

The per-track values feed the existing `_aggregate(..., mean/median/min/max)` →
`_cmp` path, so both the whole-frame lens and object lens (one track per group)
keep working.

### Outlier-frame scrubbing (`scrub_outlier_frames`)

New pure helper called at the top of `partition_rows`:

- For every `track_displacement` block with `basis = Per-frame step` and
  `outlier = Reject frame only`, find each over-threshold step (step magnitude
  satisfies the block comparator vs `value`) and mark its **"to"-frame row**
  (the displaced/anomalous position) for removal.
- Return `rows` with those rows removed. They land in **neither** branch — i.e.
  the outlier frame is dropped while the track survives and routes normally on its
  remaining (now in-range) frames.

Notes / limits (documented in code):
- Frame-only rejection is inherently **object-lens**; in a whole-frame if-else
  (`evaluate_condition`, which returns one bool for the frame and cannot drop
  rows) it degrades to `Reject object` behavior.
- Scrubbing is single-pass — consecutive bad frames are each removed by their own
  over-threshold step; no re-linking is attempted (the tracker owns linking).
- Physical units: reuses the existing `centroid_*_um` with `centroid_*_px`
  fallback, so `Value (um)` matches the existing block.

## Key decisions

- Offer **both** Net and Cumulative (rather than redefining "net" as
  "accumulation") so the existing meaning is preserved and the user's
  "accumulation" is available as a distinct choice.
- Per-frame per-track reduction = **max step**, so the existing comparator/value
  UI reads naturally as the "one step exceeds" rule.
- Outlier scrubbing lives in `partition_rows` (not the pages) so it is applied
  uniformly at both call sites with zero page changes.
