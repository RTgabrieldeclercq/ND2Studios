# V1.54 — Multipoint Stitching Pipeline (regime-aware rebuild)

## Goal

Replace the current multipoint (M) stitching **method** with the regime-aware
pipeline described in the *Build Spec: Multipoint TIFF Image Stitching Pipeline*
(research pass 2026-07-07). The one idea that drives the design:

> "Stitching" is two different problems. **Overlapping** tiles can be
> *registered* from image content (phase correlation → global optimization).
> **Zero-overlap** tiles share no pixels, so registration is mathematically
> impossible — they must be placed from **stage coordinates** only. The M data
> mixes both, so the pipeline must inspect each dataset, decide the regime, and
> route accordingly. Never let zero-overlap data reach a registrar (it will lock
> onto a spurious noise peak).

The **only** thing kept from the old stitcher is *how metadata is read to orient
the M frames to one another*: the `stage_xy_um` / `pixel_size_um` reads in
`nd2_loader.read_nd2_metadata_extended` (`f.experiment` XYPosLoop
`stagePositionUm` → fallback `frame_metadata`), and the lab's Nikon
sign/flip convention (negate stage XY; `x = (sx-min)/px`, `y = (max-sy)/px`).
Everything else — the overwrite-only `stitch_one_frame`, the ImageJ-hyperstack
`export_stitched_tiff`, the serpentine/grid-fallback heuristics — is replaced.

## Decisions (confirmed with the user)

1. **Output = pyramidal, tiled, BigTIFF OME-TIFF only.** Preserve dtype
   (`uint16`), channels, and physical pixel size. The existing "reload stitched
   TIFF" path is taught to read OME-TIFF so round-trips still work.
2. **Install the real engines.** `m2stitch 0.7.2` and `ashlar 1.20.0` are
   installed into the Python 3.12 env; `basicpy` is attempted.
   - **m2stitch** — primary **overlap** engine for regular grids. Pure-python,
     feeds a numpy stack + rows/cols + `position_initial_guess` seeded from stage
     coords; returns absolute `x_pos`/`y_pos`. Supports missing tiles.
   - **ashlar** — installed, but `ashlar.reg` hard-imports `jnius` (BioFormats)
     at module load and needs a **JDK / `JAVA_HOME`**, which this box lacks. It is
     wired as a *gated* engine that raises a friendly "ashlar needs a JDK"
     message; `auto` never selects it. Its multi-channel + OME-writer role is
     covered by our own compositor + OME writer + the register-once-apply-to-all
     rule, so nothing is lost functionally.
   - **built-in phase-correlation** — `skimage.registration.phase_cross_correlation`
     with Hann window + band-pass pre-filter, pairwise on adjacency, NCC
     confidence + rejection, spanning-tree global optimization seeded/bounded by
     stage coords. Always available; the fallback for non-grid overlap or when a
     library engine is unavailable.
   - **basicpy (BaSiC)** illumination correction if it installs; otherwise a
     built-in smoothed-flatfield fallback, gated + off by default.
3. **Regime = auto-detect.** Infer overlap fraction from stage coords + pixel
   size + tile size; route to registration when `overlap_frac > zero_overlap_tol`
   (default 0.01), else coordinate-only placement. User-overridable in the dialog.

## Approach — new backend package `nd2studios/backend/stitch/`

Backend-pure (no PySide6). Callable from the worker and headless.

```
nd2studios/backend/stitch/
  __init__.py        # public exports: StitchConfig, run_stitch, StitchResult,
                     #                 compute_tile_layout, StitchLayout
  config.py          # StitchConfig dataclass (all Section-10 knobs) + to/from dict
  dataset.py         # Tile, Dataset dataclasses; build_dataset(volume, stage_xy_um,
                     #   meta, config); grid + overlap + regime inference; the KEPT
                     #   orientation math (negate/flip stage XY → oriented µm)
  regime.py          # decide_regime(dataset, config) -> "overlap" | "zero_overlap"
  positions.py       # coordinate_positions(dataset) -> {m:(y,x)} + canvas bbox
                     #   (the kept physical layout); StitchLayout + compute_tile_layout
                     #   compatibility shim for the preview widgets & scripts
  register.py        # built-in phase-correlation refinement + spanning-tree global opt
  engines.py         # compute_positions(): auto | coordinate | phase_correlation |
                     #   m2stitch | ashlar (gated). Returns (positions, confidences, used)
  compositor.py      # composite(tiles, positions, canvas, dtype, blend, feather_px)
                     #   feather | average | max | none; dtype-preserving; gap fill
  illumination.py    # BaSiC (gated) or built-in flatfield; apply per channel
  writer.py          # write_ome_tiff(): pyramidal, tiled, bigtiff; TZCYX; PhysicalSize;
                     #   channel names; disk-incremental for large mosaics
  qc.py              # write_qc(): JSON + matplotlib PNG (positions, confidences, regime)
  pipeline.py        # run_stitch(volume, stage_xy_um, meta, m_indices, channel_indices,
                     #   config, out_path, progress_cb) -> StitchResult
```

### Pipeline (mental model)

```
build_dataset (KEEP metadata orientation)
  → decide_regime (overlap vs zero_overlap)
  → [overlap]      seed positions from coords → REGISTER (m2stitch/phase-corr)
  → [zero_overlap] coordinate_positions ONLY (no registration)
  → (optional) illumination correction
  → composite each (T,Z,C) frame with blending, reusing ONE position set
  → write pyramidal OME-TIFF (preserve dtype/channels/pixel size)
  → write QC report (regime, engine, positions, confidences)
```

Register **once** on `align_channel` and reuse positions for every C/Z/T
(spec §7). `per_timepoint_registration` re-registers per T when the stage drifts.

## Key decisions / notes

- **Register-once-apply-to-all** avoids per-channel misregistration.
- **m2stitch for grids only.** Scattered multipoints (no inferable grid) →
  built-in phase-correlation (if overlap) or coordinate placement.
- **Seed + bound.** Stage coords initialize the optimizer and cap `max_shift`, so
  a registrar can't wander; on low confidence for all edges → fall back to
  coordinates and flag it in QC.
- **dtype preservation** — accumulate blends in float32, cast back to source dtype.
- **Zero-overlap correctness** — never registered; gaps between tiles render as
  fill (0) and that is *correct*, not a bug.

## Testing (spec §12)

Synthetic ground truth in `tests/test_stitch_pipeline.py`:
1. Cut a known image into an overlapping grid with known coords + jitter → assert
   recovered positions within ~1–2 px (m2stitch + phase-corr paths).
2. Zero-overlap version → assert regime == zero_overlap AND coordinate placement
   is exact.
3. Regime selection at 0 % / 1 % / 10 % overlap routes correctly.
4. Orientation: flipped/swapped-axis fixtures preserve the kept Nikon convention.
5. OME-TIFF round-trip: reopen, assert shape/dtype/channels/pixel size; reload
   through `tiff_loader`.
6. Missing-tile grid; single-tile degenerate; multi-channel reuse-positions;
   dtype (uint16 in → uint16 out).

Then `/verify` end-to-end through `run_stitch` on a synthetic volume stub.

## Outcome (2026-07-07)

Shipped as planned. `tests/test_stitch_pipeline.py` has **17 passing tests**; the
full repo suite (**192**) passes on the (now) pandas-2.3.3 env.

- **Engines as built here:** m2stitch (grid) + built-in phase-correlation are the
  `auto` overlap engines (no Java). **ashlar is now fully wired** via an
  in-memory reader (`ashlar_engine.py`) — its `EdgeAligner` registration is pure
  Python, so the JVM never starts; we install **`jdk4py`** (packaged OpenJDK, pip)
  and auto-set `JAVA_HOME` so ashlar's `import jnius` succeeds. Verified: ashlar
  recovers jittered positions to ~1.3 px. `auto` still never selects ashlar
  (keeps the default Java-free); ashlar is explicitly selectable in the dialog.
  basicpy remains not importable (hyperactive/gradient_free_optimizers API
  drift) — BaSiC gated, `builtin` flat-field is the default illumination method.
- **Adversarial review (7 dimensions) → fixes applied:**
  - Single-row/strip acquisitions: sub-tile stage jitter on the constant axis no
    longer fractures into bogus rows / spurious ~99% overlap — `_cluster_axis`
    gained a `min_tolerance` floor (5% of tile) and overlap is capped at 0.95.
  - `register.py`: dropped the per-tile hard clip to `seed ± max_shift` (it would
    wrongly pin far tiles in large mosaics); drift is bounded by per-pair
    rejection + the Tikhonov seed anchor in the global solve.
  - `compositor.py`: negative tile offsets are clamped by cropping the source
    (no wrong-end numpy placement).
  - `writer.py`: BigTIFF decision now includes pyramid SubIFD bytes; resolution
    tag emitted so non-ome-types readers recover pixel size.
  - `pipeline.py`: per-timepoint registration uses a shared reference origin;
    memmap temp file is closed + GC'd before removal (Windows handle release).
  - `illumination.py`: supplied flat/dark shape mismatch now errors instead of
    silently skipping correction.
  - `stitch_dialog.py`: Export disabled while a worker runs (no concurrent writes).
