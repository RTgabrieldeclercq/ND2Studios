# V1.49 — Loop / Iteration connector (back-edge)

## Context

The Pipelines node graph is today a strict DAG: wires flow top→bottom, cycles are
rejected (`would_create_cycle`), and a Run walks each node exactly once
(`GraphRunner`). There is no way to re-run a portion of a pipeline while sweeping
a parameter or iterating toward a target.

Microscopy analysis frequently needs exactly that: e.g. run StarDist across
`Scale` 0.3→0.9 (0.2 steps), possibly crossed with several probability
thresholds, merge the detections, and drop duplicates by overlap — then send the
combined result down the rest of the pipeline. Other stop criteria: a fixed loop
count, "until ≥ N non-duplicate objects", or "tracking ratio ≥ 90% over ≥ 20
continuous frames of 33".

This plan adds a **loop connector**: a visually distinct wire drawn to the *left*
of the standard bridge, exiting a node's **bottom** and returning to the **top**
of the same node or an upstream node. It defines a *loop region* (the body between
entry and exit), an *iteration plan* (parameter sweep / count / until-condition),
and a *combine rule* for merging per-iteration results. Configuration lives **on
the loop wire** (double-click).

Design decisions confirmed with the user:
- Config lives on the **loop wire** (double-click → Loop Settings dialog).
- Combine rules: **Union+dedup by overlap, Best iteration, Last iteration, Keep
  all (tagged)** — all four supported.
- Duplicate detection: **mask IoU, centroid-distance fallback**, threshold set by
  the user.
- Multipoint scope: a **per-loop choice** — iterate within the current M, or
  across all multipoints.

## Approach overview

A loop edge is a new *kind* of `Edge` that is **invisible to every existing DAG
codepath** (recipe linearization, channel propagation, topological order,
`GraphRunner`, cycle check). All structural traversal is filtered to structural
edges only, so nothing about today's Run changes when no loop exists. The loop
edge carries its own config in `Edge.params`. A new pure `loop.py` module computes
the loop region and the iteration plan and does the dedup/aggregation; the Qt page
drives the per-iteration sub-runs by reusing the existing node dispatch, mirroring
the per-M queue pattern already in `_advance_run_m`.

## 1. Model layer — `nd2studios/pipeline_graph/model.py`

- `Edge` gains two fields (both serialized, back-compat defaults):
  - `kind: str = "structural"` — `"structural"` | `"loop"`.
  - `params: Dict[str, Any] = field(default_factory=dict)` — loop config (empty
    for structural edges).
  Update `Edge.to_dict`/`from_dict` accordingly (default `kind="structural"`,
  `params={}` when absent so old graphs load unchanged).
- Constant `LOOP_KIND = "loop"` and helper `is_loop_edge(edge) -> bool`.
- `GraphSlice` query helpers get a structural-only variant used by all traversal:
  add `structural_edges()` and make `incoming`/`outgoing` callers that must ignore
  loops use it. Concretely add `structural_incoming(node_id)` /
  `structural_outgoing(node_id)` (filter `e.kind != LOOP_KIND`) and `loop_edges()`.
- `would_create_cycle` gets a `kind`-aware caller: connection validation for a
  **loop** edge must *skip* the cycle check (loops are intentionally cyclic). Add
  `can_connect_loop(src, dst) -> bool` — src must be an output on the node's
  **bottom**, dst an input on the **top**; both structural (IMAGE/BINARY/DATA/ANY)
  ports, not CHANNEL. (A loop wire reuses the same structural ports; it does not
  add new ports — see UI section for the left-side anchor.)

## 2. Traversal isolation — `nd2studios/pipeline_graph/executor.py`

Every function that walks structural edges must ignore loop edges:
- `predecessor`, `recipe_for_node`, `structural_chain` — use
  `structural_incoming`/`edge_into_port` filtered to structural (the loop back-edge
  into a node's top input must not be treated as its recipe predecessor).
- `channel_sets`, `edge_channels`, `topological_order` — iterate
  `structural_edges()` only.
- `GraphRunner._active_incoming`, `reachable_nodes`, `complete`, `outgoing` walks
  — filter to structural edges so the back-edge neither adds indegree nor makes
  the entry node wait on its own descendant.

New pure loop helpers (Qt-free, unit-testable) — put in a new module
`nd2studios/pipeline_graph/loop.py` and re-export from `__init__.py`:
- `loop_region(sl, loop_edge) -> LoopRegion` — `entry` = `loop_edge.dst_node`,
  `exit` = `loop_edge.src_node`; body = forward-structural-reachable(entry) ∩
  backward-structural-reachable(exit), inclusive. Returns entry/exit/body node ids
  and the ordered body sub-recipe.
- `iteration_plan(config, body_nodes) -> List[Dict[node_id, Dict[param, value]]]`
  — expands the sweep spec into concrete per-iteration param assignments:
  - each swept axis = `{node_id, param, values}` where `values` is an explicit
    list or `start/stop/step` expanded; multiple axes → **Cartesian product**
    (grid), matching "3 prob thresholds × Scale sweep". A `combine="zip"` option
    is available for paired sweeps.
  - `mode="count"` → N empty assignments (repeat unchanged); `mode="until"` →
    a generator capped by `max_iterations`.
- `deduplicate_objects(rows, masks, *, metric, threshold) -> (kept_rows, kept_masks)`
  — mask-IoU dedup with centroid-distance fallback (reuses the greedy matching
  idea from `object_tracker.link_objects`). Operates per frame.
- `combine_iterations(results, rule, ...)` — implements the four rules
  (`union_dedup`, `best`, `last`, `keep_all`). `best` ranks by a chosen metric
  (object count / tracking ratio).
- `tracking_ratio(rows, n_frames) -> (ratio, max_continuous_run)` — fraction of
  frames covered by tracks and the longest continuous run of "well-tracked"
  frames, feeding both the `best` ranking and the new stop-condition block.

## 3. Stop conditions — reuse the Condition DSL — `nd2studios/pipeline_graph/conditions.py`

The "until" stop condition reuses `Condition` / `evaluate_condition` over the
current-iteration (or accumulated) rows. Add two block kinds so the user's
examples are expressible:
- `nondup_object_count` (Object population family) — object count **after dedup**
  ≥/≤ value. (Dedup applied by the loop before evaluation.)
- `tracking_coverage` (Timelapse/tracking family) — "ratio ≥ X% for ≥ K
  continuous frames out of N", backed by `tracking_ratio`. Params: `ratio`,
  `min_continuous_frames`.
The loop's `max_iterations` is a hard cap always present (safety), independent of
the condition.

## 4. Node board UI — `nd2studios/widgets/node_board/`

- **`edge_item.py`** — loop routing + style. When `kind == "loop"`, route the wire
  out of the source (bottom) port, **left** around the node column (x offset a
  fixed gutter left of `x=0`, left of the accent lip and rainbow column), up, and
  into the destination (top) input — a distinct C-shaped/orthogonal path on the
  left, never through the top→bottom mid-Y elbow used by structural edges. Style:
  distinct color (e.g. amber) + a subtle double/looped cap so it reads as a loop;
  reuse the existing dashed/thin channel-edge precedent for the pen setup. Widen
  `boundingRect` to include the left gutter. Add an arrowhead at the top entry to
  show flow direction.
- **`node_scene.py`** —
  - New "loop wire" drag mode: a toolbar toggle (see page) puts the scene in
    `_loop_mode`; a drag from a bottom output to a top input (same node or
    upstream) creates a loop edge. Alternatively, detect intent by target: a wire
    from an output to an input that `would_create_cycle` **and** loop-mode is armed
    → loop edge.
  - Relax `_try_connect`: allow `out_node.id == in_node.id` (self-loop) and skip
    `would_create_cycle` **only** when creating a loop edge; still enforce
    `can_connect_loop` (structural ports, output→input).
  - Loop edges are **not** subject to one-wire-per-input replacement of structural
    wires (a node's top input can hold both its structural feed and a loop
    back-edge — store the loop separately; validation ensures at most one loop edge
    per (entry,exit) pair).
  - `_add_edge_item` passes `kind`/params so `EdgeItem` styles itself; double-click
    on a loop `EdgeItem` opens the Loop Settings dialog (new signal
    `loop_edge_edit_requested`).
  - Scissors `_perform_cut` already removes any `EdgeItem` under the stroke —
    works for loop edges unchanged.
- **`node_item.py`** — no new ports; the loop wire anchors on the existing bottom
  output and top input. Confirm `boundingRect`/left gutter doesn't clip the wire
  (the routing lives in `EdgeItem`).

## 5. Loop Settings dialog — `nd2studios/widgets/node_board/loop_dialog.py` (new)

Opened by double-clicking a loop wire. Sections:
- **Iteration**: mode = Parameter sweep | Fixed count | Until condition. For
  sweep, an editable table of axes — pick a body node + one of its numeric
  `ParamSpec`s (from `param_specs_for(op_key)`), then start/stop/step or an
  explicit value list; combine = grid (default) or zip. Live preview of the total
  iteration count.
- **Stop**: max iterations (always); for "Until", a `ConditionBuilderDialog`
  (reused) editing a `Condition` — includes the new `nondup_object_count` /
  `tracking_coverage` blocks.
- **Combine results**: Union+dedup / Best / Last / Keep-all. For dedup: metric
  (mask IoU | centroid distance) + threshold. For Best: ranking metric.
- **Multipoint**: Current M | All multipoints.
Writes back into `loop_edge.params` (a versioned dict). All widgets follow the
existing `ParamPopup`/`ConditionBuilderDialog` styling.

## 6. Run execution — `nd2studios/pages/pipelines_page.py`

Reuse the async, re-entrant pump pattern already used for per-M
(`_advance_run_m`) and pause/resume.

- `_run_pump` / `_run_execute_node`: when the next-ready node is the **entry** of a
  loop region (detected via `loop_edges` on the slice), enter **loop mode** instead
  of running it once:
  1. Build the region (`loop_region`) and iteration plan (`iteration_plan`).
  2. Maintain `self._loop_ctx` (queue of iterations, accumulator of per-iteration
     outputs, the loop config) — analogous to `_run_analysis_ctx`/`_run_m_queue`.
  3. For each iteration: apply the iteration's param overrides onto the body nodes
     (temporarily, restoring originals after the loop), then run the **body
     subgraph once**. Implement the body sub-run by constructing a scoped
     `GraphRunner` over a temporary `GraphSlice` containing only body nodes +
     their structural edges, started at `entry`, and driving it with the existing
     `_run_execute_node` dispatch. Save/restore the outer run scratch
     (`_runner_obj`, `_run_context`, `_run_port_rows`, …) around the sub-run so
     node handlers are reused verbatim.
  4. After each iteration collect the exit node's rows + label masks into the
     accumulator; if `mode="until"`, evaluate the stop `Condition` (with dedup
     applied for `nondup_object_count`) and break when satisfied or the cap is hit.
  5. When the plan is exhausted / stopped: `combine_iterations(...)` →
     aggregated rows + masks; publish them as the exit node's output via
     `_run_finish_node(exit_id, port_rows=…)`, restore original body params, and
     let the outer `GraphRunner` continue downstream from the exit node.
- **Multipoint**: when the loop config says "All multipoints", wrap the whole loop
  in the existing per-M queue (loop runs once per M, results tagged by
  `m_position`); "Current M" runs the loop for the viewed M only.
- Progress/state: paint body nodes as "current" during their iteration; show an
  "iteration i/N" status (reuse the existing run status label / progress bar).
- Guard rails: validate the loop region on Run start (entry reachable from Input;
  exit reachable from entry; every swept `node_id` is inside the body; a numeric
  `ParamSpec` exists). Surface errors like the existing `_on_run` validation.
