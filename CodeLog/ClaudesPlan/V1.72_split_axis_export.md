# V1.72 — Split-by-axis export from the Import tab

## Goal

Give the Import tab (Page 1) a prominent **"Export by axis…"** button that writes the
current (cropped) dataset out as **multiple files split along the M / T / Z / C axes**,
with a per-axis *Split / Keep* choice:

- **Split** an axis → one output file per index on that axis.
- **Keep** an axis → all indices of that axis are bundled inside each file.

This covers every grouping the user asked for:

| Request                              | M     | T    | Z    | Files                     |
|--------------------------------------|-------|------|------|---------------------------|
| "TIFFs per Z"                        | keep* | keep | split| one per Z (all T)         |
| "per M"                              | split | keep | keep | one per M (all T, Z)      |
| "per T"                              | keep* | split| keep | one per T                 |
| "all T for each M"                   | split | keep | —    | one per M (all T)         |
| "all T for each Z"                   | split*| keep | split| one per (M,Z) with all T  |
| "all T and Z for each M"             | split | keep | keep | one per M (all T, Z)      |

(*The user never asked to bundle multiple stage positions into one file. Since an
ImageJ hyperstack has no M axis, when **M is *Keep* with n_m > 1** we flatten the M
positions into the front of the T (frames) axis, M-major — lossless, and the dialog's
summary states the exact page count. In the common case M is *Split*.)

Output formats are **independent checkboxes** so the same grouping/crop can be written
as two+ formats in one run: **TIFF hyperstack**, **PNG image sequence**, **Movie (MP4/GIF)**.
Channels (C) are also splittable.

## Approach

The volume API (`LazyND2Volume` / `StreamingDataset` / `MaterializedDataset` /
`Lazy*TIFFVolume`) already exposes `get_frame(c, m, t, z, z_mode)`, `channel_names`,
`n_multipoints`, `n_timepoints`, `n_zslices`, `height`, `width`. The TIFF hyperstack
writer (`export_tiff_hyperstack`), the RGB compositor (`_composite_frame`), overlay
painter (`_draw_overlays`) and `export_movie` are all reusable as-is. So the feature is:

1. A **backend engine** that iterates the axis-group grid and, per group, realizes the
   requested format(s) by reusing the existing writers.
2. A **dialog** that presents the Split/Keep matrix + format checkboxes + a live
   file-count summary.
3. A **worker mode** + **panel button** to run it off the GUI thread via the existing
   `ExportWorker` / `_run_export` plumbing.

### Axis-group math (shared by the engine and the live summary)

```
_axis_groups(n, split) -> List[List[int]]
    split  -> [[0], [1], ..., [n-1]]      # one group per index
    keep   -> [[0, 1, ..., n-1]]          # one group, all indices
```

`n_z` collapses to 1 (and Z-split is disabled in the dialog) whenever a projection is
active (`z_mode != "none"`) or the file has a single Z slice. The output-file grid is
the cartesian product of the four axes' groups; each element yields `(m_list, t_list,
z_list, c_list)`.

Per group, per requested format:
- **TIFF** — assemble `{name: (T', Z', H, W)}` (T' = len(m_list)·len(t_list), M-major;
  Z' = len(z_list)) and hand it to `export_tiff_hyperstack` (streams the write; honors
  bit depth + pixel size). Memory per group ≈ one position's stack — matches the
  existing `tiff_zstack` path.
- **PNG** — one composited RGB PNG per (m, t, z) in the group via `_composite_frame`
  (+ `_draw_overlays`), named with every varying index.
- **Movie** — flatten (m_list × t_list) as the timeline; kept Z with >1 planes is
  max-projected for the 2-D movie frame; one clip per group via `export_movie`.

XY crop (`self._xy_crop`) is applied at read time; the T/M/Z tile-strip crop is already
baked into `record._raw_volume`, so the volume's axis sizes already reflect it. Enabled
channels + per-channel color/LUT come from the live viewer, so output matches the view.

## Key decisions

1. **Reuse existing writers** (`export_tiff_hyperstack`, `export_movie`,
   `_composite_frame`/`_draw_overlays`) rather than a new pixel path, so split output is
   byte-compatible with the single-view exports.
2. **Materialize per group** (not the whole volume). Groups are bounded (usually per M),
   matching the existing `tiff_zstack` memory profile.
3. **M-keep-with-multi-M flattens into the T/frames axis** (documented in the summary),
   because ImageJ hyperstacks have no M dimension. Split M is the default and the common
   path.
4. **Coarse progress = completed (group × format) units** with a descriptive status line
   ("Group 3/12 · M03 · TIFF…"); simple and predictable for the background worker.
5. Backend stays PySide6-free; the dialog lives in `widgets/`.

## Addendum — Contrast / LUT option

Added a **Contrast / LUT** control to the dialog (`spec.lut_mode`):

- **Auto-scale each channel** — 0.5–99.5 percentile stretch per channel.
- **Keep manual** — the viewer's per-channel `(lo, hi, gamma)` window.
- **Full range** — map `0 … dtype-max` with no stretch.

`_effective_contrast(lut_mode, names, viewer_lut, dtype_max)` resolves the mode
into `(composite_lut, tiff_bounds)`: the composite LUT drives PNG + movie via
`_composite_frame`; `tiff_bounds` drives the TIFF rescale. To honor manual /
full-range contrast in TIFFs, `export_tiff_hyperstack` gained an optional
`lut_bounds={name:(lo,hi)}` arg used in place of the auto percentile stretch for
uint8/uint16 (a `passthrough` TIFF always keeps raw quantitative data, so the LUT
is a no-op there — surfaced as a note in the dialog).
