# V1.45 — "Review Objects" node: two review modes

## Goal

Rename the **Review Object** special node to **Review Objects** and give it a
`mode` choice with two ways to review:

1. **Single objects** — the existing cropped-panel accept/reject dialog
   (`TrackValidationDialog`), **generalized** so objects that aren't tracked are
   also reviewable. When a Track Objects node feeds Review Objects, each *track*
   is one unit (as today); when nothing is tracked (no Track Objects upstream),
   each *object* (one label on one frame) is its own unit.
2. **Whole frame** — a single full-frame viewer that draws every object's
   **label id in white at its centroid**, steps across **T** (or M/Z if there is
   no T), with an **M selector** for multi-position files. The user can
   **click an object to toggle reject** *and* **Accept/Reject the whole frame**
   at once. (User-confirmed interaction.)

## Approach

### Registry — `pipeline_graph/registry_adapter.py`
- `SPECIAL_REVIEW_OP_KEY` title `Review Object` → `Review Objects`.
- `param_specs_for(SPECIAL_REVIEW_OP_KEY)` → one `mode` choice
  (`"Single objects"` | `"Whole frame"`, default single).

### Migration — `pipeline_graph/io.py`
- Extend `_migrate_v2_to_v3` to retitle old `Review Object` nodes to
  `Review Objects` and seed the default `mode` param (the `special:review_object`
  op_key is unchanged). Missing `mode` already defaults via `.get(...)`, so this
  is cosmetic safety.

### Dialog — `widgets/track_validation_dialog.py`
- Refactor the per-object dialog from a *track* model to a generic *unit* model
  (`_ReviewUnit`: uid + rows + optional track_id). Track rows → one unit per
  track; with new `include_untracked=True`, each untracked row → its own unit.
- Expose `rejected_rows` / `accepted_rows` (the actual row dict refs) plus the
  derived `rejected_track_ids` / `accepted_track_ids` (back-compat —
  `results_page` keeps working unchanged).

### Dialog — `widgets/whole_frame_review_dialog.py` (new)
- `WholeFrameReviewDialog`: composites the current `(m, t)` frame, overlays
  label ids (white / red=rejected / green=accepted) via the `ImageCanvas`
  `set_overlay` painter hook, and toggles a row's decision on `ImageCanvas.clicked`
  (label-mask hit-test, else nearest centroid). M dropdown + T slider + play +
  per-frame **Accept/Reject Frame** buttons. Exposes `rejected_rows` /
  `accepted_rows`. Channels are fetched lazily per M via a provider callable so
  only the viewed position is materialized.

### Page — `pages/pipelines_page.py`
- `SPECIAL_REVIEW_OP_KEY` Run → `_run_review_objects` dispatches on `mode`:
  - single → per-M loop, `TrackValidationDialog(include_untracked=True)`, apply
    decisions by row identity (`id(r)`), supporting untracked objects.
  - whole frame → one `WholeFrameReviewDialog` across all M (rows_by_m +
    masks_by_m + channel provider), apply by row identity.
- Preview (`_preview_validate`) reads `mode` too: single → generalized panel
  dialog; whole frame → `WholeFrameReviewDialog` scoped to the current M's
  screened planes. Decisions applied back to `_results_rows` by row reference.
- Param-popup "Edit…" for Review Objects opens the preview review
  (`Review objects…`).

## Key decisions
- **One mechanism for decisions: row references** (`rejected_rows`/`accepted_rows`).
  Avoids brittle key mapping across tracked/untracked + preview re-framing.
  Track-id properties remain as a derived convenience for `results_page`.
- **Whole frame = one viewer across all M** (user choice) with lazy per-M channel
  materialization to bound memory.
- **Both per-object click and frame-level Accept/Reject** in whole-frame mode
  (user choice).
- No schema bump beyond the v3 already added for Track Objects; the review
  `mode` param is additive and defaults gracefully.
