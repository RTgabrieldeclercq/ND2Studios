# V1.46 — Streaming, Resource-Aware Analysis

## Goal

Analysis / Results / Batch must not populate RAM with the whole dataset (and
whole label-mask stacks) on memory-constrained machines. Adopt the
Fiji/NIS-Elements "virtual stack + streaming sink" model: read frames on demand
from a lazy reader, process per-frame, spill label masks to disk incrementally,
and keep only measurement rows in RAM. The eager-vs-streaming choice is
**adaptive**, gated on the resource-aware load strategy.

## Why

Even after V1.44 made *loading* honor the lazy strategy, the compute paths
called `.materialize()` / `np.asarray()` to build full `(T,H,W)` arrays before
processing, and every pipeline pre-allocated an in-RAM `label_stack`. So a low-RAM
host OOMed during analysis regardless of the lazy load.

## What shipped

### Streaming sink — `pipeline/storage.py`
`LabelStackWriter(base, shape)` writes one `(H,W)` frame at a time:
`write_frame(t, frame)`, `close() -> lazy reader`. Backend = Zarr `(1,H,W)`
chunks when available, else a memory-mapped `.npy` (`np.lib.format.open_memmap`).
Random-access writes ⇒ out-of-order completion is safe. `read_label_stack` /
`open_label_stack` learned the `.npy` suffix (lazy mmap read).

### Shared per-frame driver — `backend/analysis/plane_runner.py` (new, Qt-free)
`run_planes_to_labels(n_frames, height, width, per_frame_fn, primary_writer,
secondary_writer, has_secondary, n_workers, progress_cb, cancelled_cb)`. Runs an
index-aware thread pool (`per_frame_fn(t) -> (labels, rows, secondary)`), routing
each label frame to either an in-RAM `(T,H,W)` array (eager) or the
`LabelStackWriter` (streamed), accumulating measurement rows. `make_label_writers`
reads the reserved params (`_stream_labels`, `_label_sink_factory`) so pipeline
`run()` signatures don't change. `backend/analysis/source_utils.py` adds
`source_shape` / `read_plane` for lazy-or-eager frame access.

### Pipelines — `backend/analysis/{histogram_threshold,tear_detection,spots_pipeline,nuclei_segmentation}.py`
Refactored to: stop `np.asarray`-ing the whole stack (keep the source lazy, read
per frame), extract the per-frame body into `per_frame_fn(t)`, and route output
through `run_planes_to_labels`. Spots/Nuclei stay sequential (`n_workers=1`) since
their segmenter/Cellpose isn't thread-safe; histogram/tear stay parallel. Spots'
`bg_stack` flows through the secondary sink. `AnalysisPipeline.needs_full_stack`
(default False) lets a future temporal pipeline opt back to in-RAM.
`AnalysisResult.label_masks` typing relaxed to `Dict[str, Any]` (value may be a
lazy reader).

### Adaptive gate — `utils/resource_strategy.py`
`should_stream_analysis(volume, *, decision, monitor, force)`: `force`/
`needs_full_stack` wins → in-RAM; dataset type (`MaterializedDataset`→in-RAM,
lazy volume→stream); `decision.strategy == LAZY_CACHED`→stream; memory band ≥
CRITICAL→stream. Qt-free (monitor duck-typed).

### Measurements — `backend/results_engine.py`
`compute_measurements` no longer materializes all channels up front. It reads
each channel's frame `t` once into a per-frame cache (lazy-friendly) inside the
existing per-frame loop; masks (`label_masks`) are indexed per frame too. Peak
RAM = one mask + one frame per channel + the growing rows list.

### Workspace commit — `pipeline/stages/analysis_stage.py`
`commit_m` now persists masks via `_persist_labels` → `LabelStackWriter`
frame-by-frame (never `np.ascontiguousarray` of the whole stack — a memmap is an
ndarray subclass, so the old `write_label_stack` would have re-materialized a
streamed reader). It also swaps the in-memory `result.label_masks` to the
persistent canonical readers so the viewer/overlay reads from the workspace and
the temp scratch can be dropped.

### Call sites
- `pages/analysis_page.py` — `_build_channels_for_m` keeps channels lazy (no
  `.materialize()`); `_maybe_inject_label_streaming` injects the stream flag +
  a temp-scratch sink factory when `should_stream_analysis` says so; scratch is
  removed at finalize/cancel (commit copies masks into the workspace first).
- `pages/results_page.py` — `_channels_for_m` returns lazy channels.
- `workers/batch_worker.py` — M=0 and per-M channels kept lazy (t-stride via
  `to_lazy_channel`); `_inject_label_streaming` streams masks to an
  `output_dir/.labels_scratch/m###` scratch, removed after each M (Batch keeps
  only the CSV + optional images).

## Reused (not rebuilt)
Identical lazy/materialized frame API (`get_frame`/`to_lazy_channel`/`shape`),
the per-M disk-streaming already in `AnalysisStage`, zarr `(1,H,W)` chunking, the
overlay's existing per-frame `label_masks[ch][t]` indexing, `recommended_worker_count`.

## Verification
- `tests/test_streaming_analysis.py` (9 tests): adaptive gate matrix;
  `LabelStackWriter` round-trip over zarr **and** forced-memmap (out-of-order +
  unwritten-frame); histogram pipeline eager-vs-streamed byte parity
  (masks/measurements/summary); `compute_measurements` lazy-vs-eager parity.
- Full suite: 138 passed. `python run.py` launches clean.
- Manual (recommended on a real file): set "Force Lazy (cached)" or
  `ND2_FAKE_RAM_GB`, run a pipeline on a multi-T file, confirm Task Manager RAM
  stays bounded and the overlay + Results table are correct.

## Out of scope / follow-ups
- `RecipeWorker` still materializes a channel when a recipe is applied (bounded to
  one channel/file) — port to streamed recipe application separately.
- GPU-batched Cellpose across frames would set `needs_full_stack`.
- `export_overlay_frames` still materializes channels at user-initiated export
  time (bounded to one file).
