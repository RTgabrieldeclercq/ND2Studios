## 2. `pipeline_graph/registry_adapter.py`

- **`_SPECIAL_OPS` rows** (`:424`) — one per node, per P0 §1 (HEXAGON, `NodeCategory.SPECIAL`):
  - bead_detect: `input_types=[PortType.IMAGE]` (7th tuple element → rainbow channel wiring), `output_types=[PortType.DATA]`.
  - cluster / tessellate: `[PortType.DATA]` in; out `[PortType.DATA]` / `[PortType.ANY]`.
  - mask / boundary: `[PortType.ANY]` in, `[PortType.ANY]` out (mirrors `mask3d`).
- **`param_specs_for` branches** (`:561`) — one `if op_key == …:` block per node,
  returning the `ParamSpec` lists named in P1–P5 (use `visible_when` for `alpha`
  (tess_mode), `band_um` (band_method); no hidden geometry params — unlike mask3d,
  granule geometry is computed, not drawn).
- **`op_produces_objects`** (`:196`) — add `SPECIAL_GRANULE_MASK_OP_KEY` (and,
  optionally, `SPECIAL_GRANULE_BOUNDARY_OP_KEY`) so the Frame/Object scope lever
  appears on their outgoing edges.
- **Add-node descriptions**: optional entries in `add_node_dialog._DETAILS` (`:160`)
  keyed by node title for richer palette tooltips.

## 3. `widgets/node_board/node_scene.py` — widen the scope-lever gate

`_apply_edge_scope_lever` currently shows the lever only when
`dst.op_key == SPECIAL_DVC_OP_KEY` (`node_scene.py:185`). Widen `honored` to also
accept edges whose **source** `node_produces_objects` regardless of dst (or at least
include the granule mask as a source), so `granule_mask → DVC` and future consumers
get the lever. Keep the default-absent ⇒ whole-frame behavior.

## 4. `pages/pipelines_page.py` — dispatch + handlers

- Import the op keys; add `elif op == SPECIAL_…:` branches in `_run_execute_node`
  (`:5423`) → `_run_bead_detect` / `_run_granule_cluster` / `_run_granule_tessellate`
  / `_run_granule_mask` / `_run_granule_boundary` (bodies specified in P1–P5).
- Initialize the `self._granule_*_by_m` stores next to `self._mask3d_by_m`; mirror to
  `record._granule_*_by_m` for cross-Run reuse; clear them in the same place mask3d
  state is reset.
- Each handler ends with `self._run_finish_node(node.id, port_rows=…)`; async only if
  a node proves slow (bead detect on huge stacks) — then use the `_DVCJob`/`_run_pending`
  pattern.
- Feed granule masks to the DVC panel the same way `_populate_dvc_panel` passes
  `record._mask3d_by_m` (`V1.67`): when a `granule_mask` feeds DVC with scope=objects,
  `_dvc_scoped_object_regions` already calls `iter_objects` on the per-granule bool
  masks → one DVC field + surface + MDM per granule for free.

## 5. `backend/analysis/object_scope.py` — `(Z,H,W) int32` label support (P0 §6)

Add `iter_objects` handling (or `iter_objects_3d_labels`) so a `(Z,H,W) int32` volume
is treated as **one 3-D region per label id** (bbox via `scipy.ndimage.find_objects`,
`mask = labels==id`), not as `(T,H,W)`. The per-granule bool path already works; this
makes the combined `"_labels"` volume first-class for any consumer that reads it
directly.

## 6. Persistence

`Edge.params` (V1.68). Assert a saved granule pipeline reloads identically.
