# V1.79 — Bake DVC export into the Output node (auto-save on Run)

## Goal

Follow-up to V1.76 (DVC export/reload). Instead of a manual **Export** button in the
DVC viewer, the export is **baked into the pipeline's Output node**: wire the **DVC
node → an Output node**, and on **Run** the Output node automatically writes *all* of
the connected node's backend data (the full `.nd2dvc` bundle — every multipoint /
frame / object + the quantitative displacement/strain fields) to a **folder named
after that Output node** inside ND2Studios. The manual Export button is removed.

User's exact asks:
1. Bake the export function into the Output node automatically.
2. All backend data from the node connected to the Output node → saved in a folder
   named after that Output node, "in ND2Studios".
3. Remove the Export button in the DVC viewer.
4. Give the DVC node an **output port** so it can connect to an Output node.

## Decisions

1. **DVC output port = `PortType.ANY`.** The DVC node spec's `output_types` goes from
   `[]` (terminal) to `[PortType.ANY]`. `can_connect` treats ANY on either end as a
   wildcard, so DVC connects to the Analysis Output node (input `BINARY`) — matching
   the Registration / Granule-Volume-Mask precedent (both emit ANY). A **normal
   structural edge** (not a V1.77 view-only one), so the run walk orders DVC before
   the Output node. *Caveat:* ports are built at node-creation, so an **existing** DVC
   node in a saved pipeline must be deleted + re-added to gain the port (same as the
   V1.65 mask-node port change).

2. **Folder location = `<repo>/results/<Output-node title>/`.** The codebase has no
   central output dir (`Settings.PROJECT_DIR` is the repo root; `results/` is the
   gitignored output convention). The Output node's `node.title` (default
   `"Analysis #N"`, user-editable by double-click) names the folder. Auto-save is
   **unattended** — no file dialog (the request says "automatically … in a folder with
   the name of that output node"). The folder holds `<title>.nd2dvc` + a human-readable
   `provenance.json`. Re-running overwrites (stable, checkpoint-like).

3. **Hook point = the Output branch of `_run_execute_node`.** Previously
   `if node.role is INPUT or OUTPUT: _run_finish_node`. Split so OUTPUT routes to a new
   `_run_output(node)`. If the node wired into the Output node is a **DVC** node (and
   DVC stores are populated), auto-save the bundle **off-thread** (`DVCExportWorker`)
   and finish the node from the worker's done slot (like `_run_dvc`); otherwise it is
   the unchanged pass-through. Non-DVC Output nodes are byte-identical to before.

4. **Export button removed; import kept.** `DVCPanel.export_requested` signal +
   `btn_export` deleted; the page's `export_requested.connect(...)` wirings (DVC + the
   DIC panel's status stub) removed. Reload is unchanged — the **Import DVC results**
   toolbar button + the DVC Checkpoint node still load a `.nd2dvc` (now found inside
   `results/<name>/`). The gather/provenance helpers (`_gather_dvc_bundle_payload`,
   `_dvc_bundle_meta_for`, `_dvc_provenance`) are reused by the Output node.

## Out of scope / follow-ups

- Generic (non-DVC) Output-node auto-save — the existing Save Data / Export nodes still
  cover analysis masks / measurements. Auto-save here is DVC-specific by design.
- A configurable output root (today it is `<repo>/results/`); DIC auto-save (DIC export
  is still unimplemented).
