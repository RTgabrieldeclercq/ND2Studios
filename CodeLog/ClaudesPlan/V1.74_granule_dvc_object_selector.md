# V1.74 — Per-granule DVC surface selector (+ "All granules" composite)

## Goal

Close the last gap in the granule → DVC surface pipeline. Wiring a **Granule
Volume Mask** node into a **DVC** node and flipping the wire's Frame/**Objects**
lever already runs one surface-DVC solve *per granule* (V1.68 per-object scope +
V1.70 granule masks). But the DVC panel only ever renders the **largest**
granule's surface — every other granule's field is computed and thrown away at the
display layer (`_store_dvc_objects` keeps only the largest mask/series).

Deliver the documented follow-up: **a per-granule (per-object) selector in the DVC
tab**, plus an **"All granules"** entry that composites every granule's surface
into one 3-D scene. So the user can inspect the surface DVC (mesh + u⊥/u∥ + MDM +
2-D unwrap) of *each* granule, or view them all at once.

This is the display half of "reflect the granule mask via the Objects toggle so
DVC runs its surface pipeline onto the granule(s)". The **run** half already works
and is headless-verified; nothing about scope enumeration or the `_DVCJob`
per-object loop changes.

## What already exists (do not re-touch)

- `op_produces_objects(SPECIAL_GRANULE_MASK_OP_KEY) == True` → the Frame/Objects
  lever shows on a *Granule Volume Mask → DVC* edge (`registry_adapter`,
  `node_scene._apply_edge_scope_lever`).
- `pipelines_page._dvc_scoped_object_regions` reads `record._granule_masks_by_m`
  and enumerates each granule from the combined `_labels` volume via
  `object_scope.iter_objects_3d_labels`.
- `_DVCJob(object_regions=...)` runs DVC once per granule on its crop and returns
  `{"objects": {oid: {m: bundle}}, "object_masks": {oid: mask}}`, each bundle
  `{"primary": {t:(res,bg)}, "increment": {t:res}}`.
- `dvc_object_surface(result, mask, mask_vsz)` → `SurfaceField` (marching cubes +
  Taubin + on-surface u sampling + MDM); `DVCPanel` renders it via the embedded
  `PyVista3DViewer.set_overlay(SurfaceField)` and unwraps it via `unwrap_surface`.

## The gap (root cause)

`pipelines_page._store_dvc_objects` collapses the per-object result to the
**largest** object: it keeps `_dvc_obj_by_m = {m:{oid:{t:res}}}` (status only) and
`_dvc_display_mask_by_m = {m:{t: largest_mask}}`, and returns the largest bundle
for the normal single-surface display path. The panel never learns the other
granules exist.

## Approach

Three layers, smallest surface area that keeps the existing single-object path
byte-identical when there are no objects.

### 1. Backend — `backend/viz3d/overlays.py`

Add pure-numpy `merge_surface_fields(fields) -> SurfaceField` for the composite:
- Drop empty/None; 0 → `_empty_surface_field()`; 1 → return as-is.
- `vertices_um`/`vertex_normals`/`u_par_vec` = vstack; `faces` = vstack with a
  running vertex-index offset per field.
- `scalars` = union of keys; per key concatenate each field's array, filling
  **NaN** where a field lacks that key (NaN is ignored by the viewer's clim /
  `nan_to_num`), so a scalar present in only some granules still renders.
- `centroid_um` = merged vertices mean; `default_scalar="disp_mag"`; **`mdm=None`**
  (a composite MDM is ill-defined — the panel shows a granule-count summary
  instead); `interior=None`; `dim` = first non-empty; `n_object_voxels` = Σ.
- Renders through the **existing** `_add_surface_field_overlay` unchanged (disjoint
  components in one `PolyData`, shared color scale — good for comparison).

### 2. Page — `pages/pipelines_page.py`

- `_store_dvc_objects`: additionally build a rich store
  `self._dvc_obj_full_by_m = {m: {oid: {"series":{t:res}, "bg":{t:bg},
  "increment":{t:res}, "mask":{t:mask}, "n_voxels":int}}}`. Keep the existing
  `_dvc_obj_by_m` / `_dvc_display_mask_by_m` (largest) and the largest-bundle
  return value untouched (backward compat with the normal display path).
- `_finish_dvc`: reset `self._dvc_obj_full_by_m = {}` beside the existing resets.
- `_populate_dvc_panel`: when `_dvc_obj_full_by_m.get(m)` exists, pass
  `objects=<that m's bundle>` to `panel.set_data(...)`. Positional
  `series`/`backgrounds`/`masks` stay the **largest** (so the default view is
  unchanged); `mask_voxel_size` (raw) is shared by all granules.

### 3. Panel — `widgets/dvc_panel.py`

- New `cmb_object` combo (label "Object:") after `cmb_view`; visible whenever
  per-object data is present. Entries: **"All granules (N)"** (`data="__all__"`)
  then one per granule sorted by voxel count desc (`"Granule {id} · {k}k vox"`,
  `data=oid`). Default = **largest** single granule (index 1) → today's behavior.
- `set_data(..., objects=None)`: store `self._objects`; populate the combo; set
  `self._active_oid = largest`, `self._show_all_objects = False`. `objects=None`
  clears it (combo hidden) → legacy datasets behave exactly as before.
- `_on_object_changed`: **"__all__"** → `_show_all_objects=True`, series/masks reset
  to the largest (so 2-D views still render something), surface caches reset,
  re-render. **A granule** → swap `_series/_increments/_backgrounds/_masks` from
  `self._objects[oid]`, reset `_fb_cache` + surface caches + `_theta_series`, bump
  `_obj_gen`, autofit, re-render.
- `_surface_key()` gains a leading object dimension (`oid | "__all__" | None`) so
  the single- and all-paths key the surface cache uniformly and the existing
  `_on_surface_field_done` comparison keeps working.
- `_need_surface_field()` branches: `_show_all_objects` → build a **merged** surface
  off-thread via a new `_MultiSurfaceFieldWorker` (builds each granule's
  `dvc_object_surface(with_metrics=False)` then `merge_surface_fields`); else the
  existing single-surface worker. Both emit the same `done(key, sf, gen)` →
  `_on_surface_field_done`. `_obj_pending` becomes a small discriminated dict
  (`{"kind":"single"|"multi", ...}`) so the coalescer stays kind-agnostic.
- "All" mode: **2-D Unwrap** shows "pick a single granule" (a composite unwrap is
  ill-defined); the **3-D Object** metrics readout shows a granule-count summary
  instead of per-object MDM. Single-granule mode: unwrap + MDM work as today.

## Key decisions

1. **Composite = one merged `SurfaceField`**, not multi-overlay in the viewer —
   zero VTK/viewer changes, shared color scale, existing render path.
2. **Composite MDM is omitted** (`mdm=None`); per-object MDM needs a single
   granule selected. Documented in the readout, not silently blank.
3. **Legacy / mask3d / whole-frame paths unchanged**: `objects=None` ⇒ no combo,
   `_active_oid=None`, identical behavior. The single-object surface path is the
   default selection even when objects are present.
4. **Per-object backgrounds & increments preserved** (were discarded) so a
   selected granule's 2-D field views and Cumulative/Increment toggle work.
