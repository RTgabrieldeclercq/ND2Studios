# V1.76 — DVC export / reload as a portable checkpoint input node

## Goal

Two user-facing asks on the **DVC viewer** (`DVCPanel`, the "DVC" overlay tab):

1. **Export button** in the DVC viewer that writes *all* outputs of the DVC node —
   the **quantitative backend data included** (`DVCResult` grids, displacement +
   strain fields, q-factor, diagnostics) plus everything needed to re-render
   (per-frame image backdrops, 3-D object masks, per-granule object bundles) — to a
   single portable file, so it can be **reloaded into a new ND2Studios run** and
   rendered via the same viewer **without running anything**.

2. **Home button for the 3-D object view** (the embedded PyVista viewer), matching
   the Home button the 2-D field views already have.

### Locked scope (confirmed with the user)

- **Reloaded node identity:** import drops **one portable input node** — a
  self-contained *DVC Checkpoint* source node — at the board. It carries the saved
  results + provenance and re-publishes to the DVC viewer with no Run. Works in a
  brand-new session with **no ND2 loaded**. The original upstream nodes are **not**
  recreated.
- **Export scope:** **all multipoints** (the complete DVC node output).
- **Payload:** **everything to re-render** (fields + masks + backdrops), compressed.
- **"History":** **results + a read-only provenance record** — the upstream node
  names/params, the DVC run settings, source-file name and timestamp — shown on the
  node tooltip and stored in the file. Not re-executable; auditable.
- **"Continue analysis":** **viewer re-exploration** — every scalar field, the 3-D
  object surface + MDM, 2-D unwrap, colour/global scale, quiver/histogram, and
  figure/screenshot export, all recomputed from the saved `DVCResult`s. DVC is a
  **terminal** node today (input `IMAGE`, outputs `[]`, nothing consumes it), so the
  reloaded node needs **no output port**.

## Key design decisions

1. **Single portable file, `.nd2dvc`.** An NPZ (zip) written by
   `np.savez_compressed` (via an open file handle so the extension is *not* forced to
   `.npz`). It holds one `__manifest__` entry (a JSON string in a 0-d unicode array —
   **no pickle**) describing structure + metadata + provenance, plus the numpy arrays
   keyed `a0, a1, …`. `np.load` auto-detects the zip by content regardless of
   extension. Mirrors the app's "JSON manifest + companion NPZ" convention
   (`.nd2s`, `checkpoint_io.py`).

2. **Array dedup by identity.** Object masks are the *same* array broadcast across
   every frame (`{t: mask for t in series}` in `_store_dvc_objects`), and the display
   mask repeats the largest object's mask. An `_ArrayRegistry` keyed on `id(arr)`
   writes each distinct array once and refers to it by key — so a 30-frame object
   stores its mask once, not 30 times.

3. **Backend stays Qt-free.** All (de)serialization lives in
   `nd2studios/backend/dvc_export.py` (numpy + json only), callable headless. File
   I/O runs **off the GUI thread** in `QThread` workers
   (`nd2studios/workers/dvc_export_worker.py`) per the "Workers, not async"
   convention — the gather (reading page stores) and the populate (rebuilding stores
   + node + viewer) happen on the GUI thread; only the `savez`/`np.load` runs
   off-thread.

4. **Reloaded node = a new terminal source op** `special:dvc_checkpoint`
   (`SPECIAL_DVC_CHECKPOINT_OP_KEY`), `NodeCategory.CHECKPOINT` (white, like the V1.53
   Checkpoint), `ShapeKind.HEXAGON`, **no input and no output ports**. It stores
   `params["bundle_path"]` + `params["provenance"]`. It is **excluded from the
   Add-node dialog** (created only by Import — an empty one is meaningless) but
   round-trips through `save_pipeline`/`load_pipeline` with no `io.py` change (generic
   op_key + params, like `special:exclude`).

5. **Reload does not depend on the executor.** The viewer is populated at **import
   time** and, for a saved pipeline, at **pipeline-load time** (scan for the op_key,
   auto-load its bundle) — the same pattern as `_load_checkpoint_cache`. `_on_run`
   does **not** clear `_dvc_series_by_m`, so the loaded data survives a Run. A
   defensive Run-dispatch case (`_run_dvc_checkpoint`) re-publishes if the node is
   ever visited, so it never errors as an unknown op.

6. **Bundle-sourced viewer path.** `_populate_dvc_panel` currently derives frame
   count / pixel size / voxel size / channel names / timestamps from
   `record._raw_volume`. On reload there is no record, so the bundle stores that
   metadata and `_populate_dvc_panel` branches to `_populate_dvc_panel_from_bundle`
   when `self._dvc_from_bundle`. The surrounding-channel **context overlay** needs the
   raw volume, which a pure reload lacks, so `context_provider=None` on reload (the
   picker still lists channel names, but renders nothing — acceptable and noted).

7. **Home for 3-D.** `DVCPanel._on_zoom_home` delegates to
   `self._view3d.reset_camera()` when the "3D Object" view is active (so the panel's
   existing Home button works in 3-D), **and** a dedicated `fa5s.home` button is added
   to the PyVista viewer's own control bar (`reset_camera()` already exists).

## Data captured (round-trips exactly)

Page stores (all keyed by int `m`), from `_store_dvc_objects` / `_run_*dvc*`:

- `_dvc_series_by_m[m] = {t: DVCResult}` — cumulative/primary field series.
- `_dvc_incr_by_m[m] = {t: DVCResult}` — raw per-step increments.
- `_dvc_bg_by_mt[m] = {t: (H,W)}` — per-frame backdrops.
- `_dvc_obj_full_by_m[m] = {oid: {"series","increment","bg","mask","n_voxels","origin"}}`
  — per-granule bundles (the granule selector + "All granules" composite).
- `_dvc_display_mask_by_m[m] = {t: mask}` — largest object's mask (single-surface path).
- `_mask3d_by_m[m] = {t: (Z,H,W) bool}` — whole-frame drawn masks (non-object path).

`DVCResult` (de)serialize: arrays (`grid_coords`, `displacement_field`,
`strain_field?`, `qfactor?`) via the registry; scalars/meta (`dim`, `voxel_size_um`,
`strain_type`, `converged`, `iterations`, `mu`, `beta`, `method`, `notes`,
`diagnostics` — JSON-coerced) inline.

Per-bundle **meta** (what `_populate_dvc_panel` otherwise derives from the record):
`n_multipoints`, `context_channels`, and per-m `{n_frames_total, pixel_size,
field_shape, mask_voxel_size (dz,dy,dx), frame_times_s, surface_smooth_iterations}`.

**Provenance** (JSON, read-only): `app_version`, `created` (ISO, stamped on the GUI
thread via `datetime`), `source_file`, `dvc` (method + subset/spacing/correlation/
tracking_mode/strain_type/admm/ref-def frames from the DVC node params), `upstream`
(list of `{title, op_key, params-summary}` walking the DVC node's inputs), and a
`summary` (n_multipoints / n_frames / n_objects / dim).

## Out of scope / follow-ups

- Re-feeding the reloaded field into the graph for downstream nodes (DVC is terminal;
  no consumer exists). The node deliberately has no output port.
- Restoring the surrounding-channel **context** overlay on a pure reload (needs the
  raw ND2). Re-linking a moved `.nd2dvc` from the node. Editing the provenance recipe.
