# V1.45 — SerialTrack tracking option on the "Track Objects" node

## Goal

Add a second linker — **SerialTrack (topology PTV)** — as a `method` option on
the Track Objects node (see [V1.45_track_objects_node.md](V1.45_track_objects_node.md)
for the node itself). SerialTrack (Yang et al., *SoftwareX* 19 (2022) 101204; see
[Research/serialtrack.md](../../Research/serialtrack.md)) is a scale/rotation-invariant
topology matcher that stays robust where the centroid nearest-neighbor linker
loses tracks (large or rotational inter-frame motion). The node already operates
on segmented-object centroid rows, so we drive SerialTrack's `track_coordinates`
path — the centroids *are* the pre-detected particles; no image re-detection.

Outcome: choosing "SerialTrack" links objects via topology matching and annotates
each row with the same `track_id` / `track_length` / `track_validation`, so Review,
if-else, and Export are unchanged.

## Approach

### Vendor — `nd2studios/backend/serialtrack/` (new)
Copy the **headless** subset of the SerialTrack Python port (sibling repo
`SerialTrack_Python/serialtrack`) — 9 modules: `config, tracking, detection,
matching, outliers, regularization, prediction, fields, trajectories` — plus a new
`__init__.py` (upstream is a namespace package with none). The excluded
`io/results/run` modules pull `h5py`/`tifffile`/`PySide6`; `tracking.py`'s import
graph is closed over the 9 vendored modules, so none of those are referenced. This
keeps backend purity (no PySide6 under `backend/`). The only hard new dependency is
**numba** (already installed); `scikit-image` (detection deconv) and `scikit-learn`
(POD-GPR) are imported lazily inside paths the linker never hits.

### Backend — `backend/object_tracker.py`
- Add `METHOD_SERIALTRACK = "SerialTrack (topology PTV)"`; append to
  `TRACKING_METHODS` (which auto-populates the node's method dropdown).
- `link_objects(...)` gains `st_mode` ("Incremental"/"Cumulative") and
  `st_n_neighbors`, and **dispatches per group**: `_link_group_serialtrack(...)`
  when the method is SerialTrack, else the existing `_link_group(...)`. The
  post-pass (track-length tally, `min_track_length` filter, `track_validation`) is
  method-agnostic and runs unchanged.
- New `_link_group_serialtrack(group_rows, f_o_s, mode_str, n_neighbors_max,
  next_id)`: builds per-frame centroid arrays (frames with ≥1 detection, in order)
  with a parallel `row_refs` list; lazily imports the vendored SerialTrack; runs
  `SerialTracker(DetectionConfig(), TrackingConfig(mode, f_o_s, n_neighbors_max,
  strain_n_neighbors=0, use_prev_results=False)).track_coordinates(...)`; then
  chains `track_b2a` (aligned to `coords_b`) to assign track ids — incremental
  inherits from the previous frame, cumulative from the reference frame, `-1`
  starts a new track.
- `link_objects_with_params(...)` forwards `st_mode` / `st_n_neighbors` from the
  node params. "Max distance" → `f_o_s` (the existing µm→px conversion still runs).

### Registry — `pipeline_graph/registry_adapter.py`
In the `SPECIAL_TRACK_OP_KEY` branch of `param_specs_for`:
- Gate the centroid-only knobs with `visible_when={"method": METHOD_CENTROID}`
  (`max_size_diff`, `max_frame_gap`).
- Add two SerialTrack-only specs with `visible_when={"method": METHOD_SERIALTRACK}`:
  `st_mode` (choice Incremental/Cumulative) and `st_n_neighbors` (int, default 25).
- `max_distance`, `distance_unit`, `min_track_length` stay always-visible (shared).

No `pipelines_page.py` change: both `_run_track_objects` and the preview walk
already call `link_objects_with_params(rows, node.params, …)`, and the param popup
honors `visible_when` automatically.

## Key decisions
- **Vendor the headless subset**, not a sys.path hack or the whole package —
  self-contained, portable, backend-pure, single new dep (numba).
- **`track_coordinates`, not detection** — reuse the centroids the analysis
  pipelines already produced.
- **Deterministic id chaining via `track_b2a`** rather than stitched
  trajectories — robust and order-aligned to our input rows.
- **Incremental is the default** (handles objects appearing/disappearing);
  Cumulative is offered for large total motion when all objects are present from
  frame 1.
- **Param surface adapts to method** via `visible_when`; SerialTrack ignores the
  centroid-only area/gap gates by design.
