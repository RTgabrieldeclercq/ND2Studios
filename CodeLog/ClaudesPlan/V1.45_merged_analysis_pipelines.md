# V1.45 — Merge Analysis + Results into one branching, runnable "Analysis" tab

## Goal

Fuse the Pipelines page's **Analysis** and **Results** sub-tabs into a single
**Analysis** tab whose nodes keep per-origin colors (analysis = pink, results =
green) in one scene, and add three new capabilities:

1. A purple **if-else** triangle node (1 input on the apex; `true` bottom-left,
   `false` bottom-right) whose condition routes the pipeline (aggregate gate).
2. **Special action nodes** (orange hexagons; Dismiss is a red rectangle):
   Validate Tracked Objects, Review Object, Dismiss, Export Objects/Frames, Send
   to Results, Pause.
3. A **Run** button (replacing Apply on the merged tab) that *executes* the
   graph: pending / un-taken nodes **shaded**, the executing node **gold**,
   completed nodes **normal**; Pause drops back to editor mode (all un-shaded).

## Decisions (confirmed with the user)

- **Phased.** This pass = **Phase 1**: structure + visuals + a working Run
  skeleton. Phase 2 = the full stackable condition-block builder + the
  interactive special-node dialogs/exporters.
- **Aggregate gate** for if-else (one true/false for the scope → whole pipeline
  goes one way; per-object keep/drop is the Dismiss/Review/Validate nodes' job).
- **"Send to Results"** targets the top-level **Results page** (page 4).
- **All four condition families** (results-number, object-population, timelapse,
  AND/OR/NOT) — built in Phase 2.

## Approach (Phase 1)

### Qt-free graph core (`nd2studios/pipeline_graph/`)
- `model.py` — `NodeCategory` + `ShapeKind` enums; `category` / `shape_kind` on
  `Node` (serialized; category defaults from stage via `__post_init__`).
  `PipelineDoc.merged` aliases `analysis`; `schema_version` → 2.
- `registry_adapter.py` — `NodeSpec.category` / `shape_kind` / `input_names` /
  `output_names`; `if_else_spec()`, `special_specs()`, `merged_action_specs()`;
  if-else + Export param specs; `build_node` carries category/shape + port names.
- `executor.py` — `topological_order`, `GraphRunner` (branch-pruning Run state
  machine: `reachable_nodes` / `next_ready` / `complete(prune_ports=…)` /
  `is_finished`), `evaluate_simple_condition` (metric/aggregate/comparator/value
  over measurement rows).
- `io.py` — version → 2; `_migrate_v1_to_v2` folds the v1 Results slice into the
  merged Analysis slice on load (drops the synthetic Results in/out nodes).

### Node board (`nd2studios/widgets/node_board/`)
- `node_item.py` — shape-aware `_body_path()` / ports (triangle: apex input,
  base true/false outputs); per-category color (Dismiss → red); `set_run_state`
  (shaded dims, current gold, done normal).
- `node_scene.py` — `_color_for_node` (category → color); `set_run_states` /
  `clear_run_states`.
- `add_node_dialog.py` — catalog grouped into per-category `QTabWidget` tabs.

### Page (`nd2studios/pages/pipelines_page.py`)
- Two sub-tabs (`self._stages = (PROCESSING, ANALYSIS)`); the merged scene uses
  `merged_action_specs()`.
- `_merged_mode()` (previewed-node category) drives the overlay hook + results
  table via `_update_merged_view_mode()`; double-clicking a results node flips
  the tab into results mode.
- Control bar: Apply on Processing, **Run** on the merged tab. `_on_run` →
  `GraphRunner` stepper (`_run_pump` / `_run_execute_node` / `_run_finish_node`),
  running analysis (`_RUN_ANALYSIS_KEY`) and measurement (`_RUN_RESULTS_KEY`)
  nodes via the shared `JobRunner`, evaluating if-else over the run-context rows,
  and `_pause_run` (clear states). Previews suppressed while a Run is active.

### Reused
`TrackValidationDialog`, `results_engine` (metrics + exporters), `ResultsPage` /
`_MeasurementsModel`, `ParamEditor` / `ParamPopup`, `JobRunner` + existing
`PipelineCommitJob` / `_ResultsMeasureJob`, the DAG helpers, and the gold/dim
NodeItem states.

## Phase 2 (delivered)

Condition builder + interactive Run nodes. (Built as a dedicated dialog, not a
`ParamSpec` type — `ParamSpec` only supports flat scalars.)

- **Condition DSL** — `pipeline_graph/conditions.py` (Qt-free): `Condition`
  (ALL/ANY) of negatable `ConditionBlock`s, a `BLOCK_KINDS` catalog spanning
  results-number / object-population / timelapse families, `evaluate_condition`
  (the Run gate, robust to missing data) + `describe_condition`. The if-else
  node seeds a default condition in `params["condition"]`.
- **`ConditionBuilderDialog`** (`widgets/node_board/`) — add/remove blocks from a
  family-grouped menu, per-block NOT, ALL/ANY combine, live readout. Opened by
  double-clicking an If/Else node.
- **Interactive special nodes** in the Run stepper: Validate / Review →
  `TrackValidationDialog`; Dismiss → drop rejected (or all) rows; Export →
  folder picker + `results_engine.export_overlay_frames` /
  `export_label_masks_tiff`; Send to Results → push rows/masks into the top-level
  `ResultsPage` + navigate. Measurement nodes run `object_tracker.link_objects`
  so timelapse conditions + Validate have `track_id`.
- **Resume after Pause** — the Pause node retains the `GraphRunner`; Run resumes
  from the pause point (restarts if the graph's node set changed).
- **Whole-file Run** — Run processes every multipoint, not just the current
  frame: an analysis node loops M (`_advance_run_m`: per-M analysis job →
  measurement job → accumulate rows tagged `m_position`), and the if-else,
  Export, Send, and Validate operate over the aggregated all-M dataset. Rows are
  auto-derived from the analysis result when no Compute Measurements node exists
  (`_ensure_run_rows`).

### Measurement picker + previewable nodes (V1.45.19)
- Compute Measurements node has a `MeasurementSelectDialog` (param-popup Edit
  button) → `params["metrics"]`; `compute_measurements(metrics=…)` computes only
  the selected quantities (skips shape/intensity, prunes columns) without re-running
  the analysis.
- Double-click previews any node; results / if-else / special nodes resolve the
  upstream analysis result (committed or current-frame screened) and show the
  overlay + measurements table. Editor dialogs (condition / metrics) open from the
  param popup's Edit button. If/Else preview reports the branch it would take.

### Multi-frame preview + validate-in-preview (V1.45.20)
- A results / Compute Measurements / if-else / special preview screens + measures
  every selected (M × T) plane (`_ResultsScreenMeasureJob`); the table aggregates
  all selected frames (rows tagged `m_position`/`frame`) and the overlay is
  per-plane. Navigating / re-selecting frames re-runs the preview.
- Validate / Review nodes have a popup "Validate tracked objects…" button that
  runs `TrackValidationDialog` on the current M's selected-T stack (tracking
  across the selected timepoints), applying accept/reject to the preview rows.

### Export frame organization (V1.45.22)
- Export node *Frame organization* dropdown → `results_engine.export_organized`:
  per-frame; **M folds into T**; **T folds into M**; **all merged**; + Z variants
  (general M/T/Z fold-vs-split formula; Z collapsed today). TIFF multi-page stack
  per group; PNG/JPG single file or per-group subfolder. `EXPORT_ORG_MAP` maps UI
  labels → fold keys.

### Still deferred (future polish)
- Per-Z masks (Z is collapsed at load), so Z-fold export options coincide with
  their non-Z siblings for now.
- A dedicated single-object Review viewer; nested condition groups; per-branch
  data forking.
- A dedicated single-object **Review** viewer (currently reuses the track dialog).
- Nested condition groups (only a flat ALL/ANY of blocks today).
- Per-branch data forking (the aggregate gate routes execution over one shared
  measurement stream, not separate per-branch object subsets).
