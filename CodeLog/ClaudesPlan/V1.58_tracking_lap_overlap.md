# V1.58 — Tracking: birth/death LAP + mask-overlap (IoU) linker

## Goal

Fix the two failure modes of object tracking after StarDist segmentation,
reported on dense monolayer nuclei (H2B-iRFP670):

- **High `max_distance`** → cells that move only slightly are linked to distant
  cells (spurious long links).
- **Low `max_distance`** → cells are chain-linked to their neighbors, forming
  propagating "currents" of mis-tracking (a mismatch pushes each neighbor onto
  its next neighbor).

## Root cause

`link_frames` / `track_fingerprint` (and the base centroid `_link_group`) built
an `N×M` cost matrix, marked out-of-gate pairs with a large finite sentinel, and
called `scipy.optimize.linear_sum_assignment` directly. That solver returns a
**complete** matching of the smaller side — it cannot leave a detection
unmatched. With no birth/death ("no-match") option:

- a count imbalance (division, missed detection, cell entering/leaving) forces a
  distant partner within the gate → long links (high `max_dist`);
- when a true partner is just out of range, the solver routes the cell onto a
  valid-but-wrong neighbor, which bumps that neighbor onward → the chaining
  "current" (low `max_dist`). A chain is cheaper than eating the sentinel because
  it never reduces the number of unmatched endpoints.

The standard fix is the Jaqaman et al. (2008) LAP (u-track / TrackMate): augment
the cost matrix with dummy nodes so a detection can stay unmatched at a fixed
cost. Separately, the tracker discarded the StarDist masks and linked on
centroids only; for slow dense nuclei **mask overlap (IoU)** is far more
discriminative and removes both failure modes outright.

## Approach

1. **`backend/celltracker/tracking.py`**
   - `solve_lap(cost, no_match_cost)` — Jaqaman augmented assignment with
     birth/death diagonals; splits the gated matrix into connected components of
     finite-cost edges and solves each small block (`_solve_lap_block`) so dense
     fields stay fast (exact — components never couple through dummy nodes).
   - `link_frames` gates on raw distance (marks `inf`), then calls `solve_lap`
     with `no_match_cost` defaulting to `max_dist`. New `no_match_cost` param
     threaded through `track_timeseries`.
   - `track_fingerprint` routes its assignment through `solve_lap` too
     (`fingerprint_cost_matrix` now marks forbidden pairs `inf`).
   - `track_overlap(df, masks, min_iou, max_gap, no_match_cost)` + helper
     `_frame_footprints` — links consecutive frames on `cost = 1 − IoU`
     (pairs below `min_iou` forbidden), via `solve_lap`. Keeps each track's last
     footprint for up to `max_gap` missed frames for overlap re-linking. Overlap
     is computed with a fast crosstab over the label images.

2. **`backend/object_tracker.py`**
   - New `METHOD_CT_OVERLAP = "Cell-Tracker: Mask Overlap (IoU)"` in
     `TRACKING_METHODS`.
   - `_link_group_overlap` bridges row-dicts → DataFrame → `track_overlap`,
     looking the group's `(T,H,W)` label image up from `label_masks[(channel,
     m_position)]`; falls back to the fingerprint linker if masks are absent.
   - `link_objects` / `link_objects_with_params` gain `ct_min_iou` and
     `label_masks`.

3. **UI / plumbing**
   - `pipeline_graph/registry_adapter.py` — the new method appears in the Track
     Objects dropdown; new `ct_min_iou` knob; `ct_max_gap` now shown for overlap
     as well as fingerprint.
   - `widgets/common.py` — `visible_when` values may now be a list (row shows if
     the current choice is any of them), so `ct_max_gap` is shared by two methods.
   - `pages/pipelines_page.py` — `_TrackJob` accepts `label_masks`;
     `_run_track_objects` builds `{(channel, m): (T,H,W)}` from the per-M
     analysis results (by reference) and passes it through.

## Key decisions

- **Two gates.** A hard `inf` gate (`max_distance` for centroids, `min_iou` for
  overlap) forbids impossible links; the birth/death cost `no_match_cost` is a
  soft gate that makes an honest birth/death cheaper than a bad link. Defaults:
  `max_dist` for the centroid/topology/fingerprint linkers, `1.0` (= zero
  overlap) for the overlap linker.
- **Component decomposition** keeps the augmented LAP `O(sum of small blocks)`
  instead of `O((N+M)³)` on dense fields; it is exact because a node's only
  non-linking option is its own dummy.
- **Overlap gate on masks, not distance** — overlap already implies proximity.
- **Masks passed by reference** to the worker (read-only), no copy.

## Validation

- Unit tests (`tests/test_tracking_lap_overlap.py`): `solve_lap` decomposition ==
  full solve; the row-of-cells scenario where the old linker chains and the new
  one records a death + birth; wide-gate no-long-link; overlap identity through a
  close approach, birth of a late object, and re-link across a gap; clean-field
  regression for `track_timeseries`.
- Real data (three uploaded monolayer TIFFs, 33 frames, ~250–680 nuclei/frame,
  watershed stand-in for StarDist). Implausible one-frame steps (> nuclear NN
  spacing):

  | method | file 1 | file 2 | file 3 |
  |---|---|---|---|
  | OLD topology `max=20` (current pipeline) | 861 | 489 | 2554 |
  | NEW topology-LAP `max=20` (birth/death) | 711 | 443 | 1297 |
  | NEW overlap IoU | **7** | **3** | **31** |

  The birth/death LAP roughly halves chaining on pure centroids; overlap removes
  it almost entirely. Global drift was small (median ~0.6 px/frame) but one frame
  jumped ~26 px (> nuclear spacing) — run the V1.56 registration node before
  tracking, or rely on the overlap gap-filling, for such frames.

## Follow-ups (not in this change)

- Consider defaulting the Track Objects node to the overlap method when the
  upstream produced StarDist masks.
- The downstream `If/Else` per-frame-displacement filter becomes largely
  redundant once overlap tracking is used; keep it only as a safety net.
