# Plan: Fix Black Stitch Output (V1.0)

## Goal
Fix the bug where stitched TIFF exports produce all-black (zero pixel) output
with no error message shown to the user.

## Root Cause
`export_stitched_tiff` in `stitch_exporter.py` wrapped every `volume.get_frame()`
call in a bare `except Exception: pass` block. Any failure (wrong index, IO
error, dtype mismatch, etc.) silently produced a zero tile. The stitch worker
then emitted `finished` (not `error`), resulting in a valid-looking all-zero
TIFF with no user notification.

## Secondary Issue
Three exporters used `resolutionunit="MICROMETER"` in their `tifffile` calls.
This is not a valid TIFF spec value (valid: `None`, `"INCH"`, `"CENTIMETER"`).
`tifffile` v2026.5.15 silently ignores it.

## Approach

### Fix 1 — Remove silent exception handler (stitch_exporter.py)
Remove the `try/except Exception: pass` wrapper around `get_frame` in
`export_stitched_tiff`. Exceptions now propagate through
`BaseWorker.run_task()` → `BaseWorker.run()` which emits the `error` signal
and shows the user an error dialog with the traceback.

Add `if f.ndim != 2: f = f.squeeze()` after the `get_frame` call as a
lightweight robustness guard for edge-case dtype shapes.

### Fix 2 — Correct invalid resolutionunit (all exporters)
Replace `resolutionunit="MICROMETER"` with `resolutionunit=None` in:
- `stitch_exporter.py` — `tifffile.memmap` call
- `tiff_exporter.py` — `TiffWriter.write` and `tifffile.imwrite` calls
- `composite_exporter.py` — `TiffWriter.write` call

## Files Modified
- `nd2studios/backend/exporters/stitch_exporter.py`
- `nd2studios/backend/exporters/tiff_exporter.py`
- `nd2studios/backend/exporters/composite_exporter.py`

## Key Decisions
- Keep the `try/except` around `mm.flush()` (line ~387) — swallowing a
  flush failure is safe because the data is already written to disk.
- Do not change the Z-mode UI in `StitchDialog` now — the misleading Z
  options (max/mean/min/none) when volume is a `MaterializedDataset`
  (n_zslices=1) are a separate UX issue.

## Verification
- Ran `stitch_one_frame` + `tifffile.memmap` round-trip: non-zero frames
  confirmed for ELISA, TFM_Denoised, and WellA2 ND2 files.
- Confirmed that patching `get_frame` to raise `RuntimeError` → worker emits
  `error` signal (not `finished`) with the fix in place.
