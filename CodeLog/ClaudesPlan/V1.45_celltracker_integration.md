# V1.45 — Route CellTracker into ND2Studios cell-tracking pipelines

## Goal

Route the parts of the sibling **CellTracker** backend (`Cell-Tracker/CellTracker/backend`)
that ND2Studios *uniquely lacks* into the Pipelines node graph, **without**
re-integrating capabilities ND2Studios already has. Primary ask: a new
"Cell-Tracker" option on the **Track Objects** node; secondary: separate
supportive nodes for the cell-tracking analyses CellTracker adds.

### Already present in ND2Studios — deliberately NOT re-integrated
- Nuclei segmentation → ND2Studios uses **Cellpose** (`backend/analysis/nuclei_segmentation.py`),
  not StarDist. StarDist/TensorFlow/csbdeep stay out.
- Centroid Hungarian linker + **SerialTrack** → `backend/object_tracker.py`
  (`_link_group`, `_link_group_serialtrack`) + vendored `backend/serialtrack/`.
  CellTracker's `track_serialtrack` (hardcoded dev path) is therefore dropped.
- Per-object measurement → `backend/results_engine.compute_measurements`.

### CellTracker's unique contributions (now routed)
- Topology-Hungarian tracker (`track_timeseries`) and spatial-fingerprint tracker
  (`track_fingerprint`).
- Per-cell spatial metrics (`compute_spatial_metrics`) + self-fold-change
  (`compute_self_fold_change`).
- Eulerian gridded field maps (`compute_spatial_fields`).

## Approach

**Vendor, don't import** (per CLAUDE.md "shared code is currently copied" and the
SerialTrack precedent). Copy the minimal pure-Python subset into
`nd2studios/backend/celltracker/` — numpy/scipy/pandas only, Qt-free.

**Bridge the data-model mismatch.** ND2Studios carries measurements as row-dicts
(`centroid_y_px`, `centroid_x_px`, `area_px`, `frame`, `label_id`, `m_position`,
`segmentation_channel`, `track_id`, `mean_intensity_{ch}`); CellTracker uses
pandas DataFrames (`frame`, `label`, `centroid_y`, `centroid_x`, `area`,
`track_id`). All adapters convert per `(segmentation_channel, m_position)` group.

**Trackers follow the SerialTrack precedent** (no page changes for the linker
itself). **Field maps are export-style** — ND2Studios has no live heatmap canvas,
so they render to image files on Run (mirroring the synchronous Export node) with
an `MplCanvas` popup on Preview.

## What changed

### New — `nd2studios/backend/celltracker/` (vendored, Qt-free)
- `tracking.py` — `compute_topology_features`, `link_frames`,
  `fingerprint_cost_matrix`, `track_fingerprint`, `track_timeseries`
  (`track_serialtrack` omitted).
- `metrics.py` — `compute_spatial_metrics`, `compute_self_fold_change`
  (skimage import from the source dropped; only numpy/scipy/pandas needed). Added
  an `out_col` param to `compute_self_fold_change` so the bridge can name the
  column `self_fold`.
- `fields.py` — `compute_spatial_fields`, `FIELD_OPTIONS`.

### New — `nd2studios/backend/celltracker_bridge.py` (Qt-free)
Row-dict ↔ DataFrame adapters: `augment_rows_with_metrics` (Metrics node),
`compute_field_for_frame` / `draw_field_on_ax` / `render_field_figure` /
`export_field_maps` (Field Maps node). Rendering uses matplotlib's OO Agg API so
it never touches the GUI's global `QtAgg` backend.

### `backend/object_tracker.py`
- `METHOD_CT_TOPOLOGY`, `METHOD_CT_FINGERPRINT` added to `TRACKING_METHODS`.
- `link_objects` / `link_objects_with_params` gain `ct_n_neighbors`,
  `ct_topo_weight`, `ct_area_weight`, `ct_max_gap`.
- `_link_group_celltracker(...)`: builds a per-group DataFrame (label = `label_id`),
  runs the chosen vendored linker, and remaps CellTracker's per-call (1-based)
  `track_id` onto the shared global `next_id` counter so ids never collide across
  groups. The existing `track_length` / `min_track_length` post-pass is reused.

### `pipeline_graph/registry_adapter.py` (+ `__init__.py` exports)
- `SPECIAL_CT_METRICS_OP_KEY` / `SPECIAL_CT_FIELDS_OP_KEY` ops in `_SPECIAL_OPS`
  (category SPECIAL, HEXAGON, ANY→ANY).
- `param_specs_for`: `ct_*` params on Track Objects (gated by `visible_when`), and
  param specs for the two new nodes (`intensity_channel` injected live).

### `pages/pipelines_page.py`
- Run dispatch → `_run_ct_metrics` (synchronous, like Track Objects) and
  `_run_ct_fields` (synchronous QFileDialog + render, like Export).
- Preview → metrics augments the screened rows; `_preview_field_maps` renders the
  selected (M, T) field, popping `_show_field_popup` (`MplCanvas`) only on a
  deliberate/interactive walk.
- `_field_shape_for` reads `(H, W)` from `record.nd2_metadata`.
- Channel injection (`_inject_channel_choices`) now also fills `intensity_channel`
  and runs regardless of stage (the new specials are RESULTS-stage).

## Key decisions
- **Synchronous field render** (not a new async coalescing key): mirrors the
  existing Export node, which runs on the GUI thread — lower risk, consistent UX.
- **No schema bump / no migration**: only new op-key strings + params; the
  `Node`/`Edge` model is unchanged. Old graphs never contain these op-keys.
- **No new pip dependencies** (numpy/scipy/pandas/matplotlib/tifffile present).
- Spatial Fingerprint partly overlaps the existing centroid linker — exposed
  anyway as part of the requested "Cell-Tracker" family.

## Follow-up (2026-06-24) — If/Else object lens (per-object/per-track dismiss)

**Ask:** Dismiss was nuking the whole frame. The If/Else should toggle between a
frame lens (route the whole result) and an **object lens** (per-object, so e.g.
"exclude cells with any frame-frame vector > 20 µm" sends only those cells to the
false/Dismiss branch, and the spatial maps after the true branch contain only the
kept cells).

**Why frame-only before:** the if-else evaluated one aggregate bool and *pruned* a
branch (`GraphRunner.complete(prune_ports=…)`); all rows share one
`_run_context["rows"]`, so Dismiss dropped everything.

**Design (reuses existing pieces):**
- `conditions.partition_rows(cond, rows, group_by)` routes each group by the
  existing `evaluate_condition` — **Per track** (group by `(m_position, track_id)`)
  makes a metric block's `any/all/mean` mean "across the cell's frames"; **Per
  row** evaluates each row alone. Constants `LENS_FRAME/LENS_OBJECT/GROUP_*`.
- `registry_adapter`: if-else gains `lens` + `group_by` flat params (popup), both
  defaulting to the old behavior; no schema bump (additive, `.get`-read).
- `pipelines_page`: object-lens if-else finishes with `prune_ports=set()` +
  `port_rows={true:pass,false:fail}`; new `_apply_branch_scope` + per-output-port
  `_run_port_rows` scope every downstream node to its branch (Dismiss unchanged).
  Preview mirrors it for the previewed branch. `GraphRunner.active_incoming` added.
- `celltracker_bridge`: added `speed_um`/`velocity_*_um` (px × pixel size) so the
  20 µm threshold is set directly in µm.

**Verified:** selftest extended (`partition_rows` per-track vs per-row) stays
green; headless `augment_rows_with_metrics` emits `speed_um = speed_px·px`;
offscreen `Track→Metrics→If/Else(object,per-track)→{Dismiss,Dismiss}` routes the
fast track to FALSE and the slow track to TRUE, and each Dismiss is scoped to its
branch's rows; if-else popup exposes `lens`/`group_by` + Edit button; page boots.
Known: Per-row + a speed condition drops a track's first frame (no velocity) —
Per-track is the default for motion.

## Follow-up (2026-06-23) — If/Else sees all Cell-Tracker tracking metrics

**Ask:** an If/Else wired after Cell-Tracker nodes should let you branch on all
their tracking results — track length, speed vector, cell density, and more.

**Gaps found:**
1. The Cell-Tracker Metrics node never exposed per-cell motion: the vendored
   `compute_spatial_metrics` computes `vy`/`vx` but drops them, and there was no
   density column.
2. The condition builder's metric dropdown was the static `_METRICS` list, so
   per-channel intensities and any node-specific columns weren't selectable.

**Changes:**
- `celltracker_bridge._add_velocity_density` → adds `speed`, `velocity_y/x`,
  `cell_density` to the metrics-node output; `METRIC_COLUMNS` extended.
- `conditions.TRACKING_METRICS` + `metric_choices(extra)`; `_METRICS` now
  includes the motion/density columns.
- `ConditionBuilderDialog(metrics=…)` injects discovered columns into the
  `metric` editor.
- `pipelines_page._available_metric_columns` / `_has_upstream_celltracker`
  discover the columns (live rows ∪ upstream Track/CT-Metrics columns via an
  incoming-edge walk) and pass them to the dialog.

**Verified:** selftest green; offscreen dialog shows `speed`/`cell_density`/
`mean_intensity_<ch>`; an incoming-edge walk on `Track → CT Metrics → If/Else`
detects the upstream CT nodes (lone If/Else does not); `augment_rows_with_metrics`
emits finite `speed`/`velocity_*`/`cell_density`, and a `mean speed > 5` condition
evaluates correctly.
