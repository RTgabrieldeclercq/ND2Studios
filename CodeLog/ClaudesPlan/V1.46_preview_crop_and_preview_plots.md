# V1.46 — Preview Crop + full preview coverage (plots & nodes)

## Goal

1. Add a **Preview Crop** button to the Pipelines-page image viewer. When armed,
   the user drags a rectangle on the image (or clicks a point and enters the
   corner + width/height in a dialog) to define an XY sub-region.
2. When a preview crop is active, **preview mode** (Processing / Analysis /
   Results) runs on the *selected frames × the crop* instead of the whole frame.
   The preview viewer shows the cropped region; segmentation, tracking,
   measurements, overlays and plots all operate in crop space (internally
   consistent — chosen over "full frame with overlay confined to crop").
3. Verify + fill gaps so **all** preview outputs work: every node
   (Track Objects, Spatial Maps, if-else, Dismiss, CT-metrics …), every overlay
   (Segmentation, Tracks, Vectors: cells, Vectors: field), and — new — the
   bottom-panel plots (Cells/frame, Area, Tracks/frame, Track length), which
   were previously **Run-only**.

Crop is a **preview-only** tool: it is ignored during a full Run and is not
persisted to `.nd2s`. It is per active record and resets when the file changes.

## Key finding (from code survey)

All preview computation funnels through three frame-reader methods plus the base
image volume:

- `_read_planes_frames` → Processing preview input.
- `_extract_processed_frame` → Analysis preview input (also via
  `_read_processed_planes` → Results walk input).
- `_materialize_channels_for_m` → Spatial Maps backdrop / intensity.
- Base image display: `_show_base_image` / `_show_preview_volume` (lazy volumes:
  `ProcessedFrameVolume`, `PinnedProcessedVolume`).

Cropping at those choke points makes every downstream consumer (masks, tracks,
vectors, measurements, plots) crop-aware automatically, because the analysis
pipelines derive output size from the frame they are handed.

Overlays already respect preview (`_overlay_result_for` prefers per-plane screen
results). The bottom-panel matplotlib plots are built only during a Run
(`_update_analysis_plots` / `_update_track_plots` called from `_advance_run_m` /
`_finish_track_objects`), so preview needs to call them too.

## Approach

### Backend — `nd2studios/pipeline_graph/executor.py`
- Add `class CroppedVolume`: wraps a raw/processed volume, mirrors the
  `get_frame` read protocol, reports `height/width` = crop size, and returns
  `frame[y:y+h, x:x+w]`. Export from `pipeline_graph/__init__.py`.

### Page — `nd2studios/pages/pipelines_page.py`
- State: `self._preview_crop: Optional[Tuple[int,int,int,int]]` (x,y,w,h),
  `self._crop_selecting: bool`.
- Helpers:
  - `_crop_rect()` → the active crop, or `None` when `_run_active` (crop inert
    during Run).
  - `_crop_frame(arr)` → slice last two axes to the crop if active.
  - `_maybe_crop_volume(vol)` → wrap in `CroppedVolume` if active.
  - `_preview_metadata(record)` → metadata dict with `height/width` overridden
    to crop dims when active.
- Apply crop in the readers: `_read_planes_frames`, `_read_processed_planes`,
  `_do_analysis_preview` (frames), `_materialize_channels_for_m`.
- Apply crop to base display: `_show_base_image` (lazy volume + in-RAM
  fallback), processing `_on_runner_done` (`PinnedProcessedVolume` over the
  cropped raw vol).
- `_field_shape_for` returns crop dims when active (Vectors: field + Spatial
  Maps field shape).
- `_overlay_result_for` skips the full-frame Run masks when a crop is active
  (they would be the wrong size for the cropped display).
- Metadata for `_do_analysis_preview` / `_start_preview_walk` uses
  `_preview_metadata`.
- **Plots in preview:** new `_update_preview_plots()` clears + rebuilds
  Cells/frame, Area, Tracks/frame, Track length from `_results_rows`; called
  after `_preview_walk_downstream()` in the `_PV_SCREEN_KEY` handler.

### UI
- `_btn_preview_crop` (checkable icon button "Preview Crop") + `_lbl_preview_crop`
  in the overlay tab row, next to the viewer popout.
- Wire `viewer.crop_rect_selected` (drag) and `viewer.canvas.clicked`
  (click-to-enter) → `_show_preview_crop_dialog` (mirrors the Recipe-page crop
  dialog) → store crop + refresh. Toggling the button off clears the crop.
- Reset crop in `load_from_experiment`.

## Files
- `nd2studios/pipeline_graph/executor.py` (+ `__init__.py`) — `CroppedVolume`.
- `nd2studios/pages/pipelines_page.py` — button, wiring, dialog, crop helpers,
  reader/display/overlay/plot changes.
- `CodeLog/Updates/CHANGELOG.md`, `CodeLog/Architecture/ARCHITECTURE.md`.

## Key decisions
- **Show cropped region** during preview (consistent coordinate space) rather
  than full frame with a confined overlay.
- Crop lives on the page (preview-only, not serialized); ignored during Run.
- Recipe/background-subtract steps run on the full frame then the result is
  cropped (better context than cropping the raw input), while the expensive
  segmentation/tracking runs on the crop.
