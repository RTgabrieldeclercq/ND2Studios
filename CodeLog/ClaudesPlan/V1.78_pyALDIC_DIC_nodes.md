# V1.78 — 2D DIC (pyALDIC) nodes

## Goal

Add a 2D Digital Image Correlation capability to ND2Studios, built on the
open-source [`al-dic`](https://pypi.org/project/al-dic/) package (pyALDIC — 2D
Augmented-Lagrangian DIC, Yang & Bhattacharya 2019; the same AL-DIC lineage as
the app's 3D ALDVC node). Three new Special nodes that work with every other
node in the graph:

- **`DIC (pyALDIC)`** (`special:dic`) — the compute node. Correlates the wired
  channel's frames and opens a dedicated **DIC** viewer tab.
- **`DIC Mesh Region`** (`special:dic_roi`) — draw the AL-DIC mesh domain (ROI).
- **`DIC Mesh Refinement`** (`special:dic_refine`) — paint an adaptive-quadtree
  refinement brush + pick refinement criteria.

The two mesh nodes reproduce pyALDIC's README "mesh drawing" workflows (ROI
tools + adaptive refinement) as requested.

## Approach

**Maximum reuse of the DVC infrastructure.** `core/dvc_registry.py`'s `DVCResult`
already documents the 2D case (`dim==2`), and `widgets/dvc_panel.py` already
renders 2D fields (field / quiver / heatmap+quiver / histogram; 3D-only views
auto-dropped). So the pyALDIC engine returns a 2D `DVCResult` and renders through
the **existing** `DVCPanel` with zero panel changes. A `PyALDICMethod` is
registered under the shared `DVCMethod` registry, mirroring `ALDVCMethod`.

**Optional dependency.** `al-dic` is lazily imported and gated by
`importlib.util.find_spec` with a friendly `ImportError` — never in
`requirements.txt` (the stardist/cellpose convention). Running a DIC node without
it installed shows a friendly status message, not a crash.

**Whole-series native solve.** Per multipoint the job reads one projected frame
per timepoint and calls `al_dic.core.pipeline.run_aldic` **once** over the whole
image list, letting pyALDIC handle accumulative vs incremental tracking + seed
propagation. Each per-frame result is adapted to a `DVCResult`.

**Result adapter (the one new algorithm).** pyALDIC returns an *adaptive
quadtree FE mesh* (`coordinates_fem` `[x,y]`, displacement interleaved `[u,v,…]`);
`DVCResult` needs a *regular grid* `(Gy,Gx,2)`. `backend/dic/engine.py` resamples
the nodal displacement onto a regular grid (pitch = winstepsize) via
`scipy.griddata` (linear + nearest fill), swapping the `(x,y)`/`[u,v]` convention
to `DVCResult`'s `(y,x)`/`[dy,dx]`. Displacement stays in pixels; `voxel_size_um`
handles µm.

**Mesh drawing.** `DICMeshEditorDialog` reproduces pyALDIC's ROI toolbar flow
(Add/Cut × Rectangle/Circle/Polygon + Refine Brush + Invert/Clear/Undo) on the
app's existing `ImageCanvas`, with a live mesh-dot preview. Drawn actions are an
ordered, serializable vector-shape list rasterized to a boolean mask on Run.

**Side-artifacts (the DVC-family pattern).** The two mesh nodes are pass-throughs
wired upstream of the DIC node (`input → DIC Mesh Region → DIC Mesh Refinement →
DIC`). On Run they publish `record._dic_roi_by_m` (mesh domain) and
`record._dic_refine_by_m` (brush + criteria); the DIC job reads both (and honors
crop / registration / exclude), falling back to the full frame when no ROI node
is present.

## Key decisions

1. Reuse `DVCResult` / `DVCMethod` / `DVCPanel`; separate `special:dic` op +
   `"dic"` overlay tab + `_dic_series_by_m` state so DIC and DVC coexist.
2. `al-dic` optional & lazy (find_spec gate, friendly ImportError).
3. Whole-series `run_aldic` per M (native tracking), then per-frame adapter.
4. ROI/refinement as record side-artifacts (like mask3d/exclude), not on the wire.
5. Loop-sweep integration deferred (DIC does not participate in param sweeps yet).
