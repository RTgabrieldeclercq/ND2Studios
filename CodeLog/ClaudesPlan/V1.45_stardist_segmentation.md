# V1.45 — StarDist segmentation analysis node (+ boundary-outline display)

## Goal

Route CellTracker's **cell-boundary drawing** into ND2Studios. CellTracker's
backend has exactly one segmentation method — **StarDist** (`segment_frame` /
`get_stardist_model`, model `2D_versatile_fluo`); its "boundary drawing" is just
rendering those label masks as outlines via `skimage.segmentation.find_boundaries`.
ND2Studios has Cellpose but no StarDist. Deliver it as a **new analysis node**
(distinct from the tracker options, which went on the Track Objects node), plus a
**boundary-outline display mode** so segmentations can render as outlines.

## Approach

- **Registry-driven** (nd2-pipelines skill's golden rule): a new `AnalysisPipeline`
  subclass + one force-import line is all that's needed for the node to appear in
  the Analysis tab / palette — no `pipeline_graph/` or Add-dialog edits.
- **Vendor** the StarDist backend into `backend/celltracker/segmentation.py`,
  consistent with the existing vendored `celltracker/` package.
- **Optional, lazy dependency** (like Cellpose): `STARDIST_AVAILABLE` via
  `importlib.util.find_spec`; `run()` raises a friendly ImportError when absent.
- **Outline as an `AnalysisResult` hint**, honored by the two interactive overlay
  paths (which share one helper) and the export overlays.

## What changed

### New
- `nd2studios/backend/celltracker/segmentation.py` — vendored from
  `Cell-Tracker/CellTracker/backend/segmentation.py` (Qt-free): `get_stardist_model`
  (singleton), `segment_frame`, `segment_timeseries`, `_ensure_tf_threading`
  (single inter/intra-op threads — avoids TF worker-thread deadlock),
  `_patch_windows_symlink`. Added a `disable_gpu` arg that clears
  `CUDA_VISIBLE_DEVICES` **before** the first TF import (honors the GPU flag).
- `nd2studios/backend/analysis/stardist_segmentation.py` —
  `StarDistSegmentationPipeline(AnalysisPipeline)`, mirroring the Cellpose node:
  `STARDIST_AVAILABLE` guard, lazy import, `is_gpu_enabled()` → `disable_gpu`,
  per-frame via `plane_runner.run_planes_to_labels(n_workers=1)` (TF not
  thread-safe), area filter + `_relabel_contiguous`, measurements + summary,
  `AnalysisResult(..., overlay_outline=params["outline"])`. Params: `channel_name`,
  `model_name` (fluo/he/dsb2018), `prob_thresh`, `nms_thresh`, `scale`,
  `min_area`/`max_area`, `outline`.

### Modified
- `nd2studios/__main__.py` — force-import the new module in the startup block.
- `core/analysis_registry.py` — `AnalysisResult.overlay_outline: bool = False`.
- `pages/analysis_page.py` — `_overlay_labels(..., outline=False)` paints only
  `find_boundaries(mask, mode="inner")` pixels when set; `_composite_overlay`
  passes `outline=result.overlay_outline` (primary masks; secondary stay filled).
- `pages/pipelines_page.py` — both `_composite_results_overlay` call sites pass
  `outline=res.overlay_outline`; `_run_export` sources
  `outline = any(r.overlay_outline …)` and passes it to `export_organized`.
- `backend/results_engine.py` — `_label_boundaries` helper; `outline` param on
  `export_overlay_frames`, `export_label_masks_as_overlay`, `export_organized`,
  `_render_export_rgb`, `_label_to_rgb` (boundary-only painting when set).

## Key decisions
- **No `pipeline_graph/` / Add-dialog / schema changes** (registry-driven).
- **StarDist is optional**: not added to the auto-generated `requirements.txt`;
  install via `pip install stardist tensorflow csbdeep`. CLAUDE.md / ARCHITECTURE
  "no StarDist/TensorFlow" line relaxed to note it as an optional extra.
- **Tracking "via StarDist"** needs no new code — StarDist labels feed the existing
  measurement → Track Objects (Centroid / SerialTrack / Cell-Tracker) → metrics /
  export chain.
- Outline applies to the **primary** mask; secondary masks (background/inverse)
  stay filled.

## Verification (all pass)
- Backend purity: `grep -r PySide6 nd2studios/backend/celltracker/` → nothing.
- Registry: StarDist registers via the `__main__` force-import block;
  `get_pipelines()` includes it; offscreen `MainWindow()` boots.
- `get_params()` works without the dep; `run()` raises a friendly ImportError when
  stardist is absent.
- **Real run** (stardist installed here): synthetic 2-frame image → 11 objects,
  `(2,128,128)` int32 masks, `overlay_outline=True`, correct measurement rows;
  TF in the `n_workers=1` worker did **not** deadlock (single-threaded guard works).
- Outline render: filled 400 px vs outline 76 px for a 20×20 square;
  `results_engine._label_to_rgb(outline=True)` paints fewer pixels.
- `python scripts/_pipeline_graph_selftest.py` stays green.
- Manual end-to-end: load ND2 → StarDist Segmentation (outlined preview) → Run →
  measurements + (with downstream Track Objects) tracks → Export writes outlined
  overlays.

## Follow-up (V1.45.30): outline-parity + CellTracker-style cell review

Two refinements after the initial node landed:

1. **Exact CellTracker outline brightness.** The StarDist result now sets
   `overlay_color=(255,50,50)` + `overlay_alpha=1.0` when outlines are on, and
   `_overlay_labels` gained a **single-colour outline path** that paints *every*
   `find_boundaries(mode="outer")` pixel in that colour (no per-label
   intersection) — matching CellTracker's `draw_boundaries_on_painter`
   (`QColor(255,50,50)`, full opacity) byte-for-byte. The per-label *palette*
   outline path (and `results_engine._label_boundaries` for exports) uses
   `mode="inner"` so boundary pixels stay object-side and attributable (the
   earlier `mode="outer"` + per-label intersection painted nothing).
2. **Review Objects per-cell detail = CellTracker Results (Cells).** Each
   `TrackValidationDialog` panel now shows a red `(255,80,80)` boundary outline on
   the crop, per-frame detail text (frame · area · ecc · intensity), and a per-cell
   metric **trace** (`MplCanvas`, current-frame marker); a top-bar **Metric**
   selector (intensity per channel / area / eccentricity, derived from present
   columns) drives the trace + info. Accept/Reject flow and `accepted_rows` /
   `rejected_rows` are unchanged.

Verified (offscreen): the single-colour outline is exactly `(255,50,50)` at full
opacity (80 boundary px on a 20×20 square; filled covers >2× as many);
`results_engine` outline export is non-empty; the dialog builds with metric options
`[Intensity: DAPI, Area, Eccentricity]`, per-cell trace frames, info text, a
`(255,80,80)` crop outline, working T-marker + metric switch, and Accept records
the track id. Selftest + full `MainWindow()` boot stay green.
