# V1.48 — Channel-wire pipeline model + full M/T processing coverage

## Goals

1. **Bug fix — process the entire M and T repertoire.** The Analysis Run and its
   chained measurement currently analyze one multipoint's pixels (whichever M
   `record._raw_channels` holds — M0 at import) for *every* M, tagging results
   under each M key. Make the Run re-materialize the correct per-M processed
   channels so all multipoints (and all timepoints within each) are truly
   analyzed. (Confirmed root cause below.)

2. **Channels as connectable nodes (the big feature).** Turn "which channel a
   process runs on" from a per-node `channel_name` parameter into graph *wiring*:
   - Under the Input node, render one **channel source node per channel** plus an
     **"All"** node (colored by each channel's display color).
   - Wiring a channel into a process means that process runs on that channel.
   - Channels **propagate downstream automatically** along the standard
     (structural) wires: once a channel is wired into a node, it "follows" the
     next standard connection; a channel wired into a *downstream* node joins the
     set there ("if a process is done on one channel and another channel is wired
     to the further downstream process, that channel will also be included").
   - Each channel flowing between two nodes draws an **additional line in the
     channel's color** (channel-colored propagation wires overlaid on the
     structural wire).
   - A **rainbow input port** on each process accepts channel wires; connecting
     one **spawns another empty rainbow port** for the next channel, and rainbow
     connectors appear on **both sides** (input + output) of any node that
     carries a channel.
   - A **scissors** button (in the control bar by Preview) cuts any wire —
     structural or channel.
   - **Efficiency:** only wired channels go through the pipeline; unwired
     channels stay **raw**, in the committed processed view *and* the viewer. For
     Processing this is **per-channel from the entry point** — a channel wired
     partway down only gets the steps from its entry onward.
   - Remove the `channel_name` / `counterstain_channel` / `intensity_channel`
     parameters from all nodes; infer channels from wiring.

## Confirmed root cause of the M/T bug

`record._raw_channels` holds a **single M** (`all_channels_as_lazy(m=…)`;
`load_worker.py:218` → M0, or the last M navigated on the Recipe page). Apply
builds `record._processed_view = EnhancedDataset(record._raw_channels, …)`
(`pipelines_page.py:4318`), which therefore covers **all T but only one M**.

The Run (`_run_analysis_node` → `_advance_run_m`) captures `channels` once from
`record.processed_view()` (`pipelines_page.py:3651-3673`) and hands the *same*
single-M object to every per-M `PipelineCommitJob`; `m_index` is only a result
*tag* (`pipeline_jobs.py:155,164-166`), never used to re-read image data. The
chained `_ResultsMeasureJob` likewise reads the single-M `processed_view()`
(`pipelines_page.py:3299-3302`). Loop bounds `0..n_multipoints-1` are correct
(`:3674-3675`) — only the image data is wrong.

The genuinely all-frames view (`ProcessedFrameVolume` over `record._raw_volume`,
`executor.py:422`) already exists and is used for the on-screen base image; the
fix routes the Run through per-M channels built the same way.

## Design decisions (confirmed with the user)

- **Two-layer wiring.** Keep structural wires (Input→process→Output) that define
  operation order/topology; add a separate **CHANNEL** wire layer that decides
  which channels flow. Scissors cuts both.
- **Rainbow input port per process**, dynamic: `#connected + 1` rainbow ports
  (always one free). A connected channel propagates to downstream nodes along
  structural wires automatically; rainbow connectors show on both the input and
  output sides of any node carrying a channel.
- **Per-channel processing from entry point.** The committed recipe becomes
  per-channel; a channel gets only the enhancement steps at/after the node it is
  first wired into. Unwired channels are raw.
- **Backward-compat default:** if a slice has **no** channel wiring at all, every
  node's effective channel set is **all channels** (legacy behavior). Any channel
  wiring switches the slice to "only wired channels flow; rest raw".

## Data model (`nd2studios/pipeline_graph/model.py`)

- `PortType.CHANNEL` — new flavor for channel wires (rainbow-colored). `can_connect`:
  a CHANNEL output only connects to a CHANNEL input; rainbow input ports accept
  **fan-in** (multiple channel wires), unlike normal one-wire inputs.
- `NodeCategory.CHANNEL` — channel source nodes (colored per channel color, not
  the category color).
- Channel source node: `role=INPUT`-like source but a **distinct** op_key so it is
  not confused with the main input. Use `CHANNEL_PREFIX = "channel:"` and
  `CHANNEL_ALL_OP_KEY = "channel:__all__"`; role `NodeRole.ACTION` with no
  structural input and a single CHANNEL output (kept off the recipe chain because
  it never sits on a *structural* edge). A `ShapeKind.PILL` (small rounded) render.
- Rainbow ports live on process nodes as CHANNEL-typed inputs on the node's
  **left** edge (dynamic) plus a CHANNEL output indicator on the **right** edge
  (channel flow is horizontal; pipeline flow stays vertical top→bottom).

## Executor (`nd2studios/pipeline_graph/executor.py`)

- `channel_source_names(node) -> Set[str]` — a channel node's channels
  (`{name}` or all names for "All"; "All" needs the live channel list passed in).
- `has_channel_wiring(sl) -> bool`.
- `channel_sets(sl, all_names) -> Dict[node_id, Set[str]]` — topological
  propagation: `set(node) = ⋃ channel-edge sources ∪ ⋃ structural-pred sets`.
  When `not has_channel_wiring(sl)` → every node maps to `set(all_names)`.
- `channel_recipes(sl, output_id, all_names) -> Dict[str, Recipe]` — linearize the
  Output's structural chain (existing `recipe_for_node`), then for each channel
  include only the steps whose node set contains it (monotonic ⇒ suffix from the
  entry node). Channels absent → identity (raw).
- `edge_channels(sl, all_names) -> Dict[edge_id, List[str]]` — channels flowing
  through each *structural* edge (= `channel_sets[dst]` ∩ carried), for drawing
  the channel-colored propagation sub-lines.

## Per-channel processed view

- `EnhancedDataset` gains an optional `recipe_by_channel: Dict[str, Recipe]`; when
  present it overrides the single recipe per channel and returns raw for channels
  with an empty/absent recipe. `ProcessedFrameVolume` gains the same. Both keep
  the single-recipe path for legacy callers.
- Record: add `recipe_by_channel: Optional[Dict[str, Recipe]]` (in-session only,
  not serialized in V1.48 — recomputed from the graph). `processed_view()` /
  `_show_base_image` prefer it when set.

## Page (`nd2studios/pages/pipelines_page.py`)

- **Phase 0 (bug fix, independent):** `_processed_channels_for_m(record, m)` reads
  per-M channels from `record._raw_volume` (via `all_channels_as_lazy(m=m)` or
  `_materialize_channels_for_m`) and applies the committed recipe. `_advance_run_m`
  builds channels for the *current* m; the `_RUN_ANALYSIS_KEY` handler feeds the
  chained `_ResultsMeasureJob` the same per-M channels.
- Channel source nodes created/refreshed in `_ensure_input_node` /
  `_refresh_input_node`, laid out under the Input node.
- Analysis Run/preview: replace `params["channel_name"]` selection with the node's
  effective channel set; run the pipeline once **per channel** in the set (each
  producing its own `label_masks` key so `segmentation_channel` is preserved for
  the tracker / celltracker_bridge / interp_maps / results_engine grouping).
- Counterstain: when a tear-detection node has ≥2 wired channels, the first is
  primary and the rest counterstain (documented; single-channel behaves as before).
- Scissors: `_btn_scissors` toggle in the control bar; a scene "cut mode" where a
  drag draws a cut stroke and any crossed EdgeItem is removed.
- Remove `_inject_channel_choices` channel injection for analysis nodes;
  `param_specs_for` drops the channel ParamSpecs; saved-graph migration strips the
  params and (best-effort) auto-wires the equivalent channel node.

## Rollout order

Phase 0 (bug fix) ships value immediately and is independent. Phases 1–7 build
the channel-wire model incrementally; each phase keeps the app runnable. Legacy
graphs (no channel wiring) behave exactly as before via the all-channels default.
