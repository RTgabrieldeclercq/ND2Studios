# V1.56 — Image Registration (processing node)

**Status:** In progress
**Related review:** `Research/image_registration.md`

## Goal

Add **image registration** to ND2Studios as a **Processing-stage node**: stabilize a
`(T, H, W)` channel series onto a reference frame (temporal drift correction), with an
optional rigid/affine refinement for the more general "align a moving image onto a
reference" job. Following the attached review's *build order*, we ship:

1. A **pure estimation engine** `backend/registration/estimate.py` (Qt-free, reusable).
2. A **registration `EnhancementPlugin`** (`plugins/enhancement/registration.py`) that
   drops straight into the recipe / Pipelines palette as a Processing node — no
   node-graph or page surgery (`registry_adapter.enhancement_specs()` enumerates it
   automatically, `workers/recipe_worker.py` already invokes `execute`).

3. The **cross-channel `RegistrationMethod` registry + special node** (review Part 3.4
   / "Option A"): the general home for "register once on a reference channel, apply to
   all channels". Mirrors the DVC feature (registry → method → `special:` node →
   off-thread job → viewer panel).

Both integration paths share the one pure engine (steps 1+2).

## Approach

### `backend/registration/estimate.py` (pure, no PySide6)
Reuses the stitcher's proven primitives (`backend/stitch/register.py`: `_highpass`,
`_hann2d`, `_ncc`) instead of duplicating windowing/scoring.

- `estimate_translation(reference, moving, upsample, highpass_sigma)` — sub-pixel
  phase correlation (`skimage.registration.phase_cross_correlation`,
  `normalization="phase"`), returns `(shift (row,col), ncc)`.
- `apply_shift(image, shift, order)` — `scipy.ndimage.shift`, dtype-preserving.
- `ecc_align(reference, moving, model, init_shift, interp_order)` — `cv2.findTransformECC`
  (translation / euclidean / affine / homography), seeded from a phase-correlation
  translation; returns `(warp_matrix, cc, aligned)`.
- `apply_warp(image, warp_matrix, motion, output_shape, interp_order)`.
- `stabilize(volume, model, reference, upsample, highpass_sigma, interp_order,
  min_confidence, progress_cb, cancelled_cb)` — the `(T,H,W)` driver. Reference modes
  `first` / `previous` (cumulative) / `mean`. Returns `(aligned (T,H,W), shifts (T,2),
  confidence (T,))`. Low-confidence frames fall back to identity (pitfall guard).

### `plugins/enhancement/registration.py`
`RegistrationPlugin(EnhancementPlugin)` — params `model`, `reference`, `upsample`,
`highpass_sigma`, `interp_order`, `min_confidence`; `execute()` calls
`estimate.stabilize(...)` and returns the aligned array (same shape, dtype preserved).

### Wiring
Force-import `nd2studios.plugins.enhancement.registration` in `__main__.py` next to the
other builtins so the `@EnhancementPlugin.register` decorator fires at startup.

### Option A — cross-channel `RegistrationMethod` node (mirror DVC)
- `core/registration_registry.py` — `RegistrationMethod(ABC)` + `RegistrationResult`
  (per-frame `shifts_px`/`transforms`/`aligned`/`confidence`/`pixel_size_um`), reusing
  `ParamSpec`. Mirrors `core/dvc_registry.py`.
- Engine additions `estimate.estimate_series` (per-frame **absolute** effective
  transforms — translation shifts, or composed ECC affine warps) + `apply_series`
  (apply those transforms to any channel = the "apply to all" half).
- `backend/registration/method.py` — `RigidRegistration` (`@RegistrationMethod.register`)
  estimates on the reference series and returns the transform bundle + aligned ref.
- `registry_adapter.py` — `SPECIAL_REGISTER_OP_KEY`, a `_SPECIAL_OPS` HEXAGON entry with
  an `IMAGE` rainbow port (copied from DVC), and a `param_specs_for` branch (scope +
  `apply_to_all_channels` + `RigidRegistration().get_params()`).
- `pipelines_page.py` — `_RUN_REGISTER_KEY`, `_RegisterJob` (off-thread: read each
  channel's `(T,H,W)` via `get_frame`, register the reference channel, apply to all),
  `_run_register`/`_finish_register`, dispatch wiring (preview/run/done/cancel/progress),
  and the `registration` overlay tab.
- `widgets/registration_panel.py` — `RegistrationPanel`: before/after playback + a
  drift-vs-time plot + confidence + "Write aligned → processed channels".

## Key decisions
- **Register once, apply to all** is honored for future cross-channel work by keeping
  transform estimation (`estimate_translation` / `ecc_align`) separate from application
  (`apply_shift` / `apply_warp`). The single-channel plugin can't do cross-channel, so
  it is scoped to per-channel drift/rigid stabilization (review Part 3.2).
- **Translation is the default** (subpixel, cumulative-safe, illumination-robust,
  matches the stitcher). ECC euclidean/affine seed from the phase-correlation shift.
- **`previous` mode references the raw previous input frame** and accumulates the
  *shift* (translation path, blur-free); the ECC path references the already-stabilized
  previous frame so any model accumulates without homogeneous-matrix composition.
- **Confidence gating**: a cross-correlation peak always exists, so near-blank frames
  can produce spurious shifts — frames below `min_confidence` (NCC) fall back to identity.
- Dtype preserved: compute in float, clip, cast back.

## Validation
`tests/registration/` (synthetic ground truth, mirrors `tests/spots/` style): known
sub-pixel shift recovery (≤ ~0.15 px @ upsample=20), apply/estimate round-trip,
random-walk drift reduction for `first`/`previous`/`mean`, uint16 in → uint16 out,
ECC euclidean recovers a known rotation, register-once-apply-to-all (shift from A
aligns B).
