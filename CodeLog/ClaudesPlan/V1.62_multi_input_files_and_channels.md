# V1.62 — Phase 2: multi-input files + channels on the node body

Part of the pipelines overhaul (master plan
`V1.61_pipelines_tab_overhaul.md`). Phase 2 = **R3** (one input node per loaded
file) + **R8** (channels attached to the input-node body) + **R9** (channel-bridge
spacing).

## Goal

Every file loaded in the Import tab appears as its **own input node** in the
Pipelines scene, named after the file, so multi-file / multi-channel workflows
are possible. Each input node's downstream chain executes against *that file's*
data.

## Key findings (grounding)

- `ND2StudiosManager` tracks **only the active record** — there is no registry of
  all loaded files. Multiple files live as `FilePanel`s in `ImportPage._panels`,
  each owning a `record` with a stable `exp_id`. `ImportPage.get_confirmed_records()`
  already enumerates them; `FilePanel.filepath` gives the path,
  `FilePanel.panel_close_requested`/`loaded` are the lifecycle signals. The
  Pipelines page reaches the Import page via `main_window.pages.get("import")`.
- The Pipelines page calls `_active_record()` in **52 places** and the executor
  path assumes a single record. A full per-record rewrite of all 52 is neither
  safe nor necessary.
- `NodeItem` already **dims a node when `node.enabled is False`** — so
  "close-disables" is just `node.enabled = False` + `item.update()`.

## Design

**Bind each input node to a record by `exp_id`** (stored in
`node.params["source_exp_id"]`), and make `_active_record()` resolve through a
**focused input node** — the input feeding the previewed/running chain — with a
fallback to the Import tab's active record. Because the 52 call sites go through
`_active_record()`, they all follow the focused file with **one** change and
**no regression for the single-file case** (the sole input is bound to the active
record, so `_active_record()` returns it unchanged).

### R3 — per-file input nodes (this pass)
- `_loaded_files()` → `[(record, basename)]` for every loaded panel (+ the active
  record); `_loaded_records_by_id()` keys them by `exp_id`.
- `_active_record()` → focused input's bound record, else `exp_manager.active`.
- `_focused_input_id` tracks the input node feeding the previewed node; set on
  double-click (`_input_node_for(node_id)` walks structural inputs back to the
  INPUT node).
- `_sync_input_nodes()` (replaces the single-universal-input `_ensure_input_node`):
  adopt a legacy unbound input for the first file, then ensure one input node per
  loaded file (bound by `exp_id`, titled by basename), laid out in a column;
  **disable** (grey, keep) input nodes whose file was closed. Called from
  `_select_stage` / `on_activated` / `load_from_experiment` (fires on navigation +
  `active_changed`).
- Double-click rename (R4) still lets the user relabel an input node's title; the
  `exp_id` binding is independent of the title.

### R8 — channels on the input-node body (next pass)
Per-channel `CHANNEL` output ports rendered on each input node's body, driven by
the bound record's channel names — subsuming the standalone `channel:{name}` PILL
nodes for file inputs (pills kept for back-compat load only).

### R9 — channel-bridge spacing (next pass)
Increase the channel-port pitch / strand offset once R8's in-body channel rows
land.

## Execution semantics
Preview / Run resolve the record from `_active_record()`, which now follows the
focused input node. So double-clicking File B's analysis node previews File B's
data; a Run walks the focused input's chain against its record. Multi-file
*simultaneous* execution + per-input result viewers are Phase 4 (POV).

## Verification
- Qt-free self-test unaffected (this is page-level).
- Offscreen: with a mock Import page exposing 2 panels/records, `_loaded_files()`
  returns both; `_sync_input_nodes()` creates 2 bound, basename-titled input
  nodes; closing one disables it (kept); `_active_record()` follows the focused
  input; single-file case returns the active record unchanged; `MainWindow` boots.
